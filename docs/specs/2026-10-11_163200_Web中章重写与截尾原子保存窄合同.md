# Web 中章重写与截尾原子保存窄合同

状态：accepted。承接[尾章重写合同](./2026-10-11_151900_Web尾章重写原子保存窄合同.md)，关闭其中列出的两个 Web 多事务写入窗口；不改变 Hosted wire、IDB schema 或 Desktop/Native 入口。

## 共用源与隔离范围

点击固定原 session/目标章身份；生成或确认前，用同一三 store readonly 事务取得完整 session、全部章（含 superseded）和 checkpoint。共享源验证保证目标仍属连续活动链；canonical 全图摘要涵盖窗口外正文、旧回执、summary、角色和未知字段。提交事务重新验证完整图与纯投影，Web 章数不充当 revision。

所有变更仅在同一三 store readwrite 事务内发生，oncomplete 才确认成功；预检失败或 onabort 才证明该次未写。确认/生成期间的并发续写、重写、截尾或摘要变化使旧 CAS 失败。这保证这两个写者的原子性和提交时源一致性，不宣称其它 metadata writer 已全局隔离。

## 中章重写

原产品语义保持：重写第 k 章后删除后续章。使用原 action=rewrite、sourceChapterId、章节位置、包含原目标的最多十二章窗口；章前角色与安全摘要使用尾章合同的共享规则。

单事务保留旧目标全文、扩展和回执，仅将其改为 superseded；删除 index>k 的全部章（含旧 superseded）和 boundary>=k 的 checkpoint；写入新 rewrite 第 k 章、新 boundary k 与 count=k 的 session。标题、seed、计划、分支来源和未知 session 扩展保留。

保存包采用独立 action=middle-rewrite；新章的封闭有界 v3 receipt 使用 kind=middle-rewrite，其余字段、ID/摘要约束与尾章 v3 相同。精确旧回执优先于后来图变化；新章后来 superseded 仍可证明历史成功，已真正删除的回执不能复活。

完整输出先保留，再冻结保存包。角色未决、原包重试、导出、丢弃、已保存待读沿用现完成章状态机。所有已完成章的 unknown 查询都只核对原操作的精确回执，absence、mismatch 和读失败均不授权再次提交；只有明确 not-written 可重试原包。首章已有的显式另存新会话入口不变。

## 所选章截尾

首章继续走既有整会话删除确认。其它章在新鲜同图上准备独立 truncation 包，保留原确认文本；确认后同事务 CAS、删除 index>=k 的全部章与 boundary>=k 的 checkpoint，写入回退到 k−1 的 session。工作角色取第 k 章原输入，新的 lastChapterInputCombatants 取第 k−1 章原输入，均保留 checkpoint/首章 seed/仅最新章 lastInput 的兼容优先级；摘要覆盖达到 k 时失效。

没有新增持久删除回执或账本。结果 unknown 时保留原身份与源图，阻止旧视图继续修改该会话，并提供独立只读核对入口。读到相同图、目标消失或后来变化仅能报告当前状态，不能证明原事务未写或制造历史成功。只读重载成功后可解除旧视图阻断，历史结果未知提示保留；新的删除必须再取新鲜图、重新明确确认，绝不自动重放原请求。读取失败继续保留原未知操作；已确认成功后读取失败仍称截尾完成，只重读。

同 tick 双击在首次 I/O 前互斥，切换会话或同会话 ABA 以 selection epoch 隔离；晚成功不得抢回旧选中项。captured reload 必须明确返回已发布才可解除旧视图阻断；被新读取取代而静默结束不是重载成功，包括另一会话保存后的回读失败。

## 实现与保留边界

Web 入口为 middle-rewrite-commit-storage、truncation-commit-storage 与真实 useBattleStorySession；纯投影位于 domain 的 arena-story-middle-rewrite 和 arena-story-truncation。合成 fake-IDB 故障与真实 hook 测试不代替真实浏览器、Windows/Tauri 或生产验收。Native rewrite 的 schema、revision 与历史 receipt 仍需独立合同，入口继续关闭。
