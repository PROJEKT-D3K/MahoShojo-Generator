# Desktop 多人原生会话最小闭环

状态：工作规格，范围与 HTTP/WS 传输容量已确认；Native 缓冲、消费回执与生命周期仍须实施验收。归属既有 D5.1c，不代表完整多人生成交付。

依据：[线上本地整合规格 DESK-ONLINE-006/012/013](./2026-10-04_202000_Desktop线上本地整合与AI配置共源规格.md)、[Room 共享 Hono 入口规格 ARI-001/004/005](./2026-08-31_080100_Arena生产Room入口简化与架构重整规格.md)。本片只扩展 Desktop 的受控 Room 通路，不修改 Web 默认协议、房间权限或生成规则。

## 1. 可交付范围

首片包含 `discover/create/join/session/ticket/leave/close` 七项已有操作，路由以 `packages/contracts/src/room-http.ts` 为准：collection 的 GET/POST，以及 `/:roomId/{join,session,ticket,leave,close}`。ticket 仅供 Native 内部消费。Desktop 必须同批完成创建或加入、权威成员与在线状态、断线重连、成员退出及房主关闭的真实页面闭环；不能只交 HTTP 快照页面。

- 创建仅在用户明确操作后发送既有 sharedConfig 投影；加入不上传当前本地草稿。沿用现有空草稿/可共享配置语义及 visibility，不新增公开发现权限。
- 页面明确当前阶段；不展示不能执行的配置发布、提案、踢人或生成按钮。这些操作既不注册 Native capability，也不回退 Web 请求。已有房间的配置与生成状态只能作权威状态展示；本片不宣称正文恢复或生成控制已实现。
- 房主退出导致关闭、成员退出只撤销自身 membership，遵守既有服务端裁决。失联/本机断订阅不表示已退出房间或已停止服务器生成。
- 多人期间有效执行位置锁为 server，普通 AI 配置不落盘修改；退出恢复普通偏好。不上传 Provider 配置、Key 或本地生成结果。

## 2. 同路径 opt-in 与身份

服务目标由现有 `config/hosted-routing.json` primary 构建期固化；WSS 只从该 HTTPS origin 派生，无 DR fallback。Rust 固定注入当前环境已批准的 Web caller Origin，该值与 Hono 服务 origin 分开；renderer 不得提供两者。保留浏览器 exact Origin/CSRF 策略，不添加通配或无 Origin 豁免。Origin 仅为 CSRF 兼容，实际权限仍来自受保护 cookie 的真实 resolver。

新增 `packages/contracts/src/desktop-room-session.ts` 定义以下窄协商，不扩为通用网络代理：

- 每次 HTTP 都由 Native 注入 `X-Mahoshojo-Desktop-Room-Protocol: desktop-room-session-v1` 与 `X-Mahoshojo-Room-Expected-User-Id: v1:<正安全整数>`。
- 每个 POST 都使用闭合外封套 `{ desktopRoom: { version: 'desktop-room-session-v1', expectedUserId }, request: 原操作DTO }`。仅 create 的 desktopRoom 还必带 `createMode: 'new' | 'resume-only'`，其他操作拒绝此字段。header/body 版本与 owner 必须完全相等；缺失、未知版本、未知字段均拒绝，不能降回 legacy 分支。
- 新服务在所有 Room service 与 operation rate-limit 前核实际 resolver.userId 等于 expectedUserId。全局 ingress limiter 仍可能计数。房间 `self.userId` 是 opaque 成员 ID，不是账号 numeric owner。
- 仅协商请求使用闭合响应 `{ desktopRoom: { version, viewerUserId }, result: 原操作回执 }`；错误采用闭合 error 分支，包含白名单 code、有界 message 与 outcome；只有 resolver 与 expected owner 匹配后 viewerUserId 才为 numeric，否则为 null，不返回实际错配账号或业务数据。GET 的 outcome 为 not-applicable；POST 在任何 Room service 前的明确拒绝为 not-applied，进入服务后保守为 unknown，均不表示认证或限流没有副作用。Native 对缺失/错误版本、错误 viewer、非法原 DTO 一律拒收，不展示正文或继续 ticket 流程。
- 未协商 Web 请求与响应保持原样。Native 不接收任意 URL、header、method、cookie、ticket、secretRef 或自报角色权限。

### 旧部署与滚动节点

首片各 POST schema 均为顶层 `.strict()`，旧节点必拒绝上述外封套；新节点核对协商后才剥封套并复用这些原 schema：

| 首片写入 | 原严格 schema | 原业务调用前的解析位置 |
| --- | --- | --- |
| create | ArenaRoomCreateRequestSchema | 创建 receipt 读取、额外创建预算、memberships.create 之前；包括 new/resume-only 两种 wire |
| join | ArenaRoomJoinRequestSchema | memberships.join 之前 |
| ticket | ArenaRoomTicketRequestSchema | websocketAuthority.issue 之前 |
| leave / close | ArenaRoomEpochMutationRequestSchema | memberships.leave / close 之前 |

因此旧节点可以拒绝业务写入、ticket 签发和生成，不承诺零限流计数。验收必须将每条新 wire 送入冻结旧 handler，断言这些业务调用为零；不能仅凭 header 或一次能力 GET。GET 旧节点可能正常读取，Native 拒收无协商回执即可；`session` 会进入 actor recovery，甚至可能收敛已到截止时间的房间关闭，不能描述为绝对无存储维护的纯读。新节点 owner 检查必须早于该 recovery。

## 3. Native socket 与双重作用域

新增独立 `arena_room` Native consumer，复用现有账号受保护槽、固定请求构造与 main-ui ACL，不扩大 `arena_hosted_*` 授权。窄 IPC 为 `arena_room_attach/request/subscribe/detach`：attach 只在本机建立作用域，request 区分上述六种固定 HTTP 操作与闭合的本地 pull/ack 分支（后者绝不发 HTTP/WS），subscribe 内部取得 ticket，detach 只关闭匹配本机作用域。需采用已维护的 Rust WSS 客户端并复用正式 TLS 验证，不手写握手，不开启压缩、代理继承、重定向或明文降级。

- attach 返回随机非秘密 handle，绑定 Native 账号快照和真实 Document 代次，不返回凭据派生 fingerprint。后续操作强制引用该 handle，失效后不得在旧 callback 中自动 attach 续签。前端在 attach 前后核当前面板、账号验证与凭据意图代次；迟到 handle 只 detach 丢弃。同一 Document 按显式 attach 的发起代次保留最新意图，不能按异步完成顺序让旧 attach 取代新 attach；旧 detach 只能命中原 handle。
- 真实宿主以私有 ResourceTable marker 的 `Arc` 身份匹配，不能用可复用 label 代替；marker 缺失也不能重置未消费账。主 frame 的 document-start nonce 不可改写，固定 Native eval 同时核 nonce 与随机 challenge；Started 立即撤销并标 loading，Finished 后才允许稳定 attach。物理 eval 单槽在超时后仍占用，只有真实 callback 或匹配实例销毁才能释放。每个 Document 按显式 attachIntent 单调推进，旧排队调用不能取代新意图。导航开始到各平台 commit 回调之间的实际时序仍须实机验收。
- 账号作用域：在现有账号写入锁内一起冻结 raw session 与 credential epoch；所有 await、成功、错误、401 条件清理都检查原作用域。同账号重新登录也撤销旧作用域。当前原凭据的过期或腐坏清理即使遇删除 IO 失败也先撤销旧 Room 连接；Room 受检条件清理保留实际存储错误，不假报已删除。旧 cached-first 腐坏记录恢复只表示无可用缓存，不作为物理凭据删除成功的回执。
- 房间作用域：roomId、服务器 roomEpoch、Native 连接代次及 main-ui Document 代次共同绑定；旧 ticket、HTTP、socket callback 或 detach 不能影响新连接。服务器 recovery 换 epoch 后，先丢弃旧副本并安装匹配 owner 的新 session，再明确重连；不以重连重放业务 mutation。
- 登出、凭据替换/清除、切房、Document reload/destroy、主动 detach 必须立即撤销 ticket flight、重连 timer 与闲置 socket。仅在下一帧检查身份不足以关闭持续 Pong 的旧在线连接；应在账号 epoch 更新处增加窄内部撤销信号。
- ticket 只短暂存在 Native 内存。复用原固定 WSS path 和既有一次性 ticket query handshake，URL、票据及错误原文不得进入日志、IPC、持久化或导出。Native 必须校验 ticket 响应固定 path，不能跟随任意返回地址。
- 必须成功选择 `mahoshojo.arena-room.presence.v1`；缺少 presence 能力时明确不可用，不回退为假在线。复用原 Ping/Pong、membership/role/roomEpoch 校验及一次性消费。
- HTTP session 与 socket.open 都不能单独证明在线。只有当前连接、room/epoch 匹配的服务器 snapshot 与 presence 才建立在线展示；presence 的成员必须来自 active membership。断线立即清空 presence。
- 只采用 Native 有界缓冲、小 Channel 通知、本地 pull/ack 这一条传输路径。通知不带正文；pull 的闭合批次带 handle、subscriptionId、batchId 与递增 sequence，同 scope 最多一笔未 ack，不能重复派发同一批。TS 完整验证并接纳到有界状态后才 ack，不把回调到达当消费或像素已绘制。ack 只单调推进已发范围，重复幂等，未来序号/错误 scope 拒绝。
- 已交给 Tauri 但未 ack 的通知/批次按完整序列化字节纳入跨订阅总额度；invoke 大响应也可能进入框架队列，不能假定 pull 绕开它。退休/detach 清 Native 自有正文，但不退还框架在途额度；超额暂停并关闭 socket，UI 明示重新打开真实窗口/重启应用的恢复方式。timeout、reload、换账号不能自动清账。退休 ack 仅释放同 Document 精确旧批次自身额度，不续签、不发网络、不推进新订阅；无法证明跨 Document 消费时保留至真实 Webview 销毁。
- 所有业务 HTTP（含 discover、session 与 ticket）按真实实例共享一个物理在途槽，退休任务实际结束前不释放；socket 后台任务同样等待真正退出。业务 POST 不自动重放。HTTP 派发前预留固定终结投递容量，成功/失败必须关联原 requestId、operation 与 outcome；成功回包尚未可靠交付或确认时仍保留原意图，不能因本地缓冲失败偷偷新建。 业务 HTTP 与存续订阅分别在原总预算内预留至多 1 KiB 的终结通知容量，订阅预留不占住在线 leave/close 的 HTTP 槽。当前受检认证失效或原 HTTP/订阅读取凭据失败时，原子选取一个闭合 `revoked` 终结；内部 ticket 失效只标记原 subscribe（requestId 为 null），不暴露 ticket。只释放尚未投递的预留，桥仅终结原作用域；该通知独立计入交付债，其精确 ack 不释放任何旧未消费批次。通知失败不等于原 mutation 未发生。
- 无任意 WS send；仅允许 Native 自己发送既有固定 resync 请求。失序、慢消费者或溢出走明确 resync/断连，不悄悄丢帧后继续显示最新状态。重连重新取 ticket，沿原 control cursor 恢复，并用当前连接的完整 snapshot 与包含 active self 的 presence 确认在线；本片不收集或伪装完整 story 正文。权威关闭与自身 membership 撤销作为明确终态交付，不当作暂时断网重连。

生产 WSS 采用固定 TCP、平台验证 TLS 后的 handshake-only 客户端，SNI 与证书验证不放宽，仅声明 HTTP/1.1，不接受扩展或重定向。显式使用 NoKeyLog，禁用 early data 与 secret extraction。Desktop 普通 runtime/test 依赖图的 `log` 在 debug/release 均编译为最高 info，因此开发时也不能用 trace/debug 打开第三方握手和帧正文日志；这不覆盖独立构建工具日志。平台验证器仍可能记录 OS、CA 或证书警告/错误，不得误称证书零日志。传输错误、Close reason、URL、Request/Response 原件始终只在私有边界内处理，对外仅给固定码。

## 4. 未知结果与本地边界

所有 mutation 禁止网络自动重试。POST 一旦可能已派发，响应丢失、超预算或缺失/非法 version、viewer、DTO 都归结果未知；拒收展示不等于业务未发生。只有明确受检认证失败且原 raw+epoch 仍当前时才可沿既有条件清理凭据，普通协议/业务错误不能删凭据。create 冻结 creationRequestId、原正文和账号作用域；结果未知时禁止新 ID 的隐式再次创建。现服务没有 creationRequestId 的 GET 查询接口，只能由用户显式确认后，以原 ID/原正文重发既有幂等 create 来核对；UI 不得将其称为只读查询。确认前再次核原 owner/credential epoch；`resume-only` 由服务端强制 `memberships.create({ requireExistingCreationReceipt: true, ... })`，不能把 `hasCreationReceipt=false` 当首次创建。复用原 service 对账号、creationRequestId、正文 digest 和活跃原房间的检查；receipt 过期/丢失、原房间已关闭或原意图失效时只返回明确 conflict/unresolved，不能新建或偷偷换 ID。`new` 保持原创建逻辑，未协商 Web 行为不变；本机计时不能证明 receipt 存在。join、leave、close 先用 session 核对；未知、拒绝与已结束分别呈现，不因重连或恢复自动重发 mutation。

本片不新增本地 room membership 数据库。Native 进程内保留待核对意图供 Document 重建后显式恢复；意图仍绑定原 raw、credential epoch 与撤销 token，不能凭 numeric owner 或新 attach 续签。同账号重登也废止旧意图；临时凭据读取 IO 失败只保留私有待核对，不当作已换账号或已完成。账号切换不得向新身份暴露旧意图；跨进程恢复尚未实现时必须如实提示，不能从草稿自动重建房间。离开页面与显式退出/关闭是不同操作，页面关闭前须处理在途或未知意图。

## 5. 容量与验收门

以下为 Desktop 的传输拒收门：原业务 POST 的完整 UTF-8 JSON 上限为 64 KiB，固定外封套另留 1 KiB，完整 request 的实际 raw body 上限 65 KiB；Native 封套中的 request 在任何 schema 投影前按 compact JSON 的 UTF-8 字节限制为 64 KiB，legacy Web 仍按原 raw body 计量；HTTP 响应完整序列化上限 256 KiB；完整 WSS message（含碎帧聚合）仍为 64 KiB。原 ticket 不超过 4,096 字节、寿命不超过 60 秒。限制按实际 UTF-8 wire bytes 判定，不按字符串长度，也不能截断后接受。

这些容量不保证容纳所有原 schema 合法数据。比如原 ISO 时间戳允许长小数精度，合法目录也可能超过响应上限；Desktop 对过大的 GET 明确显示暂不可用，对可能已派发的 POST 保留结果未知与原意图。服务端不能通过裁剪配置、材料、成员或时间字段伪造可用回执，也不为 Desktop 放宽或收紧 Web 原格式。Room 状态机保证 snapshot 能放入控制帧，不代表含重复 self 的完整 HTTP session 也只有 64 KiB。

Native 慢消费相关容量仍是实施验收门：含作用域元数据的单批 IPC 上限候选 256 KiB、小通知 1 KiB、Native 自有缓冲 256 KiB、跨退休订阅框架未 ack 总额度 1 MiB。须以完整序列化批次、重复 pull、慢消费者、多次退休与真实 Webview 销毁验证；不能从 HTTP/WS 样本推断队列回收已经成立。

Native Rust 字符串的可表示边界限定为 Unicode 标量文本，IPC 的字符串值和对象键都拒绝孤立 UTF-16 高/低代理项，合法配对不受影响；先验证再计 UTF-8 字节，不替换、规范化或截断。原 JSON/Web schema 不因此改变，合法但不可表示的上游 GET 明确拒收，已派发 POST 保持结果未知。

跨退休额度只约束本片受控业务路径的 Native 缓存、通知和大结果。固定小回执与错误小于 1 KiB，由 bridge 串行等待每次 invoke 完成，不增加 ack-of-ack；等待消费者不持 invoke 队列锁，退出先同步废止旧回调再发 detach。此保证不覆盖任意直接 invoke 洪泛或框架自动错误回执的全局内存。已完整验证且确认同 Document 的退休批次可丢弃后精确 ack，只释放自身债务；跨 Document 或无法确认消费的批次仍不清账。

TS/Rust 应消费同一黄金样本，覆盖 32 成员、50 项目录、完整权威 snapshot、Unicode/JSON 转义、重复 self、新封套和恰好超界一字节；拒绝不安全整数、非对象输入、未知字段与过深结构。预算调整须先更新该窄合同，不放松 Web 原预算。

验收分层：

1. 冻结旧 handler 与新 handler：逐 POST 的拒绝/双标记一致性/owner 顺序；原 Web 全回归；resume-only 的缺失/过期/关闭/异体正文/跨账号 receipt 均零新建；GET recovery 先验 owner；重定向与错误无秘密泄露。
2. 真实 Native 模块和合成 HTTP+WSS：presence 子协议、Ping/Pong、ticket 过期/重放、帧边界、主动注销闲置连接、同账号重登、切房、reload、迟到结果、cursor gap、唯一终结、unknown 零自动重放。
3. 真实 Desktop 页面与同一服务器权威 fixture：host/member 互相看见 presence、断线重连、member leave/host close、权限与错误路径；Web 宿主实际回用同一展示/纯状态规则。禁止 renderer 网络和 secret 通路，三处 command/ACL 登记相符。
4. 原完整 CI；Windows/Tauri、OS 凭据、真实部署 WSS 和生产配置分别待验，不用合成测试替代。新 producer 需要用户另行部署，本源码施工不执行生产部署。

## 6. 原子实施顺序

- 合同与 producer：新增窄 opt-in schema/fixture，原 HTTP handler 受检适配与旧 client/server 兼容测试；不复制 Room 业务服务。
- Native consumer：固定 HTTP、WSS、主动身份/Document 撤销及有界 Channel，与同一 fixture 端到端联测；不提前开放尚无 consumer 的其余路由。
- Desktop 实际入口：同批接通上面的 host/member 会话闭环，抽取的最小展示/纯状态接缝必须 Web 当下回用；不整体迁移 Web controller 或 BattleStore，不建立只有未来消费者的平台。

前两步可以分原子提交审查，但仅在第三步闭合后宣称本片产品可用。D5.1c 后续配置/提案/生成仍复用原权威协议，另按实际消费者扩展，不能据此开放 Web 的任意 customProvider JSON。
