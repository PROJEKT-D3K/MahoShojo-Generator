## 产品与共源边界

- Desktop 新分支先限 Direct：任意已保存活动章 k（计划仍容纳 k+1）产生独立新会话，包含完整活动前缀 1..k、检查点 0..k 与新生成章 k+1。源故事不变，删除源不影响目标。不加入重写、截尾、插图、自动备份或永久账本。
- 角色章末状态、锚点摘要安全性、分支标签与前缀身份/摘要映射 **MUST** 真正共源于 domain；Web 真实业务消费同一函数。纯提取不等于双端分支完成，Desktop owner 未消费时必须保留明确迁移差距。
- 首片 **MUST** 保持 Web 原有 ID 分配、有效角色回退、旧 active rewrite 历史、boundary0/anchor 补齐及生成协议。身份分配作为宿主输入，不在纯层调用随机数或时间；纯投影不授予写入权限，不承担不可信记录校验。
- 最终 Web 分支 **MUST** 在同一 session/chapter/checkpoint 三 store 事务内核对冻结源实际图/身份、目标不存在、完整写集合，以 oncomplete 成功。源 CAS 覆盖 legacy rewrite/summary/edit 等实际变更，不套用 Native revision=headCount。此 adapter 完成前保持旧保存语义并明确不得宣称原子化。
- Hosted arena-story-v1、start/continue receipt、pointer/claim/restore 围栏及 hash 金样 **MUST** 保持。domain 已有 branch union 不代表 Hosted 协议获准扩展。

## 预算计量与 Native 可行性门

| 对象 | 约束 |
| --- | --- |
| 新增模型输入/输出、角色结果 | 原32角色、12MiB请求、4MiB正文/推理、16MiB角色响应不变 |
| 新增保存包、shared staging/upload、active槽 | 原128MiB相应计量边界不增；共用预算，不各路径独享 |
| 逻辑在途与 frame | 原384MiB逻辑边界与4MiB传输frame保持；frame不是RSS承诺 |
| 已保存历史前缀的 Native 内部复制 | 逐记录核验并精确统计复制写量、journal/磁盘峰值与锁时间；**不新增整段历史合计128MiB上限** |

历史通过多次合法保存可超过128MiB。**MUST NOT** 将历史累计量重解释成新增上传或保存包预算，也不假设任意大小历史已被证明可行。每条源/目标仍服从受检记录边界；不得全前缀 renderer hydration 或累计 transformed String 数组。超限新增内容保全文/导出，不删角色、历史或扩展，不重模型。若实测必须新增历史总量限制，先说明将拒绝哪些现有故事并另行确认产品取舍，不静默加门。

Native 首选同 store 源辅助逐记录物化；复用 arena_story_pending.rs 的 raw member scanner、UTF-16键比较及原 token 能力，不新增通用 parser/patch 引擎。仅重写明确身份字段；未知键/值 token、孤立代理和未知重复扩展 **MUST** 保留；歧义重复身份/权威键拒绝，不递归禁止 opaque 扩展重复键。原 scanner 不等于完整 copier，原键 token 保真、关系/哈希核验、逐条释放仍须实测。

资源门 **MUST** 覆盖超过128MiB的多次合法历史、长单条/转义放大、大量短章、RSS、journal、磁盘不足、锁占用、取消/rollback。不能用4MiB读取frame代替证明。若改用逐记录 TS 变换，必须重新核算全prefix staging总占用；逐条上传本身不降低保留预算。未过门不开放 Native 分支。

## 事务、身份与回执

- 新写 **MUST** 同一事务核 source session 的完整 instance/revision/digest、head/count、锚点及checkpoint，与目标不存在；后缀续写也冲突。目标完成后与源独立。只新写要求当前 source CAS。
- exact success receipt 查询 **MUST** 先于 source 存在或当前 instance 检查；来源已删除或进程重启仍可确认原保存成功。query 不授予写权；unknown 仅查原 target/operation/requestDigest，absence/mismatch/IO不能自动重存。明确 rollback 才能显式重试原冻结包。
- 复制章保留历史 action/generationId（包括合法的历史 branch），但其 operation_id **MUST** 各自独立（如目标 chapter.id）。所属 branch operation 仅在 copy provenance marker 关联，不能所有复制行共用 UNIQUE operation_id。
- copy marker **MUST NOT** 复制旧生成receipt、冒充新模型执行或被查询当成功生成回执。目标新章 action=branch，sourceChapterId指向目标内锚点；branchOf仅记录来源。后续线性续写继续旧v1 receipt。
- 新branch receipt/copy marker **MUST** 有明确version/discriminant；旧v1 shape与其2048B读取上限不变。新shape亦限序列化UTF-8 **2048B**，无全前缀ID数组或无界用户文本。仅固定有界ID、digest、计数和范围；精确字段/单字段上限与最坏序列化金样须在新增writer之前冻结并校验。若证明放不下，不可直接扩大旧reader；另审新shape。首片不创建未冻结wire DTO。
- 若保留物化digest，必须定义有序增量算法；不得引入冗余sourceSnapshotDigest或第二namespace而无额外保护。目标sessionId可作为映射namespace，Native只做身份物理映射并与TS对拍，不复制Prompt/摘要/角色规则。

## Native 存储后继冻结（2026-10-11）

以下冻结内部磁盘格式和物理映射；不注册 IPC，不扩展 Hosted v1，不开放两页入口。Native 完整资源门仍按上文待验。内部 branch staging 与线性/Hosted upload 共享原槽和128MiB预算；新增包固定仅 `session/chapter/checkpoint1`，历史 seed、章与 checkpoint 从同 store 逐条复制，不占新增上传预算。目标 session 的摘要、角色及 branchOf 由 domain 投影的宿主提供，Native 不另写摘要/角色业务。

### 封闭 receipt 与 copy marker

- branch success 固定序列：`version=2, kind="branch", operationId, sessionId, chapterId, chapterIndex, revision, chapterCount, prefixEndIndex, anchorChapterId, anchorCheckpointId, checkpointId, requestDigest`。
- 六个 ID 均复用1–128字节 `[A-Za-z0-9_-]`，`requestDigest` 为严格71字节 `sha256:`+64小写hex；`prefixEndIndex=k` 为1..9007199254740990，其余三个数值均=k+1；`chapterId=operationId`。anchor 两ID为目标第k章/boundary k，checkpointId为目标新增k+1边界。序列化上界1123B，真实Rust serializer金样sha256=`93d6b217eb2635b61b98b502f0b2ee9948d35cb8bef61320e4a2f4c1b0b67861`（ID分别o/s/o/a/p/q各128次，digest f×64，计数取上界）。
- copy marker 固定序列：`version=2, kind="branch-copy", branchOperationId, sessionId, chapterId, chapterIndex, sourceSessionId, sourceChapterId, requestDigest`。五ID同上，chapterIndex为1..k；上界891B，金样sha256=`b5d0cd43e68e9fb930ec936b3b0aad1662b3cb1234ef05e547839634749cbf13`（ID分别o/s/c/u/v各128次，digest f×64，index取上界）。本章operation_id=自己的chapterId；source两ID仅直接来源provenance，无跨会话FK。它不代表一次模型执行，任何生成success查询不得把它当成功。
- 两形状均拒未知/重复字段、错误discriminant和越界；先2048B读取门再解析。旧v1 shape与reader不变。copy必须关联同target真实branch receipt、相同requestDigest及完整1..k范围，同批sourceSessionId一致；不能要求source存在。
- 不保留全前缀ID数组、物化digest、sourceSnapshotDigest或第二namespace。success查询仅target/op/requestDigest，不要求当前session revision等于历史receipt revision，也不看source/current instance；当前source CAS只用于新写。

### 物理映射与冻结请求

复制ID算法：SHA-256依次输入ASCII `maho:arena-story-branch-record:v1`、NUL、kind单字节（章c/checkpoint p）、index的u64大端、目标sessionId UTF-8长度u64大端、sessionId字节；结果为 `branch_`+64小写hex。目标sessionId是唯一namespace。宿主把此物理ID分配交给已有domain投影函数；Native仅核关系并物化，不复制业务投影。

章仅改 `id/sessionId/sourceChapterId/status/supersededByChapterId`，checkpoint仅改 `id/sessionId/chapterId`；原key token、未知成员和原值token保持。Native线性源第1章start/null，之后continue或历史branch并指向同source上一章；不接受rewrite、断链或superseded。目标status=active、supersededByChapterId=null、可选link缺失补null，与domain归一一致。顶层权威重复键按UTF-16键相等拒绝，opaque子树不递归禁重。每条源长度/hash/index关系先核验，写出长度/hash重算；无历史总量128MiB上限。

内部 `BranchManifest` 固定序列为 `version=2/operationId/sessionId/source/parts`；source固定序列为 `session/seed/expectedLastChapterId/expectedChapterCount/anchor/anchorIndex/checkpoint`，四descriptor沿现RecordDescriptor序列固定，均同source instance/revision/session；parts沿现PartDeclaration序列，固定Session/Chapter/Checkpoint1顺序。requestDigest=SHA-256（ASCII `arena-story-branch-wire-v2`+LF+真实serializer紧凑UTF-8）。它绑定source完整session/seed/anchor/checkpoint身份、长度/hash、head/count、instance/revision及新增三件内容声明；不是逻辑JSON值hash，不更改既有hash金样。写事务重核全部CAS和目标不存在，再逐条复制，目标初始revision=count=k+1，后续continue仍用原v1。

schema9追加迁移，不改v1–8 migration字节。因循环FK，三张story表一起临时复制原列值、删除旧表、改回原表名，foreign_keys始终开启，版本/journal同事务提交。它需临时磁盘和writer锁，不能把小库迁移验收当大库资源已过；失败须rollback保旧库。backup依自身历史版本分派：v5–8仍旧线性规则；v9采用目标内部branch/copy关系规则。新写只审计受影响target，全库审计用于backup/restore。

内部stage在实际COMMIT前或显式ROLLBACK失败时标记unknown；同token再次end仍先查exact成功，无成功则只返unknown，零二次写。明确rollback成功的取消不置unknown。该内存位不是完整owner恢复合同：abort/expiry/fresh begin/重启的原generation围栏尚未接入，IPC开放前必须补齐；本存储切片不得据此宣称整条unknown旅程已闭合，也不新增永久账本。
