# 连续故事分支窄合同

状态：`accepted`。2026-10-10；D5.1b b-2 / DESK-105 的窄后继。

本文接受分支目标合同，不声明实现已完成。首片只迁移纯业务投影并让 Web 真实消费，SQLite8 / IDB4、Web 旧多步保存与 Desktop 入口保持原状。后续原子 writer、迁移、Native 资源验证与两页接线均未交付。此前 DESK-103/104 的排除项保持当时范围，不是永久禁止。

## 产品与共源边界

- Desktop 新分支先限 Direct：任意已保存活动章 k（计划仍容纳 k+1）产生独立新会话，包含完整活动前缀 1..k、检查点 0..k 与新生成章 k+1。源故事不变，删除源不影响目标。不加入重写、截尾、插图、自动备份或永久账本。
- 角色章末状态、锚点摘要安全性、分支标签与前缀身份/摘要映射 **MUST** 真正共源于 domain；Web 真实业务消费同一函数。纯提取不等于双端分支完成，Desktop owner 未消费时必须保留明确迁移差距。
- 首片 **MUST** 保持 Web 原有 ID 分配、有效角色回退、旧 active rewrite 历史、boundary0/anchor 补齐及生成协议。身份分配作为宿主输入，不在纯层调用随机数或时间；纯投影不授予写入权限，不承担不可信记录校验。
- 最终 Web 分支 **MUST** 在同一 session/chapter/checkpoint 三 store 事务内核对冻结源实际图/身份、目标不存在、完整写集合，以 oncomplete 成功。源 CAS 覆盖 legacy rewrite/summary/edit 等实际变更，不套用 Native revision=headCount。此 adapter 完成前保持旧保存语义并明确不得宣称原子化。
- Hosted arena-story-v1、start/continue receipt、pointer/claim/restore 围栏及 hash 金样 **MUST** 保持。domain 已有 branch union 不代表 Hosted 协议获准扩展。

## 预算计量与 Native 可行性门

| 对象 | 约束 |
| --- | --- |
| 新增模型输入/输出、角色结果 | 原32角色、12MiB请求、4MiB正文/推理、16MiB角色响应不变 |
| 新增保存包、shared staging/upload、active槽 | 原128MiB相应计量边界不增；共用预算，不各路径独享 |
| 逻辑在途与 frame | 原384MiB逻辑边界与4MiB传输frame保持；frame不是RSS承诺 |
| 已保存历史前缀的 Native 内部复制 | 逐记录核验并精确统计复制写量、journal/磁盘峰值与锁时间；**不新增整段历史合计128MiB上限** |

历史通过多次合法保存可超过128MiB。**MUST NOT** 将历史累计量重解释成新增上传或保存包预算，也不假设任意大小历史已被证明可行。每条源/目标仍服从受检记录边界；不得全前缀 renderer hydration 或累计 transformed String 数组。超限新增内容保全文/导出，不删角色、历史或扩展，不重模型。若实测必须新增历史总量限制，先说明将拒绝哪些现有故事并另行确认产品取舍，不静默加门。

Native 首选同 store 源辅助逐记录物化；复用 arena_story_pending.rs 的 raw member scanner、UTF-16键比较及原 token 能力，不新增通用 parser/patch 引擎。仅重写明确身份字段；未知键/值 token、孤立代理和未知重复扩展 **MUST** 保留；歧义重复身份/权威键拒绝，不递归禁止 opaque 扩展重复键。原 scanner 不等于完整 copier，原键 token 保真、关系/哈希核验、逐条释放仍须实测。

资源门 **MUST** 覆盖超过128MiB的多次合法历史、长单条/转义放大、大量短章、RSS、journal、磁盘不足、锁占用、取消/rollback。不能用4MiB读取frame代替证明。若改用逐记录 TS 变换，必须重新核算全prefix staging总占用；逐条上传本身不降低保留预算。未过门不开放 Native 分支。

## 事务、身份与回执

- 新写 **MUST** 同一事务核 source session 的完整 instance/revision/digest、head/count、锚点及checkpoint，与目标不存在；后缀续写也冲突。目标完成后与源独立。只新写要求当前 source CAS。
- exact success receipt 查询 **MUST** 先于 source 存在或当前 instance 检查；来源已删除或进程重启仍可确认原保存成功。query 不授予写权；unknown 仅查原 target/operation/requestDigest，absence/mismatch/IO不能自动重存。明确 rollback 才能显式重试原冻结包。
- 复制章保留历史 action/generationId（包括合法的历史 branch），但其 operation_id **MUST** 各自独立（如目标 chapter.id）。所属 branch operation 仅在 copy provenance marker 关联，不能所有复制行共用 UNIQUE operation_id。
- copy marker **MUST NOT** 复制旧生成receipt、冒充新模型执行或被查询当成功生成回执。目标新章 action=branch，sourceChapterId指向目标内锚点；branchOf仅记录来源。后续线性续写继续旧v1 receipt。
- 新branch receipt/copy marker **MUST** 有明确version/discriminant；旧v1 shape与其2048B读取上限不变。新shape亦限序列化UTF-8 **2048B**，无全前缀ID数组或无界用户文本。仅固定有界ID、digest、计数和范围；精确字段/单字段上限与最坏序列化金样须在新增writer之前冻结并校验。若证明放不下，不可直接扩大旧reader；另审新shape。首片不创建未冻结wire DTO。
- 若保留物化digest，必须定义有序增量算法；不得引入冗余sourceSnapshotDigest或第二namespace而无额外保护。目标sessionId可作为映射namespace，Native只做身份物理映射并与TS对拍，不复制Prompt/摘要/角色规则。

## 迁移与退出门
