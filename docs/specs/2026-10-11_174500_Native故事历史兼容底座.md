# Native 故事历史兼容底座

状态：候选，默认数据库仍为 schema 10。schema 11 只在合成测试的显式作用域内迁移；未开放 rewrite 写入、IPC、ACL 或页面入口。Linux headless 证据不能代替 Windows/Tauri 实机验收。

## 存储与历史证明

迁移保留 schema 1–10 的原 SQL。候选 11 在同一事务中先审计旧故事图和 pending，再重建 session/chapter/checkpoint 循环外键组件，保留 `foreign_keys=ON`，将新图验证、迁移 journal 和版本一起提交。旧正文、未知 JSON 成员、摘要、operation 和 receipt 的字节不重写。事务回滚未确认时连接必须停止使用。

chapter 增加 `status`、`superseded_by_chapter_id` 和 `committed_revision`。仅活动章的 `(session_id, chapter_index)` 唯一；生成行记录提交 revision，branch-copy 为 NULL。活动章序列连续，`chapterCount` 为活动数；revision 独立递增，不能由活动数或物理行数代替。当前历史审计仅接纳尾章重写：旧、新章同 index，相邻生成 revision，旧章指向新章，新章 `sourceChapterId` 指向旧章。中章截尾需要单独扩展合同。

所有历史 checkpoint 保留。零边界每会话唯一；非零 checkpoint 按所属 chapter 唯一。当前角色状态由活动章与其 checkpoint 关联，历史回执使用原 chapter/CP 身份和边界验证，不能要求它们仍是活动 head。

v1 linear、v2 branch/copy 的 wire 字节格式不变；schema 5–8 保持旧线性审计，9–10 保持原 branch 审计。11 的生成行将 receipt revision 与 `committed_revision` 比较。内部 v3 `tail-rewrite` 仅用于历史审计，包含 operation/session/chapter/index/revision/count、target、input/output CP 和 requestDigest；本片不提供 producer 或 manifest。

## 既有消费者

- 活动目录、续写窗口与 Markdown 导出只枚举 active；按 ID 仍能读取 superseded 原件
- 现有 linear/branch writer 在 11 下补写 committed revision；branch 源 revision 与 count 分别校验
- 尚未实现 rewrite 前缀复制的 lineage 映射，因此有重写历史的 branch 源明确拒绝，正常读取和导出不受此限制
- 整会话删除核实际历史行数，返回物理删除数量；原显式确认、未知结果及重启围栏不变
- pending 的 11 原件校验将 chapter index 与 revision 分开，计划和窗口使用 index；最终保存包必须覆盖同一 input chapter index，仍由既有 revision/head/count CAS 决定写入
- 备份检查版本、新增列、partial unique 和 chapter-owned CP 约束，拒绝旧版本标签伪装的新表形状；恢复先按备份原版本审计，再走迁移，保留 restored pending 的 receipt-only 限制

测试版本选择器仅在 `cfg(test)` 下存在，以同线程 RAII 作用域运行真实 backup/restore/open；不读取环境变量，不可通过 IPC 配置。离开作用域后普通打开和备份继续拒绝 11。

## 激活与回退边界

默认激活保留到内部尾章写入与 owner 安全闭包完成后，另行评估。兼容消费者、历史 receipt、失败迁移、完整备份恢复及独立审查是必要前提。当前候选不会自动升级用户数据库。

旧二进制不能直接打开 11。关闭未来 rewrite 入口时仍须保留新 reader/export；这不是磁盘降级。需要回到 10 时应使用经验证的升级前备份，升级后新增历史不能无损倒灌。真实升级或恢复是独立操作，本片没有执行。

128 MiB 共享 staging、两槽、4 MiB frame 和既有逻辑原件预算不变，不增加累计历史容量上限。
