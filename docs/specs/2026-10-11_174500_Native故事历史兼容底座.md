# Native 故事历史兼容底座

状态：候选，默认数据库仍为 schema 10。schema 11 只在合成测试的显式作用域内迁移；尾章重写仅提供内部注入式 producer，未开放 IPC、ACL、默认 binder 或页面入口。Linux headless 证据不能代替 Windows/Tauri 实机验收。

## 存储与历史证明

迁移保留 schema 1–10 的原 SQL。候选 11 在同一事务中先审计旧故事图和 pending，再重建 session/chapter/checkpoint 循环外键组件，保留 `foreign_keys=ON`，将新图验证、迁移 journal 和版本一起提交。旧正文、未知 JSON 成员、摘要、operation 和 receipt 的字节不重写。事务回滚未确认时连接必须停止使用。

chapter 增加 `status`、`superseded_by_chapter_id` 和 `committed_revision`。仅活动章的 `(session_id, chapter_index)` 唯一；生成行记录提交 revision，branch-copy 为 NULL。活动章序列连续，`chapterCount` 为活动数；revision 独立递增，不能由活动数或物理行数代替。当前历史审计仅接纳尾章重写：旧、新章同 index，相邻生成 revision，旧章指向新章，新章 `sourceChapterId` 指向旧章。中章截尾需要单独扩展合同。

所有历史 checkpoint 保留。零边界每会话唯一；非零 checkpoint 按所属 chapter 唯一。当前角色状态由活动章与其 checkpoint 关联，历史回执使用原 chapter/CP 身份和边界验证，不能要求它们仍是活动 head。

v1 linear、v2 branch/copy 的 wire 字节格式不变；schema 5–8 保持旧线性审计，9–10 保持原 branch 审计。11 的生成行将 receipt revision 与 `committed_revision` 比较。内部 v3 `tail-rewrite` 包含 operation/session/chapter/index/revision/count、target、input/output CP 和 requestDigest，原回执可在后续重写、续写及恢复后按历史身份核验。

## 既有消费者

- 活动目录、续写窗口与 Markdown 导出只枚举 active；按 ID 仍能读取 superseded 原件
- 现有 linear/branch writer 在 11 下补写 committed revision；branch 源 revision 与 count 分别校验
- branch resolver 与新写先核完整历史图和原源 CAS，再仅复制活动前缀 1..k 与所属 checkpoint 0..k；superseded 版本、历史 checkpoint 和旧生成 receipt 留在源。复制章保持 action/generationId 与未知原 token；rewrite 的旧同 index 来源不在活动前缀，按共享 domain 映射为 null，不能伪改为上一章
- 仅 11 的 copy marker 严格关联目标 branch receipt、物理 ID/index、requestDigest 与来源时，才允许 committed_revision=NULL 的 rewrite/null 复制行；真实 v3 rewrite 仍须同 index supersession、历史 checkpoint 和提交 revision 证明。9–10 继续拒绝该新形状，复制标记不得查询为模型成功
- 整会话删除核实际历史行数，返回物理删除数量；原显式确认、未知结果及重启围栏不变
- pending 的 11 原件校验将 chapter index 与 revision 分开，计划和窗口使用 index；最终保存包必须覆盖同一 input chapter index，仍由既有 revision/head/count CAS 决定写入
- 备份检查版本、新增列、partial unique 和 chapter-owned CP 约束，拒绝旧版本标签伪装的新表形状；恢复先按备份原版本审计，再走迁移，保留 restored pending 的 receipt-only 限制

测试版本选择器仅在 `cfg(test)` 下存在，以同线程 RAII 作用域运行真实 backup/restore/open；不读取环境变量，不可通过 IPC 配置。离开作用域后普通打开和备份继续拒绝 11。

## 内部尾章写入闭包

[独立 v3 合同](../../packages/contracts/src/desktop-arena-story-tail-rewrite.ts)冻结 operation/session、instance/revision/count、当前尾章、章前 input CP 及三个源原件的长度和 SHA-256。manifest 与成功 receipt 的原始 UTF-8 均限 2048 字节，拒绝未知和重复键；requestDigest 使用独立前缀与固定字段顺序，不能替代为 Web 内容摘要。候选只有 session/chapter/checkpoint1 三段，继续使用原 staging、帧和聚合预算。

内部 resolver、begin 与 end 要求真实 schema 11；普通 schema 10 调用明确失败。end 在同一 `BEGIN IMMEDIATE` 中先核对原 exact receipt，再对新写校验原 instance、源图 CAS、三原件 hash、全库章/CP 新身份和完整候选关系。旧尾章仅修改 status/supersededBy 的原始值区间；旧 receipt、正文及所有历史 CP 保留。新章沿原 index，revision 加一，chapterCount 不变。session 在源 raw 上更新已知可变成员，未知成员保留原 token；未失效摘要保留原件，失效摘要按共享领域语义移除。

注入式 owner 实际调用共享角色效果与 `arena-story-tail-rewrite` 投影。内容窗口与 Web 一致，包含旧尾章；输入角色独立来自 CP(n−1)。完成正文先保留，再一次冻结保存包。已确认回滚仅允许显式重试原包；提交或回滚结果不明沿共享 operation 围栏，只查原 exact receipt。重启后的旧包只读核对，不刷新 source 或再次生成。成功回执先成为终态，目录或正文读回失败仅保留“已保存、待读取”状态；取消、换选及执行账号/目标世代不夺取较新选择。

这些内部方法不是尾章重写产品入口。重写后分支使用既有 v2 branch/copy 格式，目标新生成章仍为 action=branch、index/count/revision 初值 k+1；原 sourceSessionId/sourceChapterId 与 index 记录直接来源，目标后续续写、再分支、备份恢复及删除不依赖源仍存在。跨平台资源、真实 Windows/Tauri、真实数据库升级及默认激活分别验收。

## 激活与回退边界

默认激活须在内部尾章写入与 owner 安全闭包通过完整验证后，另行评估。兼容消费者、历史 receipt、失败迁移、完整备份恢复及独立审查是必要前提。当前候选不会自动升级用户数据库。

旧二进制不能直接打开 11。关闭未来 rewrite 入口时仍须保留新 reader/export；这不是磁盘降级。需要回到 10 时应使用经验证的升级前备份，升级后新增历史不能无损倒灌。真实升级或恢复是独立操作，本片没有执行。

128 MiB 共享 staging、两槽、4 MiB frame 和既有逻辑原件预算不变，不增加累计历史容量上限。
