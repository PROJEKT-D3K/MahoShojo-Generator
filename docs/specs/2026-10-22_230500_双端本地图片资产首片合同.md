# 双端本地图片资产首片合同

状态：active（已接受的 IMG-0a 窄合同；落地进度以唯一 Desktop 计划为准）
日期：2026-10-22
标识：SPEC-local-image-assets-v1
依据：维护者同意 D5.1-IMG 的现有渠道优先、本地资产与恢复目标，以及继续实施授权。
规范词沿用 RFC 2119 / RFC 8174。

## 范围与覆盖关系

首个真实消费者是 Web/Desktop `/local-library` 的独立图片库：上传、保存、重新打开、预览、单图导出、
软删、恢复与彻底删除。两端消费同一资产合同与生产 UI，存储和文件出口各由宿主适配。
它不要求先创建角色卡，不改角色 JSON/签名，不将工坊内嵌图片、茶会旧 IDB 或远程 URL 自动迁入。
生成任务恢复、渠道凭据、角色/战报/消息关联、图片 portable archive 属后继，不能用本片代替其验收。

本合同按真实需求扩展 [Desktop 实施规格](./2026-09-30_160000_Desktop客户端实施规格.md) DESK-054，
使图片成为第二个 blob 消费者；其余 DESK-050/051/055/056/057/058/064/065 不变。
没有通用附件、任意 URL 下载、缩略图或多态 owner 引用。

## IMG-ASSET-001 原图与边界

- 只接受静态 PNG、JPEG、WebP；拒绝 SVG、GIF、APNG 与动画 WebP。格式由字节判定，不信任扩展名或 MIME。
- 输入最多 10 × 1024 × 1024 字节，宽高均为 1..8192，像素积最多 16 × 1024 × 1024。
  这是现有 Desktop 工坊预算的精确值；不截断、不静默缩放或重新编码。
- Web 在写入前检查头部并实际浏览器解码；Native 在写入前独立检查格式、动画与尺寸并实际解码。
  头部合法但无法解码不能保存。Native 使用有限格式解码器、尺寸/像素限制和单飞解码，
  allocation 限制是辅助防御，不能称为严格 RSS 保证。
- 存储、下载与摘要使用原始字节，预览 URL 只属于当前进程。失败保留已保存原件，不用空图冒充成功。

## IMG-ASSET-002 身份与仓储

图片不可变内容的 SHA-256 是 `sha256:<64位小写hex>`；稳定资产 ID 为 `image-<同一hex>`。
同字节重复保存返回已有记录，不制造新资产、不覆盖原名称或创建时间；软删记录不会因再次上传而自动恢复。
同字节的正确上传可修复损坏 blob，并显式返回 `repaired`。未知保存结果可按原内容身份查询或幂等重试，
不触发图片生成。

V1 元数据为 `schemaVersion:1/id/digest/title/mimeType/byteLength/width/height/createdAt/deletedAt/source:'uploaded'`。
未来生成来源与参数需显式演进合同；本片不因相同字节去重而覆写来源。
`title` 是去首尾空白后非空、最多 240 UTF-8 字节且不含控制字符的展示名称，不作路径。
时间由宿主产生；`deletedAt` 为 null 或删除时刻。仓储分页按 ID 升序、独占 cursor，
每页 1..100 条，分别读取 active/trash；失败不能转成空列表。

Native 以 `local_image_asset` 保存元数据、`image_asset_blob_ref` 保存资产到 blob 的真实外键，
不得复用 Web Package 引用表或引入 `owner_kind + owner_id`。
写入持完整写许可与共享连接临界区，顺序为 blob 原子落盘与校验，再事务写资产及引用。
数据库失败允许留下可诊断的孤儿 blob；不允许记录先于字节落地。
软删保留引用；只有软删资产可 purge，purge 去引用后交现有可达性 GC 回收物理字节。
审计和 GC 的全部查询/最终删除复核必须同时覆盖 Web Package 与图片引用；备份拒绝无引用资产或坏引用。

Web 使用现有 `mahoshojo-local-library` IDB 的版本升级增加图片元数据与字节 store；两者写入/删除同事务。
旧连接收到 versionchange 后关闭，配额失败保持旧记录。它与茶会缓存、公开卡缓存和 localStorage 分离。

## IMG-ASSET-003 IPC 与导出

仅 `main-ui` 授权业务级 save/list/read/delete/restore/purge/export 图片命令；第二 WebView 无此权限。
保存仅接受展示名称与有界 Base64 信封（encoding、data、byteLength），拒绝未知字段、长度不符及超限。
Native 自算摘要、格式、尺寸和 ID，不接受 renderer 指定 SQL、磁盘路径、远程 URL 或 blob 任意读入口。
读取按资产 ID 解析真实引用，返回校验过的原始 IPC 字节；renderer 复核摘要/长度/格式后再预览。

Desktop 单图导出按 ID 从本地资产读取，在应用管理的 exports 图片目录原子写入，Native 分配文件名与
正确扩展名，成功仅在原子发布完成后返回路径/字节数。Web 使用浏览器原图下载，明确仅表示发起下载。
导出不包含凭据或生成配置，不保证浏览器下载目录中的文件落盘完成。

同一 UI 操作同步置 busy；迟到读/预览不覆盖新选择，object URL 在替换/卸载时释放。
Desktop 图片读写与本地库维护、恢复挂起和离开/关闭守卫接线；Native 写许可仍为最终边界。
失效响应不得把持久保存未知写成明确失败；可以重新列举/按原内容重试，不能自动删除可能已保存的记录。

## IMG-ASSET-004 迁移、备份与回滚

生产 SQLite 从 11 升到 12，12 只新增图片资产及引用；旧 schema 1..11 按既有流程迁移，升级前备份守卫保留。
当前仅 cfg(test) 合成使用的 Arena history 候选 12 移至测试专用 13，保持全部候选隔离/故障测试，
不得随图片激活 history 生产能力；此前测试专用 12 不作为已发布用户数据库接受。
正式 12 库必须具有精确图片表/索引/外键，不能误认旧候选；release 仍拒绝未来 13。

Native backup 继续当前 manifest 版本，包含图片元数据、全部 blob（含回收站图片）并验证摘要、长度与引用。
新客户端可恢复支持的旧无图片备份；旧客户端拒绝新 schema，不提供降级写入或删除图片表的“回滚”。
撤回 UI 可保留资产；需要运行旧版本时仅从升级前备份恢复到独立/原有受控恢复流程。

当前 portable archive 的实际格式为 V2，只定义数据卡与 Web Package；本片不悄然加入图片字段/条目。
两端该区段改称“卡片与 Web 包归档”，明确排除独立图片。单图导出仅包含原图，不携带名称时间或回收站。
Desktop 整库备份覆盖图片，Web 暂无整库快照；图片跨端携带先用单图导出/上传，带元数据归档留后继。

## 验证要求

至少验证有效三格式、伪装/动画/截断/解码失败、边界预算、重复保存、重开读取、软删恢复/purge、
损坏拒读与正确字节修复、配额/写入失败、双消费者 GC、含图备份恢复与旧 schema 升级、未来版本拒绝、
第二 WebView ACL、TS/Rust 合同，以及真实共享面板到宿主的上传/读取/导出旅程。
自动化与真实 Windows 文件/关闭/重启验收分别报告；未执行的项目保持未验。

解码器依据（2026-10-22 核验）：[image-rs 格式特性](https://docs.rs/image/0.25.10/image/codecs/)、
[Limits 的严格尺寸与辅助 allocation 边界](https://docs.rs/image/0.25.10/image/struct.Limits.html)。
仅启用 png/jpeg/webp，不引入默认格式或原生编解码外部库；依赖许可与锁文件随实现核验。
