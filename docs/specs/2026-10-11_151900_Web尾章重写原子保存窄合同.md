# Web 尾章重写原子保存窄合同

状态：accepted。承接[连续故事分支窄合同](./2026-10-10_233200_连续故事分支窄合同.md)的完整源快照与原完成章恢复原则；仅覆盖 Web 尾章重写，不改变 Hosted 请求、IDB schema 或 Desktop/Native 能力。

## 生成与纯投影

- 点击时固定 session 和目标章身份。单一三 store readonly 事务读取 session、全部章（含 superseded）和全部 checkpoint；完整 store 扫描也包括没有正确索引的所属异常记录。目标必须仍为连续活动链的 head；已经成为中章则拒绝本次操作，不退回旧截尾路径。
- 原请求保持 `action=rewrite`、`sourceChapterId=旧尾章`、`chapterIndex=n`，最近最多十二章的窗口包含原尾章。重写不受下一章计划上限阻挡。
- 章前角色依次取 boundary n−1、首章 seed、仅最新章的 lastChapterInputCombatants。共享 domain 纯投影由真实 Web hook 消费；ID、时间与存储由宿主提供。
- 摘要覆盖达到 n 时清除；无 summaryMeta 的历史摘要保留原兼容语义。新记录保持 session 标题、章数、seed、计划、branchOf 和未知业务扩展，只更新 source、输入/输出角色、head、安全摘要及更新时间。

## 单事务提交

Web 没有单调 revision，章数不能代替版本。提交包固定为 `version=1, action=tail-rewrite, operationId, expected, session, chapter, checkpoint`；expected 包含原 session、目标章/索引与完整源图的 canonical SHA-256。章/检查点先按索引和 ID 排序，摘要涵盖原正文、superseded、角色、summary 与未知字段。

同一三 store readwrite 事务依序：

1. 精确原操作回执优先；已有成功不受后来 head 或源图变化影响
2. 核对完整源 CAS、目标仍为活动尾章及完整写集合；无写前 await
3. 原尾章浅拷贝，只改 status 和 supersededByChapterId；旧正文、扩展及旧回执保留
4. 新章 action=rewrite、index=n、sourceChapterId=旧尾章；不删除任何章
5. 替换 boundary n 的 checkpoint，更早 checkpoint 原样保留；最后更新 session

只在 oncomplete 认定成功，明确预检未写或事务 abort 才提供未写证据。quota、碰撞、请求成功后 abort 都必须恢复原图。保存包在保全文后深冻结；原包摘要缓存于同一不可变对象，重试不得刷新源快照或混入后来草稿。

## 独立有界回执与恢复

新章 commitReceipt 使用独立封闭形状，固定字段为：

`version=3, kind=tail-rewrite, operationId, sessionId, chapterId, chapterIndex, chapterCount, targetChapterId, checkpointId, contentDigest`

五个 ID 均为 1–128 个 ASCII `[A-Za-z0-9_-]`；chapterId=operationId，targetChapterId 不等于新章 ID。chapterIndex=chapterCount，为正 safe integer。contentDigest 为 `sha256:` 加 64 个小写 hex。拒未知字段；UTF-8 JSON 上限 2048 字节。独立版本避免旧线性 v1 reader 或 branch v2 reader误认，不扩旧 reader。

沿用同一个 pending 完成章状态机的导出、丢弃、保存与待读入口。unknown 仅查询原 session/operation/contentDigest；absence、mismatch 或读失败都不授权写入。只有已确认未写，才允许显式重试同一冻结包，不重发模型或另存新会话。新章后来 superseded 仍保有原 receipt 时可证明历史成功；原记录已被真实删除则不能复活。

成功后的列表/章节读取失败显示“已保存待读”，不能变回未保存。旧请求的晚成功不抢新选中，同会话切走再回来也按 selection epoch 隔离。

## 明确保留的边界

旧中章 rewrite 与截尾删除仍是多事务，可在跨 tab 并发时影响此事务之后的图。本片只保证尾章提交本身全有或全无与提交时 CAS，不代表所有编辑写者互斥或全部重写安全。Desktop/Native rewrite 继续关闭；其历史记录、单调 revision、receipt 和迁移合同须另行设计。删除确认语义不变。
