## 当前全 store 游标成本与优化边界

当前 `readSourceInTransaction` 按两个 object store 的全表 cursor 遍历，再以 sessionId 保留匹配记录；不是索引限定的源范围读取。readonly 冻结快照各遍历章/CP全表一次。无历史 exact receipt 的新保存事务先扫描目标孤儿，再扫描源，因此各遍历两次；已命中 exact receipt 则在这两轮之前返回。新增成本回归记录无关会话章/CP确被 readonly 访问各一次、write访问各两次，且不会写入无关记录。

这一成本随整个本地故事库而非仅当前源增长：无关行也有游标I/O与值读取/反序列化，写事务占用可能因此变长。仅源记录汇入完整图数组，不能据此声称浏览器内存、磁盘或锁时间已取得资源上界；本片只有合成正确性测试，没有大库真实性能承诺。

IDB4 当前只有 `sessionId+index/boundaryIndex` 与 `sessionId+createdAt` 复合索引。两者都可能漏掉相应字段无效/缺失的所属孤儿；使用二者并集仍不能证明未索引行不存在。现无迁移完成标记或写入来源证明可在事务内安全把全部现存记录视为已验证，因此仅切既有索引将弱化本片完整源/无孤儿保证，不在本修片中静默改为该语义。

后继可评估按 sessionId 的专用索引及相应 schema 迁移/历史数据验证，或在保持同一事务全部完整性条件下合并目标/源扫描减少一次遍历。需另测大库、无关故事量、长行、内存与事务耗时后决定；本片不为此加入历史总量限制、缓存可信标记或通用存储框架。
