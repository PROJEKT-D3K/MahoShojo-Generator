## 范围与冻结时点

- 新增独立 `arena-story-branch-storage.ts`：显式注入的 v2 port、浏览器安全物理 ID、三件准备器、原 requestDigest 的精确 receipt 查询和保存。旧 v1 port、manifest、hash 与默认 binder 不变；Node `crypto`/`Buffer` 只留在测试/runner。
- `captureBranchCompletion` 仅供受控完成候选生产者：生成前复制并冻结 source 四 descriptor、head/count、anchor、operation、target 与 generation 关联，同时捕获现 owner 的 epoch/selection。它没有读任意锚点、模型生成、IPC 或页面能力。
- 完成后转移已独立持有的新 session/chapter/checkpoint1 图，先保完整正文，再一次性预检、冻结原件与 requestDigest。digest 包含这三件，不能在完成前计算；此后显式重试仍用同一个 prepared handle/manifest/字节，不刷新 describe 或重建内容。
- 复用 `DesktopArenaStorySession` 的 pending/savePending/selection/savedUnread。取消、fail、detach、scope 变化释放未完成 capture；一次性 callback、owner 存续期的已消费 operation/generation 防止原身份经 discard 重入。该内存集合不是永久账本或冷启动全文恢复。

## 保存和恢复

unknown 只能查原 target/operation/requestDigest。null、mismatch、IO、abort、expiry 或进程重开都不授予写权；只有明确 Native not-written/rollback 可由用户显式重试同一包。end 派发前取消可以证明未写；派发后取消不能据此宣称未写，晚 exact success 仍算成功。

精确 receipt 证据先清 writable pending，后做目录/正文读取。目录失败保留已保存待读。独审发现目标已续写时旧 prepared head revision 会阻止读回，现只更新读取所需的当前同 target head，以原 receipt.chapterId 打开完成章；不改 writer 的 source、身份或 digest。该修复同时覆盖原线性 owner 路径。晚成功与后续读取都不抢用户的新 selection。

默认无 branch 注入直接拒绝；Hosted 提前拒绝。实际 battle/arena 路由的故事控件没有分支按钮，Tauri build/handler/main ACL 无 branch 注册。
