## 交付行为

本片从现有 Web 图片生成中提取任务生命周期与反馈区段，给后续 Desktop 图片适配提供实际被 Web
消费的端口；尚未开放 Desktop 图片生成、持久化或新路由。

- `@mahoshojo/ai-core/image-generation` 负责一次创建、原任务查询、停止等待与结果状态。
  `submit/query` 由宿主提供，核不读取凭据、不 fetch、不导入 React 或宿主模块。轮询次数可由宿主
  传入，Web 保留原有预算，后续 Desktop 不必继承 Web 的固定时长。
- `apps/web/lib/tachie/manager.ts` 成为三渠道适配。LibLib / ModelScope 仍使用项目 Next 接口，
  NovelAI 仍由浏览器直连；服务端 wire、鉴权与内容检查不变。NovelAI 的本地参数校验在派发前完成，
  无效参数不会被误报为“可能已提交”。
- 现行工坊生成响应应读 `data.generateUuid`、查询应使用 POST。工坊已回用同一 adapter，
  退出错误的顶层 ID / GET 查询路径，且真正等待异步任务完成。
- `@mahoshojo/ui-web/image-generation` 提供生产反馈和结果视图：未知进度、停止等待、原任务查询、
  未知提交说明、seed=0、PNG 下载、图片加载失败。TachieGenerator 与工坊使用同一反馈组件；
  样板间覆盖实际生产组件，清理了被替换区域的 inline style/styled-jsx。

## 任务身份、结果归属与失败

查询断线、等待预算耗尽、提交响应不明均属于 `unresolved`；收到供应商明确失败才将该任务归为失败。
已知任务 ID 在停止/故障后保留。“继续查询原任务”使用原渠道、凭据与任务 ID，不调用创建接口。
请求配置与结果回调只在创建时冻结；更改下一次提示词或配置不会改写原请求或恢复任务的保存元数据。
所有渠道成功结果携带原提示词。恢复记录本片只在页面内存中，
刷新/重启恢复属于后续 IMG-0/2/3 的合同与持久化，不冒称本片已完成。

停止等待会中止客户端 HTTP/轮询，但不宣称已取消供应商异步任务或退款。提交前取消不发请求；
提交后停止而未收到任务 ID 时明确说明可能已计费。查询或取消后迟到的响应不会恢复为成功，也不会
自动创建第二个任务。已成功图片在下一次生成失败/停止时仍保留，图片加载失败与生成失败分开展示。

独立审查指出，提示词不能作为结果 owner：同一对象编辑提示词应保留旧图，相同提示词的不同对象也
不应共享原任务。宿主现传稳定的角色/报告/茶会目标身份，切换目标撤销原任务与局部图片选择；
上传图片的异步读取也有 owner/epoch 围栏。工坊在新卡导入提交时再次撤销图片任务，关闭“导入等待期间
开始生成、导入完成后旧图覆盖新卡”的窗口。上述问题均有行为回归，不仅依靠类型检查。

公共结果只投影 imageUrl/seed/auditStatus 等允许字段，供应商图片对象的额外字段不能覆盖任务 ID、
success 或 outcome。图片落地、有效图片字节校验、稳定资产 ID 和备份仍为后继；本片预览继续消费
Web 原有 URL/data URL，不将远程 URL 当成持久图片资产。

Web 全测的两项失败位于未修改的 `web-package-trust.test.tsx` 与
`arena-deferred-web-result.test.tsx`：断言精确查找带 emoji 的「下载生成目标／下载 HTML」，
而本片基线 HEAD 的 `ArenaWebReport.tsx` 已使用无 emoji 文本和独立 `Download` 图标。
定向重跑两项均复现；本片未修改该组件或相应断言。

根全测失败包含 `arena-story-export-boundary` 的 4 项 Windows 路径断言、
`desktop-room-acceptance` 的 2 项 symlink EPERM、`desktop-story-acceptance` 的 1 项 symlink EPERM，
以及 room preflight 超时、story mock 随机端口触发 fetch `bad port` 和 Web Arena 构建 hook 超时。
以 `--maxWorkers=1` 重跑七个相关文件得到 252 通过、3 失败：room preflight 与 story mock 已通过，
room 的 2 项 EPERM 仍在，Web Arena 变为 prepare-only 构建超过 60 秒。
等待生产构建与全测结束后，单独重跑 `web-arena-acceptance` 的 37 项全部通过，未放宽超时。
其余未改动的路径/宿主验收失败保持显式记录，不通过修改安全检查或清理他人进程掩盖。

测试使用合成供应商响应，没有调用真实付费模型，也没有验证 Windows 原生文件/关闭/重启旅程或
真实 WebView2 视觉表现。本片未做浏览器截图验收；视觉证据为 token/contrast 门禁与生产组件 DOM 样板测试。

## 后继与回滚

IMG-1 仍需进一步抽取三渠道完整受控表单和纯 Prompt/参数规则；本片仅先完成可独立交付的任务核与
反馈区段。IMG-0 的 Native 路由、凭据、准入、持久化合同，IMG-2 的本地图片资产以及 IMG-3..6 的
Desktop 入口/角色/战报/茶会接线保持待实现。不将 shared export 或 Desktop 构建成功等同于产品能力开放。

没有数据库迁移、新环境变量、生产依赖或部署操作。可通过撤回本片代码回到原 Web 路径；本片没有写入
新的持久数据格式或删除旧数据。回退会重新带回旧工坊接口缺陷，应优先修复回归而非长期使用旧路径。
