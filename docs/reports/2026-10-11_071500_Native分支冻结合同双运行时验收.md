## 证据分层与不变量

### 闭合字节合同

manifest、source、descriptor、part 与 receipt 均按现有 Rust struct 声明顺序编码。未知字段、版本/类型错误、非法身份、descriptor 所属 session/instance/revision 不一致、revision 与 head count 不一致、anchor 越界、新三件错序和总量超过128MiB均拒绝；source descriptor 表示历史记录，不被累计成新增上传量。

有效身份、各 descriptor hash/长度、head、协调后的 count/revision/instance、锚点、新三件声明变更均改变 request digest。整数限 JS safe 范围，k+1 无溢出；copy ID 使用 u64 big-endian，固定向量覆盖32位截断风险。最大 success receipt 使用六个128B ID与最大计数，真实两端序列化均1123B，hash仍为 `93d6b217eb2635b61b98b502f0b2ee9948d35cb8bef61320e4a2f4c1b0b67861`，读取/编码预算仍2048B；copy marker不能被解释为success receipt。既有891B copy marker验收保留。

TS 提供的是已解析对象 schema 与编码器，不提供原始 JSON decoder，不声称能发现 `JSON.parse` 已抹掉的重复键或数字词法。Rust 独立读取 raw 文本，拒绝重复 `version`、转义等价重复键、嵌套重复字段、未知字段及浮点/指数版本词法；不是拿 JS 解析后的对象冒充重复键证据。原件 Unicode、孤立代理、重复 opaque 扩展则按既有 raw-token 能力保真，不对自由载荷强制闭合。

### 真实内部存储消费

静态 manifest 的零 instance 仅供 codec 金样。每个真实 store 场景在新 generation 开始时读取当次合法 descriptor，首次构造并冻结请求；新增三件字节及声明与静态 fixture 完全相同。此后 source CAS 冲突、删除、重开均持有同一冻结请求，绝不刷新 instance 为原 generation 重授权。

- 锚点1/2/3均完整保存，source全行快照不变；target session/chapter/checkpoint为独立物理映射，seed原字节相同，新三件原字节落盘。
- 复制历史 action/generationId 和独立 operation_id 保留；另经第二次真实内部 branch 复制已保存的历史 branch 章，copy provenance不可成为生成success receipt。
- 源及目标复制章、目标 checkpoint 无条件检查完整 opaque token片段，覆盖指数数字、转义 Unicode、孤立代理和嵌套重复键，避免条件断言空过。
- 在冻结后合法续写源后缀，原请求得到 `Stale`，零 target行且 source不被分支改动；这对应 source CAS冲突，不改错误协议。
- target后续继续沿旧v1 receipt续写；删除 source及重新打开库之后仍可查询原 exact receipt。内部 exact replay仅验证只读幂等，不授权未来owner对unknown结果重写。
- 重开后没有原receipt的旧instance冻结请求拒写，source及target状态不变。

### 关闭入口

负测试核对 build.rs、generate_handler、main-ui ACL、实际默认 Native binder 无branch命令/权限；共享两页宿主与owner不引入branch接线。真实控件在 battle/arena 两产品保存一章后均无branch动作。原 domain leaf esbuild边界仍只含domain源码，没有吸入Zod/hash或平台依赖。
