# Desktop 任意锚点分支源冻结

依据 accepted [DESK-105 窄合同](../specs/2026-10-10_233200_连续故事分支窄合同.md)，本片只闭合内部注入接缝的生成前源读取。不开放正式 IPC、ACL、默认 binder 或两页分支 UI，不接真实模型，不改变 Hosted 与原线性保存。

## 当前实现

- 内部 request 固定 `sessionId/revision/expectedLastChapterId/expectedChapterCount/anchorChapterId/anchorIndex`；response 仅既有 `StoryBranchSource` 和截至锚点最多十二条 chapter descriptor。调用者不预知或提供 checkpoint ID。
- Native 同一 connection 锁核完整 head/revision/count、锚点归属/index、原字节 hash 与 active 状态、真实 boundary k 的 checkpoint 关系。合法复制章可以作为锚点，但不会读取 copy marker 当生成成功 receipt。窗口外直接前驱只核有界索引/原件关系，不遍历或 hydrate 全前缀。
- TS 逐记录复用既有分帧读取和原字节 hash，核 descriptor instance/revision/session、CP/章身份及窗口顺序和关系。角色只来自 boundary k；空或非对象角色拒绝。最近上下文复用 domain 的两全文、其余摘要规则。完整 head/count 保留用于后续 CAS，章计划只看 k+1。
- 摘要复用 domain 锚点安全投影。没有覆盖元数据不携带旧摘要；覆盖未来的摘要在顶层和 session 中都清空；畸形元数据拒绝。未在本片实现全前缀 summary ID 映射或通过十二章窗口证明每个历史摘要 ID 的完整来源。
- 新 snapshot 独立并递归冻结。owner 在读取前冻结所有输入、占用原 generation/run；读取取消立即释放占用，epoch 或 selection 变化拒绝旧结果。准备与完成共用同一 run，不再次捕获 epoch。完成后的现有保文、一次准备、unknown 原回执查询逻辑保持，不刷新 source describe。

## 测试边界

真实小 SQLite pipe 通过目录选择锚点，调用真实 resolver，再使用冻结 snapshot 的角色/摘要/源元数据构造受控完成候选；没有模型请求。源读取覆盖首/中/末锚点、超过计划、混合 instance/revision、错误 checkpoint、读取 session/seed 后源续写、删除或 Native 重启、取消与 selection 变化。源读取失败零新增分支保存；源库 fixture 初始化不计为生成保存。旧成功、响应丢失、rollback 重试和冻结后重启四条保存旅程继续核验。

这是生产 TS → 内部测试 pipe → 实际 Rust store/SQLite；不是 Tauri IPC、Windows、真实模型或全资源门验收。单条原件读取及借用校验不宣称任意历史规模资源已可行；不新增历史总量 cap。
