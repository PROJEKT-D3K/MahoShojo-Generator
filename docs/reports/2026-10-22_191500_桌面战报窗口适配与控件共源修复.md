# 桌面战报窗口适配与控件共源修复

日期：2026-10-22
状态：实现与浏览器验证完成；真实 WebView2 本轮未验。

## 范围与依据

依据 [双端视觉基线与工程契约](../specs/2026-10-19_215200_双端视觉基线与工程契约规格.md) 的 VIS-CSS-001/002、VIS-SHOW-001、VIS-A11Y-001 与 VIS-GOV-001，以及 [双端视觉治理决策](../decisions/2026-10-19_215000_双端视觉治理体系决策.md)。复用 ui-web 的共享战报、显示切换与沉浸控件，宿主仅装配图标和原有动作。

延续 [Web 战报隔离运行验收](./2026-10-22_180900_Web战报共源与Windows隔离运行验收.md) 的独立作品窗口边界，本次不修改 Native、执行确认、网络策略、保存语义或 IPC。

## 根因与修复

- Desktop 完整版竞技场的输入、结果 `fieldset` 缺少 `min-width: 0`，默认最小内容宽度会被长源码撑开，连显示方式切换也一起超出窗口。补齐收缩约束。
- 流式战报沿用默认 `pre`，代码 renderer 又输出 `span`；长代码只能被卡片裁切。改为语义化 `pre > code`，保留原始内容、语言标记和行排版，在代码块内滚动，提供具名键盘焦点。普通长文本使用 `overflow-wrap: anywhere`。
- Web 操作沿用通用 `.save-button` 的顶部边距、边框和字号，与沉浸控件不同。统一共享按钮底座及 Lucide 图标，维持至少 44px 高度，按内容宽度排列并自动换行。折叠工具栏单独保留深色 hover，避免白色公共 hover 覆盖后丢失对比。
- 共享 Web 卡片使用紧凑品牌/模式页头，Desktop 独立窗口状态改为共享展示面；在结果样板分区同步展示生产组件、禁用态与长源码。

## 验证

- ui-web 战报、viewer、样板、卡片宽度与导出端口定向：5 文件、30 项通过；新增长 HTML 不执行、不截断、代码语义与键盘聚焦验证。
- Desktop Web owner、实际组件、多人结果与 battle-page 页面回归：4 文件、240 项通过。实际组件覆盖确认、聚焦、重载、沉浸、普通切换关闭及 unknown 围栏。
- Web 原战报组件：39 项通过。
- token、contrast、showroom 根契约：54 项通过。
- ui-web 类型检查、两端生产类型检查与两端构建通过；Web Hosted DR client bundle safety 通过。ui-web lint 与两端修改文件 lint 无 error，未新增未解释的 a11y warning；代码滚动区的 tab stop 有局部规则说明，未放宽全局规则。Desktop 构建保留已有大 chunk 提示。
- `pnpm review:visual -- --no-server --url http://127.0.0.1:1435 --routes /#/showroom --screenshots`：亮/暗 1280/375、forced-colors、200% 根字号六条件，fail=0。两项 warn 来自暗色样板主题选择器“浅色/深色”文字抽样对比度 3.44，本次未修改该控件。
- 本地 Vite + Chromium 合成夹具使用真实 DesktopWebReport、执行 owner、共享页框与卡片，Native 端口为模拟。375/640/1024/1180/1440 下普通与 Web 状态页面均不溢出，六个 Web 操作全部在视口内、正常字号下高度均为 44px。1180 下移除 fieldset 修复，结果区立刻从 1116px 扩展至约 11897px；恢复后源码只在 1068px 的代码区内滚动。键盘右方向键使代码区 scrollLeft 从 0 变成 40。暗色、forced-colors、200% 根字号补验也无横向溢出。
- 独立 UI 审查发现并闭合折叠按钮 hover 冲突；修复后浏览器实测白色图标、80% 黑色 hover 背景，无剩余阻断项。

本地证据位于 `.tmp/visual-review/report.json`、`.tmp/visual-review/report-fix/`（几何数据与普通/Web、窄屏、暗色、forced-colors、200% 字号截图）；不提交生成截图或临时夹具。

过程中的首次 Desktop 类型检查暴露状态文案可为 null，已修正共享 view 类型；新增测试最初硬编码了错误文案，已改为核对 owner 实际状态并通过。另一次直接运行 Web 默认 `tsc --noEmit` 将测试文件一并纳入，因测试类型错误失败；正式 `typecheck:build` 和 Web 构建随后通过，不将默认配置的全测试类型检查报告为通过。
