另核验完整四文件82例日志。独审不代替完整CI，后续组合冻结树的实际完整结果见下节。

- “另存为新会话”原新 pending 未携带 selectionEpoch；现在捕获该次显式点击的 fresh epoch。
  deferred commit 覆盖点击后改选会话、改选章节，以及点击前已导航但之后未导航的正例
- 请求 headers 内有多个 await；原实现在全部 headers 之后才冻结 actor epoch，可能将 A 的
  Authorization 绑定切换后的 B 世代。现在在准备 headers 前冻结认证原件/epoch，异步完成后
  仍相同才派发；变化时不产生 generation/role POST，保留当前输入并明确请求未发出。
  覆盖 A 头已取→activity 等待→B，以及注销→重新登录同 A；正常匿名首次 bootstrap 仍通过。
  认证 bootstrap 若确实改变原件也保守停止在派发前，不暗中补发。最终复核还发现提前 acquire
  的未派发 latch 无 settlement 会阻断下次请求，现将 acquire 移到校验通过后、紧邻 dispatch；
  同组测试使用真实 `createGenerationApiIntentLatch`，断言失败时 acquire=0/onSettled=0，并验证
  用户下一次明确重试只取得一次 lease、正常保存。原通用 dispatch 还有一次补头与 placement
  await：本宿主仅注入已准备头的 no-op 补头端口，以及模型 fetch 前的同原世代校验；没有额外
  CSRF 注入被省略，原路由/能力/credentials/回退/settle 均保持。真实 latch 覆盖内部等待期间
  换身份零模型出站、正常 settle、随后显式重试，并覆盖 fetch 同步抛错/异步拒绝及准备 auth
  失败；错误后 busy 均释放。请求头和无 story header payload 同时断言，测试独立 stub 低基数
  telemetry observer 避免把遥测 POST 误计为模型出站，生产 observer 未改
- 基线已有“重新读取”先等列表后无条件选会话的窗口，本次同类收口只加点击 epoch 与 await
