# Web 启动与公开库性能排查

状态：本地修复与验证；未部署生产。调查跨 2026-10-15 至 2026-10-16（Asia/Shanghai）。

## 范围与约束

用户报告近期默认分支部署后，公开库加载变慢、网页长时间显示加载本地设置。
调查时默认分支为 `feature/v0.2.0_Battle_Growth_MahoShojo` 的 `c23c47a9`，工作分支
`feat/desktop` 的 `4c807b80` 领先 52 个提交。以下涉及的启动依赖与公开摘要查询问题已核对存在于默认分支；
本次修复落在工作分支，不代表这 52 个提交已经上线。

遵循[数据卡列表加载可靠性与真分页修订](../specs/2026-09-23_013000_数据卡列表加载可靠性与真分页修订.md)：
保留摘要分页、完整正文按需读取、失败与空列表区分、用户权限以及请求取消语义。
不改变协议、数据库 schema、线上数据、生产配置或部署状态。

## 已确认的现象

- 在线服务器采样未见内存、磁盘或持续高负载压力；Hono 健康检查成功。
- 首次浏览首页，HTML TTFB 约 2.55 秒，DOMContentLoaded 约 7.27 秒，但所需 JavaScript
  直到约 38.5 秒才全部到达，随后才开始账号状态请求。该样本包含当时客户端网络因素，不能视为服务器 SLA。
- 随后打开 `/arena`，额外脚本加载仍需约 12 秒。`ArenaPersistedStateBoundary` 的
  “正在恢复本地设置…”同时是 SSR 占位；浏览器在依赖脚本到齐前无法执行恢复 effect，
  因而此提示不能证明 localStorage 本身慢。本次未取得报告用户的具体设备或本地存储样本。
- 浏览器实际公开库请求为 `view=summary&type=character&limit=12&sortBy=created_at`，
  响应约 8 KB，首次耗时 2.83 秒；额外两个发布时间分页样本为 2.38 / 2.43 秒。
  未发现当前选择器下载 500 张完整卡片的情况。旧接口的大响应不是此路径的直接原因。
- `EXPLAIN QUERY PLAN` 显示摘要查询虽然命中过滤索引，仍因 `COALESCE` 排序使用临时排序树。
  查询还在分页前计算 JSON 字段、标签与关联投影，统计路径复用了不必要的关联。

## 修复

公开摘要列表先用原有过滤和排序取当前页 ID，再仅对这一页计算 JSON/标签展示投影；
公开统计保留 `users` 内连接与过滤实际需要的 metrics 关联，去除无关关联。
保留原 `COALESCE` 的空时间兼容、同值 ID 次序、所有者存在性检查和全部筛选条件。
仍需排序的查询不被描述为完全消除了扫描。

前端把未打开的登录弹窗、公告正文等依赖改为按需加载。公告正文此前将 Markdown/数学渲染器
纳入全站初始依赖，登录弹窗则引入敏感词处理使用的拼音依赖。延迟加载不改变实际使用时的
内容检查或媒体政策；不把认证、生成恢复或本地设置恢复的生命周期整体移出首屏。

按需加载机制参考 [React lazy 官方文档](https://react.dev/reference/react/lazy)，
加载失败与重开行为需要单独验证，不能仅以编译成功判定交付。

## 测量与验证

用 Drizzle logger 捕获修改前后的实际 SQL 和参数，通过 D1 管理 API 各执行一次 SELECT；
只保留查询及聚合执行元信息，没有输出或保存卡片正文。最终结果如下：

| 查询 | 修改前 D1 执行时间 | 修改后 D1 执行时间 | 修改前/后 rows_read |
| --- | ---: | ---: | ---: |
| 公开角色首屏 12 条摘要 | 1,108.47 ms | 367.73 ms | 36,615 / 33,181 |
| 同条件总数统计 | 455.52 ms | 394.36 ms | 33,152 / 22,377 |

行查询单次采样降低约 67%；原实现和新实现均并行发出行查询与统计，不能把二者相加当作
接口耗时。统计仍需要读取全部匹配范围，且保留用户存在性条件，不能以去掉该条件的快速
COUNT 微基准冒充最终实现。上述为单次只读对照，受缓存和同时在线负载影响，不是稳定 SLA。

数据库回归：两文件 20 项通过，覆盖既有摘要 API、NULL 时间兼容、同值稳定分页、缺失作者排除、
公开组合筛选、原生过滤与统计；对应 ESLint 通过。

本地生产构建按各页面 HTML 引用的去重脚本文件统计（包含 `nomodule` polyfill；gzip 为本地
逐文件压缩之和，不等同于生产实际传输量）。对照基线是本轮首个中间构建，**已包含公告正文
懒加载**，并非修改前的完整基线，也不是线上部署版本：

| 页面 | 中间基线脚本 / gzip | 最终脚本 / gzip |
| --- | ---: | ---: |
| 首页 | 1,796,627 / 621,128 B | 1,140,836 / 335,838 B |
| `/arena` | 4,750,452 / 1,534,519 B | 4,730,010 / 1,529,722 B |
| `/battle` | 4,665,894 / 1,509,546 B | 4,673,887 / 1,511,934 B |

首页相对此基线减少约 36.5% 脚本字节、45.9% gzip 字节。两个竞技场页面收益很小，简洁版
略有增加，不能把弹窗拆分描述为已经解决竞技场启动性能。

实际完成的验证：

- Web 定向测试 11 文件、78 项；共享公告测试 21 项，均通过。
- `pnpm --filter @mahoshojo/web run build` 通过，包含生产 TypeScript 检查、Next 生产构建
  和 Hosted DR 客户端 bundle 检查；共享 UI `build`（类型检查）通过。
- 修改文件 ESLint 无错误；两个竞技场页面各有一项既有内部导航 warning。
  workspace 边界检查与 `git diff --check` 通过。
- 本地生产构建浏览器验收（API 使用测试响应）：首页无未捕获异常，登录表单正常；登录
  点击时才新增约 660 KB 脚本，公告详情点击时才新增约 434 KB 脚本。竞技场与简洁版能够
  完成本地设置恢复，公开库正常打开，Escape 关闭后重开保留排序选择。未触发生成或账号写操作。
- 加载在途关闭、真实 lazy 拒绝时保留父页面及焦点/Escape 行为，由新增回归测试覆盖。

未运行全仓 CI、Cloudflare/OpenNext 部署构建或生产发布。数据库计时区分实际 SELECT 执行与
EXPLAIN 的计划编译时间；浏览器耗时、D1 内部耗时及本地构建体积分别报告，不互相替代。

## 发布与剩余风险

本轮未生产部署，也未执行远端迁移或数据写入；生产改善需在部署修复后，以同一网络和设备复测。
用户地区网络/CDN传输、带大量历史记录的浏览器存储以及各时段服务负载仍可能影响体验。

竞技场剩余启动依赖已定位到 `BattleResult → useBattleEngine → sensitive/shield-word-filter
→ pinyin-pro`，以及战报、连续会话到 Markdown/KaTeX 渲染器的静态导入。仅延迟一个 Markdown
包装器无法切断其他战报渲染链；屏蔽词处理还是同步 API，不能直接替换成异步导入而维持既有
调用语义。进一步优化应拆分展示层与引擎生命周期，验证断线恢复、流式停止及过滤失败路径。
本轮保留这些行为，不把重型引擎整体延迟挂载，也不改变内容检查策略。

本次已确认性能瓶颈和局部改善，但尚未将用户报告归因到某一次具体生产发布；需在修复部署后，
用受影响用户的具体页面、设备与网络补做同条件对照。
