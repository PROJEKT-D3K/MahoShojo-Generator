# Native 分支长记录形状资源探针

状态：DESK-105 内部资源计量切片。仅新增 opt-in 测试、串行 runner 和验收记录；不改变生产 parser、store、限制、IPC、ACL、Hosted v1 或两页入口。完整资源门仍未关闭。

## 范围与输入预算

依据 [DESK-105 窄合同](../specs/2026-10-10_233200_连续故事分支窄合同.md)，承接[单次源核验](./2026-10-11_023900_Native分支源记录单次核验.md)和[unknown 围栏](./2026-10-11_041200_Native分支未知结果围栏验收.md)。本次不重复把已有 129MiB 累计历史、SQLite `max_page_count` 或 unknown 生命周期结果算成新的资源门通过。

每个形状分别置于章或检查点：长字符串；密集 `\ud800` / `\u0000` 转义；大量唯一短未知顶层成员；未知顶层重复键；单个超长未知 key。扩展预算按 UTF-8 序列化字节计算，不按解码字符计算。源先经正常真实保存建立小第1章，再用正常三记录 `session/chapter/checkpoint1` 包保存第2章；正文字段保持原 fixture 的11字节，未知扩展没有挤入或扩大正文上限。

所有大包在上传前精确相加三件记录并断言不超过原128MiB；append 仍拆为原4MiB frame，未扩大任何限制。源第1章的 seed/CP0 使用原真实合法 start 保存路径，不省略存储校验。分支从同 store 复制章1..2、CP0..2及seed，新三件为正常小分支包；无历史累计 cap 或额外输出 cap。

## 独立进程与测量口径

每个 case 串行运行五个干净进程，共用该 case 的唯一磁盘 fixture：

1. fixture：真实 begin/append/end 保存，比较输入记录长度/hash和存储 descriptor，再重算实际源文档hash并记录所有持久列fingerprint
2. rollback：重开库并提交真实 branch，在原 `before-commit` hook 返回 Busy；验证明确 rollback、零 target及无成功receipt
3. verify-rollback：新进程重开，核全部源三表持久列未变、零target及audit
4. branch：新进程重开，正常 branch/receipt/count；独立 HWM 不包含 fixture 构造或大型验证
5. verify：再重开，核成功receipt、源全部持久列/receipt/index等typed fingerprint、实际源/目标hash、目标(1 session/3 chapters/4 checkpoints)、全库audit、未知 raw token和原key token保真

源与复制目标的章/检查点逐记录对拍，仅容许合同规定的身份值变化；保留每个源字段的原 key token，缺失link只容许既定尾部null补齐。序列化文档精确逻辑字节分为 session、seed、chapters、checkpoints和 copied prefix（章1..2+CP0..2+seed）；它们不是含receipt/index/journal的底层实际写入IO量。

`VmHWM` 是 Linux 内核提供的进程生命周期高水位字段；下表取该独立阶段所有marker与外部samples的观测最大值。branch 的范围包括重开、describe、staging、end及小型回执/计数；fixture HWM包括构造、真实保存及基线fingerprint。另保存各marker RSS/HWM及外部约25ms采样RSS。采样RSS不代表捕获所有瞬时峰值；`endElapsedUs` 包围整个 end 调用，不是精确写锁持有时间，不得改称锁收益。

runner记录库、WAL、shm、journal/临时文件的各次逻辑文件长度和文件系统free bytes。目录遍历/逐文件stat不原子，文件尺寸和不能称同时分配磁盘峰值。低于256MiB free会终止当前子进程并保留fixture；这只是保护共享环境，不是磁盘不足成功测试。

## 只读后继建议（未实施）

现有 `arena_story_pending.rs` 的 `members` 保留全部顶层 `Vec<&str>`；`raw_member` 对每个key先构造完整 `Vec<u16>`。分支 `authority` 实际仅需章17/CP6个白名单字段，且复制与内部target audit共用它。16MiB重复键扩展有2,796,202个6字节成员；按本次64位 `&str` 的16字节，仅有效成员向量约42.67MiB，不含容量余量。超长未知key的完整UTF-16向量也随key长度增长。

最窄候选是复用现quote/escape/depth扫描，改为借用原RawValue的逐成员iterator；拆开raw key/value slice与key解码，白名单比较复用现UTF-16语义按需遍历。保留现 `string_units` 接口及需要完整向量的旧用途，第一片只让branch authority走流式匹配。`CheckedCopySource`、逐记录回调生命周期、原value span替换、输出hash、source CAS、事务/receipt、target audit和全部限制保持。第一片不顺带跳过未知value的现RawValue校验，也不建设通用parser/patch框架。

三种重复规则必须分开：branch authority对白名单decoded-key重复拒绝而保留opaque重复；closed `raw_object` 对所有decoded-key重复拒绝；Hosted role实际使用的 `raw_projection_fields` 对白名单last-wins。共享scanner优化不能把三者合成一个去重政策。未知孤立代理必须按UTF-16单元处理，不能转为有损String或serde Value树。

后继先用既有hook采样 `before-copy-*→copy-*`（包含查询/hash/语法/authority/物化/写SQL）、`checkpoint→before-commit`（target audit包围区间）、commit前后。当前没有这些分段实测，不能把整个end叫parser耗时，也不能把外部verify当内部audit。精确writer锁等待/持有还需独立测量。

保留整串raw-token golden、全部权威alias拒重、未知/嵌套重复、孤立代理、长key、原键token及缺失link补null回归；特别注意本资源测试的token遍历复用了scanner，后继必须保留独立oracle，不能生产和验证一起改错而自证。冻结baseline/candidate同profile、同fixture独立进程串行对照，再验证共享Closed/Hosted消费者、完整Native/clippy及协调后的CI。以上仅源码评估，没有在本片实施，也不承诺未经实测的收益。
