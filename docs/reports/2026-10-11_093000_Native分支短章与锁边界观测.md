# Native 分支短章与锁边界观测

[DESK-105 窄合同](../specs/2026-10-10_233200_连续故事分支窄合同.md) 的有限资源证据：大量短章下逐次合法保存的耗时、分层锁生命周期，以及当前 branch writer 的真实容量失败。不关闭全部资源门。

## 范围

仅新增 opt-in 短章测试/runner、`cfg(test)` 固定槽观察器，并强化既有 page-budget 测试。正式 IPC、预算、schema、生产错误分类与 unknown 围栏均不变；原 129MiB 历史、长单条/转义与有界 WAL 证据保持原范围。

- `arena_story_branch_probe.rs`：显式启用的线程本地 64 槽；未启用不累积，overflow/缺失/乱序/借用失败拒绝证据，Drop 不打印、不做文件或目录采样、不阻塞握手
- `arena_story_branch_store.rs`：guard 前声明 after-release 哨兵、guard 后声明 before-release 哨兵，用逆序析构夹住原 guard 的自然释放；不拥有/借用原 guard，不移动原 stages、connection、permit 的作用域
- SQLite BEGIN/COMMIT/ROLLBACK 各调用边界单列；复制章 INSERT 映射为原 `StoryError` 之前保存真实 primary/extended code 与 autocommit 状态，不新增 SQL
- `native-branch-short-history-probe.py`：串行独立 fixture/rollback/verify-rollback/branch/verify 五进程。原件逐次真实 begin/append/end 保存；回滚只在复制至 N/2 章时返回 hook error，不是外部强抢占取消

## 语义澄清

`MaintenanceGate` 的 WritePermit 是活动写者计数许可，持有期间不占 gate mutex；维护期准入被拒绝，不是等待维护结束。正常无争用获取只反映 acquisition/admission 调用开销。生产自然释放顺序仍是 connection → permit，随后 stages 内围栏/清理，再释放 stages。

## 短章规模下的关键观测

100 / 1,000 / 10,000 章 fixture 档位（仅实验档位，不是产品上限）。10,000 章逐次合法保存循环约 145s，其中成功 end 约 38s，且随章数呈明显非线性放大。每 100 章完成批次从首批约 0.1s 增长至末批约 2.7s，属实际初始化耗时现象，未归因到具体 SQL，也不作线性外推或产品 SLO。

`end` 与 writer 分段不是精确 SQLite 写锁时间：观测器自身的 clock/slot 开销未从区间中扣除。RSS/WAL 为间隔采样，不是绝对峰值；文件长度是非原子逻辑快照，不代表已分配空间或设备写峰值。

**10k 成功 end 约 38s 的长临界区仍是未收口性能风险**，后继诊断另片进行。参见[章反向索引与短章写放大](./2026-10-11_101500_Native分支反向索引与短章写放大.md)。

## branch INSERT 的真实 page-budget 失败

独立小库，同一 store connection：page_size=4096，将 max_page_count 调到略高于当前 page_count，核对 SQLite 实际返回该值后触发：

1. 第一条复制章的真实 INSERT 返回 `ErrorCode::DiskFull`，primary/extended 均为 13，即 SQLite `SQLITE_FULL`
2. 捕获 INSERT 错误时 `is_autocommit=true`，SQLite 已自动回滚；随后生产原显式 ROLLBACK 返回 primary/extended 均为 1
3. 保持 `Err(CommitUnknown)` 与原请求轻围栏：source 指纹未变、target 三表零行、原 exact receipt 为 None、旧 token/fresh begin 不能重写
4. 重开后 source/零 target/原 receipt 及关系审计仍通过；absence 没有被改成写授权

这是 branch writer 的真实 SQLite page-budget 容量失败，不声称 OS ENOSPC、fsync 失败或真实外部取消，也没有为测试变绿放宽 unknown 语义。

## 已知陷阱

原始 JSON 的通用 `short_totals(session).sourcePrefixIncludingSeedBytes` 字段在任何传入 session 上都表示该 session 的 **seed + 全部 chapters/checkpoints**（不含 session document）；对 target 它包含新增章/CP，名称不能当作复制前缀。复制前缀字节应使用独立 SQL 的 `targetCopiedPrefixBytesIncludingSeed`，原件字节合计用 `sumDocumentBytes`。
