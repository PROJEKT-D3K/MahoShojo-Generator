## 2. 分轮验证与修复留痕

### 2.1 源码独审发现并修复

1. P1：擦除原 Flight 的 redaction 列表后，同一已解析 HTTP chunk 的第二个 SSE event 可能继续发送，空列表不再阻断 secret echo。修复为同一 Flight 上不可逆 revoked 位，先撤销再擦；统一 emit/redaction、raw JSON、Hono/Next auth、token capture 和订阅建立均拒绝旧 Arc。原 current-instance 与账号世代围栏保留

3. P2：COMMIT 已成但 ACK 未知时，上层仅查 active 缺失可能跳过原 uploads 的内存 buffers/attempts 清理。现在存储函数持有 exact token 集合和内存锁，在 autocommit 且全部 token 缺失后统一收口；上层不得仅凭 active 缺失宣告完成

三项修后定点源码复审通过，无剩余确认阻断。该结论是源码审查，不替代测试或真实平台。
