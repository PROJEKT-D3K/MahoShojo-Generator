# 共享 AI 预设与端点能力边界

## 维护入口

供应商/模型目录唯一来源是 `packages/ai-core/src/provider-catalog.ts`，生成参数能力唯一来源是 `packages/ai-core/src/generation-settings/model-capabilities.ts`。Web 与 Desktop 共用它们；Rust 的 `generated/provider-presets.json` 只能通过 `scripts/generate-desktop-provider-catalog.mjs` 生成，不能手改。

继续遵守 [AI Provider 共源选择器规格](../specs/2026-10-08_173400_DesktopAIProvider共源选择器、快速配置与多模型连接.md)及[预设独立身份与服务器 BYOK 修订](../decisions/2026-10-09_010600_DesktopAI预设独立身份与服务器BYOK修订.md)。目录收录、协议证据与具体账户可调用是不同层次，新增目录不等于真实凭据验收。

## 新通道为什么采用文本 JSON

- 端砚展示站点是 `discovery.intern-ai.org.cn`，实际 API 为 `https://discovery-api.intern-ai.org.cn/v1`。[官方概览](https://cdn-static.openxlab.org.cn/magic-maker/action-static/tokenplan-doc/api-reference/01-overview.md)、[Chat 文档](https://cdn-static.openxlab.org.cn/magic-maker/action-static/tokenplan-doc/api-reference/03-chat-completions.md)说明 Bearer、Chat Completions 与 SSE `[DONE]`；[型号表](https://cdn-static.openxlab.org.cn/magic-maker/action-static/tokenplan-doc/quick-start/04-model-limits-and-pricing.md)保留大小写和日期后缀。请求级 thinking/reasoning/effort 不可控，不能从模型家族推导
- STA1N 公开站点拒绝读取，端点及完整 served IDs 依据维护者提供的接入说明：`https://cdn.sta1n.cn/v1`，使用 `/chat/completions`。本站同时列出的 Responses/Messages 不代表本项目实现了这些 adapter。中文前缀与大小写原样保存；“公益”“抗截断”等仅是供应商标签，不构成免费期限或输出行为保证

这两个预设没有可用的原生结构化输出证据，声明 `structuredOutput: 'text-json'`：

1. Hosted 根据实际 provider ID、类型及端点匹配可信目录，在首次请求前使用现有 Prompt JSON + `generateText` + 本地 schema 校验，避免先发送未核验的 `response_format/json_schema`
2. Native 仅对可信 Preset 解释派生策略。显式 `responseFormat: json` 在读取 Secret 和网络调用前返回 `UnsupportedRequest`；不会将显式 JSON 意图静默降级为无 schema 的文本
3. Desktop 的产品生成旅程已经发送 `responseFormat: text` 并本地校验，因此不需要另建兼容流程。普通文本与流式路径保留

旧预设缺省行为与同名 custom Profile 不受新策略影响。不扩展工具调用、任意 URL 代理、凭据受众或 renderer 权威。

## 预设 baseUrl 与 Direct 端点分轨

预设 `baseUrl` 是供应商主协议面；`AiDirectWireEvidence.baseUrl`（可选）记录已核验 Direct wire 的实际端点，只在两者不同面时声明。`google-cloudflare` 即此形态（2026-10-19 核验）：`baseUrl` 是 Gemini 原生 `https://generativelanguage.googleapis.com/v1beta`（服务器 BYOK 经 `createGoogleGenerativeAI`），Direct 走同一供应商的 OpenAI-compatible 面 `…/v1beta/openai`（adapter `openai-compatible`，依据 [Google 官方 OpenAI-compat 文档](https://ai.google.dev/gemini-api/docs/openai)）。

端点解析链两端必须一致：TS `resolveAiPresetModelDirectBaseUrl` 与生成物 `directBaseUrl` → Rust `direct_base_url` 都按「模型级证据 → preset 级证据 → `baseUrl`」回落；生成脚本对全部端点字段做 https + 无凭据校验，native 解析侧重复同一校验。新增分轨预设时三处同步，不要只在 TS 或生成物单侧声明。

## 参数按 provider + model 判断

同名模型在不同通道可能有不同协议。OpenRouter [公开模型元数据](https://openrouter.ai/api/v1/models)中，新 GPT 与 Claude 5.5 型号没有 `temperature`，因此 Hosted 丢弃任务默认和旧存用户温度；生成器将明确不支持的信息派生为 `omitTemperature: true`，Native 仅在可信 Preset 的精确模型路径省略该字段。未知能力与自定义 Profile 保留原行为，不跨 Kouri/Poe 复制 OpenRouter 的结论。

[Gemini 3.8 Flash](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash)在 Google 通道不接受 temperature，输出上限为 65,536，思考仅 low/medium/high 且不能关闭；不能复用包含 minimal 的旧 Flash 档位。system 仅登记安全通用能力，中转不继承 Google 专属参数。上下文长度也不能当作最大输出长度。

## 型号更新与兼容

具体型号以目录为准，维护时使用平台实际 served ID：[OpenAI](https://developers.openai.com/api/docs/models)、[Poe Bot/API](https://creator.poe.com/docs/external-applications/openai-compatible-api)、[MiMo](https://mimo.mi.com/docs/en-US/quick-start/model)、[NVIDIA](https://build.nvidia.com/nvidia/nemotron-3-ultra-550b-a55b)。Kouri 新 GPT 供给由维护者确认，不能扩展成其他小中转的供给证据。[OpenCode Zen](https://opencode.ai/docs/en/zen/)与 [Go](https://opencode.ai/docs/go/)存在已知按模型分流，必须分别核验 Chat allowlist。

旧型号、alias、已保存 Profile/凭据与模型选择保留，系统默认轮询不变。MiMo V2.5 / V2.5 Pro 官方停服时间为北京时间 2026-10-21 10:00，旧 ID 保留提示，用户可显式改选 V2.6；不自动改写已有配置。
