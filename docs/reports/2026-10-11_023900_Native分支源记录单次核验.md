## 根因与最小修复

旧路径先在 `read_document` 对同一不可变源 String 核验长度、SHA-256 与完整 RawValue 对象语法，随后章/检查点 copy 再做相同检查。这是每记录重复全量扫描，未证明章数平方复杂度。

新增私有 `verified_source` 子模块，`CheckedCopySource` 字段仅该模块可见。父 branch 与兄弟 storage 都不能用字段字面量伪造证据；唯一 constructor 仍验证原有全部字节、摘要和对象语法。返回原文与 RawValue 的同源不可变借用，不克隆原文、不增加无界 cache、不使用 unsafe。

`read_document` 保持 SQL 的单条长度与实际 BLOB 字节长门，读取后仅通过受检回调交出借用；回调不能使局部 String 的借用逃逸。章与检查点 copy 接收该证据，不重复核验源字节。源 CAS 四个 descriptor、seed 写入仍各自明确走受检入口；不是全局跨记录缓存。

以下不变：每章/检查点的权威重复键、索引与关系核验；原 key token、未知重复扩展与孤立代理保真；输出摘要；完整目标审计；source CAS、exact receipt 优先、unknown 围栏、原子提交与 rollback。无磁盘格式、依赖或 domain 规则变化。
