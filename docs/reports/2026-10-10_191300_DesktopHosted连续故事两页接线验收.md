## 1. 实际改动与边界

同一 DesktopBattleForm 的 /battle 与 /arena 已接 Hosted 线性首章/续章；目录、按需章节读取、完整故事导出仍由原 DesktopArenaStorySession 持有。新 Hosted coordinator 只围绕 Native pending snapshot 编排，不复制 Web 大 hook、不新建 C0、不生成 renderer 凭据 fetch、不新增布局或 CSS。页面实际消费共享 BattleStoryPendingOutcome、canResolveBattleStoryRoles、projectHostedStoryPendingContent 和完成记录装配。

实际顺序是：冻结原 input/localAssembly → 本机 input seal → v4 raw-CAS pointer → 原 Native create claim/C0 → 保窗口原文 → 同次合法 SSE done、完整 Channel end 与 Native invoke 成功且原 actor/owner 世代仍有效 → 完成原件 seal → 原 generation role → shared project/freeze → pending seal → single-use save/原 exact receipt。晚拒绝、缺 end、done 后畸形 IPC 均不得产生完成权威、role 或保存。

两槽通过 Native 发现，另一 product 候选卡只导航原页。pointer 丢失但 claim 存在仅显式 lookup/replay；cold 无 claim 不猜 funding、不补发 create。restored 只能读取/回放/receipt/导出/明确放弃。accepted 不重 role；save unknown 只查原 receipt，missing 不授权第二次 prepare/save。

完成正文、推理、原 header/meta/telemetry/role 原件与提交分开保存；流式未完成或 invoke 未 settle 的最新正文/推理仅在当前窗口，分别提供 Markdown/TXT 导出。初始 input ACK 未知时只读 exact active 或 query 原已知 token；token 缺失/查询未知不 begin/append/seal。窗口 input 可按原冻结 bytes 导出，上传 token 不进入公开状态、预览、日志或导出。Native 原件/manifest 逐文件导出只认最终回执；导出与放弃分开，默认先导出/返回，可最后明确不导出放弃。放弃只处理本机候选与原恢复身份，不表示服务器停止、退费或删除已存章节；foreign-retained 保留原诊断/明确替换入口。

### 1.1 本地组装保真

localAssembly 是 manifest1 的闭合可选本地字段；SQLite 保持8、网络 DTO不变、metadata 仍64KiB。缺失为历史未知，恢复不组装；`{version:1, chapterPlan:null}` 才是明确无计划。计划的 totalChapters/source/locked 初次冻结且不可补改；输入总数、已存原 session 计划与冻结提交全字段匹配。1–20 仅是既有显式计划范围，无计划故事没有20章总存储限制。

重建来源逐字段如下：sessionId/operationId/checkpointId/CAS位置取原 manifest；首章 createdAt 取原 session 冻结进 manifest 的时间；章节、checkpoint、summary 与更新时刻沿 Native 已有约束使用原 manifest.createdAt，不改成重试/完成时钟。source 的 mode/language/storyLength/customStoryLength 仅取原 input.seed，generationMode 为本片唯一 stream，providerMode 为原 Hosted 通路，providerId/modelId 取 Native claim funding。首章 seed 为原 input.seed 去除上述四个 source 字段；workingCombatants/userGuidance 取原 input。续章的标题、原种子、摘要、分支扩展与创建时间从 exact revision/head 的既有本机 session 读取，不复制整份 session 进 pending，也不取当前页面编辑态。

## 2. 实际失败与修复

1. **普通 Hosted SSE/JSON 原有完成时序缺陷，并非故事专属。** Channel done/end 曾早于 Native invoke 结算便被当成成功；JSON late reject 也会被 ended 忽略。抽取共用 collector/settle，普通与故事实际共用；完整 JSON封套只能保文，不能替代 invoke 成功。第一版独审又用真实 C0 复现缺 stream-end 的 P1：done 后 reader 已释放，晚协议错误无人消费。修为同 invocation 的独立 bridge 完成证明，done 后畸形/错序/额外 SSE/重复 end 仍可被 owner 观察。对应 `cf43bcefbc` + `3ce10d9ef4` 已合为完成门禁语义原子 `d1eae3c829`；独立复审在精确 `3ce10d9` 上13文件245通过、2既有跳过，另覆盖两次 invoke 证明不可串用和合法后续恢复不被早失败误杀
2. **匿名 bootstrap 晚到的真实路由失败。** AI目标已稳定后 cached-account 返回null，原 effect 未更新 Hosted actor，按钮可用但新建被错误阻断。现 actor effect 显式跟随 bootstrapped；与普通 scope取消 effect分离，匿名 bootstrap 完成不会取消同scope正在准备的 Direct 单次/故事凭据。真实红例修后通过
3. **晚到候选读取覆盖新窗口/accepted。** loadBaseline 后缺 epoch/abort 检查；同epoch较新 discovery 后也可能被旧 describe回退。现读取绑定 controller、actor/owner epoch和已有 discovery版本，先完成核对再发布 live。隔离旧源码负对照分别真实得到3项、2项失败；正式19项回归通过。历史缺 localAssembly 两态另有真实负对照，旧逻辑会错误新增 prepare/save，现均只读
4. **真实 Native pipe 揭示时间不一致。** synthetic fixture原先未检查 chapter.createdAt==pending.createdAt，真实Native在role accepted后正确拒绝commit seal。现 Hosted assembler只取原manifest时间，Native约束未放宽；新增 synthetic Native同约束与显式不同完成时钟回归，完整pipe重跑通过
5. 初始input known-token且无active时的本地重试原先未核当前actor；现 canRetryLocal与UI均核原manifest actor，换账号零query/write，原输入仍可导出。角色accepted在内存但seal未知保原response，不允许重新POST
6. **独审真实复现保存前异步授权缺口（P1）。** helper 内 receipt/read/prepare 各 await 原先未贯通原 actor/epoch/controller：换账号或 detach 后仍可能 prepare/save。现副作用前与 ACK 后逐段重核同一授权；prepare 前失效确定本次零写，prepare 已发/已领取而 save 未发只能保原 attempt、查原 receipt/导出/明确放弃，不伪称已保存或重新领取；save 已派发的 ACK unknown 仍只查原 receipt。独立4条原红例与2条既有 save-dispatched 边界在精确 `2b6164d4` 上全部通过；正式专项14条回归通过
7. **独审真实 DOM/路由复现4项 P2。** 完成原件首次 seal 失败后重试成功，恢复当前窗口已有 hydrated 事实，显式角色按钮重新可达且零自动 role；cold 槽保存/放弃后普通 Hosted owner 按当前 product raw 只读刷新，不滞留旧 readonly 缓存、不覆盖新 pointer；顶部取消按真实活动 owner 分发，Hosted 文案明确请求服务器停止，Direct story 保原 cancel，本地处理阶段不显示误导的普通取消；recover 在首 await 前同步取得单飞所有权，晚读与 finally 只认原 controller/epoch。精确终版独立6条原反例/Close/Back及10条真实路由出口复验通过；foreign-retained 的明确 replacement 精确使用原 requestId，另一 product 原 Unicode/换行 bytes 不变


保留失败日志、隔离负对照与修后结果，未仅修改测试期待。pipe中匿名fixture误注账号、单次故障被合法本地重试吸收及receipt故障注入位置的修正属于测试装置修正，未放宽产品协议或成功证据。
