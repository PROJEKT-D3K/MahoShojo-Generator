# 分支 Native 命令维护

Native command/default binder 与两页 Direct 分支共用以下边界。依据 [DESK-105](../specs/2026-10-10_233200_连续故事分支窄合同.md)。

## API 边界

- command 名称与参数由 `apps/desktop/src/platform/arena-story-branch-native.ts` 和 `apps/desktop/src-tauri/src/lib.rs` 定义；`build.rs`、`capabilities/main-ui.json` 仅为 `main-ui` 精确注册四项分支权限
- begin/end 使用独立 v2 carrier；append/abort、两槽、15 分钟 expiry 与原线性保存共用。body 仍为不超过 4 MiB 的 raw bytes，metadata 仍使用原固定 ASCII headers
- binder 只转发原冻结 manifest 和精确 target/operation/requestDigest，不 describe source、不重建包。unknown 仅查原 receipt；只有明确 not-written 才能显式重试原包
- 旧 `STORY_IPC`、v1 receipt、Hosted 协议、Native schema 与历史逐记录复制规则不变

## 页面装配与维护

- `/battle` 与 `/arena` 在 `battle-page.tsx` 的同一个工厂注入分支保存和源读取 port；`generateBranch` 复用既有 owner、AI 准备、完成投影和保存恢复，不另建页面状态机
- Web 与 Desktop 实际使用 `ui-web/arena-story-session` 的 `BattleStoryBranchAction`；控件只展示宿主提供的禁用、忙碌、冷却和点击回调
- 尾章锚点取活动 head 的 `lastChapterId/chapterCount`，不能取当前分页末行；历史锚点取已读取所选章的真实 ID/index。计划检查使用 k+1，因此满计划的故事仍可从更早章分支
- 分支仅支持 Direct，AI 准备完成后再次检查执行位置，不自动换模型。Native 缺少 boundary 快照时拒绝；不能套用 Web 旧数据补齐逻辑
- pending/unknown 和原 Hosted 候选继续阻断新生成；unknown 只查原 receipt，明确未写才显式重试原冻结包。角色效果仅属于新故事工作副本；源故事零写
- 源读取拒绝由页面捕获。换选或账号/目标世代变化不能让旧结果抢选，保存成功后读失败仅提供重读；回滚入口时保留既有分支的读取、导出与删除能力

## 验证层次

`arena-story-branch-native.test.ts` 调用无参数工厂与真正的 Tauri JS invoke，仅替换 host transport。`arena_story_command_pipe_tests.rs` 使用 Tauri MockRuntime、正式 command 宏及生产 ACL；`arena-story-branch-command-probe.ts` 将默认 binder 接至该 Rust harness 和真实 SQLite。跨进程 carrier 为有界测试 pipe，不是 OS webview transport。

当前环境缺少完整 Tauri crate 和 GTK/WebKit 系统库，真实 Tauri 编译、MockRuntime 与 JS→Rust command probe 尚未执行；既有 headless store 验证不能替代这些检查。Windows/WebView、真实模型及 renderer RSS 同样不因该 harness 通过而自动验收。无需为了本片在云环境安装整套 GUI 依赖。

## Windows 本地 Agent 待验步骤

在已配置项目工具链的 Windows checkout 中执行，不需要真实 API Key。先确认工作树内容及剩余空间；以下测试只使用 runner 自建私有临时库，不选用户数据库。缺 SDK/依赖时报告具体缺项，不自行扩大安装范围。

```powershell
pnpm --filter @mahoshojo/desktop run generate:content
if ($LASTEXITCODE -ne 0) { throw "Content generation failed" }
$evidence = Join-Path $env:TEMP ("maho-branch-command-" + [guid]::NewGuid())
New-Item -ItemType Directory $evidence | Out-Null
cargo test --locked --manifest-path apps/desktop/src-tauri/Cargo.toml --lib --no-run --message-format=json 2> (Join-Path $evidence "build.stderr.log") | Set-Content (Join-Path $evidence "build.jsonl")
if ($LASTEXITCODE -ne 0) { throw "Tauri test build failed" }
$artifact = Get-Content (Join-Path $evidence "build.jsonl") | ForEach-Object { $_ | ConvertFrom-Json } | Where-Object { $_.reason -eq "compiler-artifact" -and $_.profile.test -and $_.executable -and $_.target.name -eq "mahoshojo_desktop_lib" } | Select-Object -Last 1
if (-not $artifact.executable) { throw "Missing test executable" }
& $artifact.executable --exact arena_story_command_pipe_tests::command_macros_and_app_acl_reject_invalid_or_untrusted_calls --nocapture 2>&1 | Tee-Object (Join-Path $evidence "command-acl.log")
if ($LASTEXITCODE -ne 0) { throw "Command/ACL check failed" }
pnpm --dir apps/api exec tsx ../desktop/tests/helpers/arena-story-branch-command-probe.ts $artifact.executable $evidence 2>&1 | Tee-Object (Join-Path $evidence "probe.log")
if ($LASTEXITCODE -ne 0) { throw "Default binder command probe failed" }
```

返回 checkout commit、编译日志与 evidence 下的 JSON。保留失败现场，区分编译失败、command/ACL 失败、probe 失败和未执行；不把这些步骤当作两页 UI 或 Windows WebView 人工验收。

## 只读分支链

- Web/Desktop 共用 `ui-web/arena-story-session` 的分支链按钮、模态与显示投影；`domain/arena-story-branch` 区分真实根、尚未读取的父记录、循环与损坏关系。目录缺项不能证明父会话已删除；Web 仍只使用当前最近会话目录，子分支也只表示已加载记录
- Desktop 仅在明确打开模态或点击“读取上一级父会话”时读取一条 session 原件，复用 `readStorySessionDocument` 的 descriptor、revision、逐帧校验与完整 hash。不自动递归、不扫全库，不为打开目录加载 session/seed/检查点；父不在当前目录时，由用户明确载入更多目录后再读
- 每次读取后只保当前模态的窄展示投影与目录 head，不缓存完整 session 或祖先原件。一次显式读取仍可能达到现有单记录预算，尚无 Native 小型关系 DTO，也不声称完成全部子分支发现或大规模父链性能验收
- 关闭模态、会话换选/版本变化、执行 scope 变化、离页或 owner 销毁会取消后续帧并撤销旧读取的发布权。相同会话重新打开也是新世代；来源读取失败不改变当前分支正文，不增加模型、保存或删除调用
- 回归入口为 `arena-story-branch-chain.test.ts`、共享模态测试、Web wrapper 测试，以及 Desktop `arena-story-branch-reader*.test.ts*`；保留循环、自指、目录外父、实际缺失、摘要损坏、迟到响应与分帧取消场景。真实 Tauri/Windows 和原资源量级门仍单独验收
