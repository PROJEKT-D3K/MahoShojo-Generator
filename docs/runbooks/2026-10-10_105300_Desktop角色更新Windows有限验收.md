## 结果区共源复验（Direct / Hosted）

以下补充普通单次战报的结果操作验收，不替代上面的 Hosted 协议检查，也不代表已完成真实 WebView2 验收。使用无敏感内容的两张不同名测试卡，在已获授权的测试环境中分别检查 `/battle`、`/arena`；云端写入仍需明确选择测试账号与目标卡。

1. 生成中用鼠标和键盘操作紧凑停止按钮，确认可访问名称明确，连续点击不另建请求；Direct 取消当前本机 owner，Hosted 仍走原任务停止/查询语义，不声称撤销服务器已完成的操作。晚到正文不得恢复保存资格。
2. 同视口对照 Web：生成诊断与原始输出、保存与导出各有清晰语义容器，角色更新归属各自角色卡；长正文、错误、空更新和窄窗口不溢出。未展开角色卡不加载大正文，首次展开后再折叠不丢表单状态；无需给页脚和普通说明另套卡片。
3. 展开每张更新卡，逐卡下载 JSON，核对只含该卡完整数据而非会话备份；逐卡“另存本地副本”后从本地库重开，核对两卡身份/内容不串位、源卡未覆盖。恢复旧草稿后仍可查看/下载，但不能因此重新获得新鲜候选的本地保存资格。
4. 点击“保存到云端”前不得上传；在现有弹窗明确提交测试副本。替换另用已有选择目标与确认流程，核对当前账号只操作有权限的目标；本地另存按钮不得暗中上传，换账号前的在途请求不得借新账号身份继续写入或把晚响应标记为新账号保存成功。
5. 在授权测试环境提供可控未知写入结果时，保留表单，折叠并重开内外两层，或操作其他卡：不得自动重放原请求，也不得由另一表单清掉原锁。导航、清除草稿、新建生成/故事入口不能丢弃未知结果；按现有核对和明确再次确认流程处理。原生写入未返回时卸载表单不能提前解除请求锁。没有可控故障条件就记“未执行”，不要为验收改 host 或制造生产故障。
6. 分别操作逐卡下载、逐卡另存、加入活动历史与“完整导出 JSON”：确认提示和产物语义分离，完整备份保留会话/报告上下文；文件下载开始不等于本地库或云库保存成功。磁盘/权限失败仍保留原结果与可用导出入口。

## 手动修复、排位归栏与结果容器差集

只补验以下变化，不重跑已验旧矩阵。前六项入口为 `/battle`（简版）与 `/arena`（进阶版）的普通单次结果区；两页各选 Direct 与 Hosted 代表路径，Hosted 至少包含正文先完成、角色更新后到达的非流式报告。最后一项另验独立生成页。沿用上述测试账号、环境与操作授权；需要延迟或未知结果的项目只用已有受控条件，无法制造时记“未执行”。

1. 在“角色更新”展开“自定义修复本次角色变化”。Hosted 更新晚到时，尚未输入的草稿应自动填入本局历战影响/当前状态；若已手动输入，晚到更新不得覆盖文本。折叠再展开保留输入，新战报或离页后不恢复旧修复草稿。
2. 使用面板示例的 `impacts` JSON，只改一名角色，保留其 `combatantIndex` 与准确名称；核对另一名角色不变。无效下标、名称不符或重复目标应明确报错，不能半更新。原生/来源降级确认与缺失本局 effect 的创建确认分别取消，均不得改角色；原值直接应用应提示未修改，不损失信任或来源。
3. 显式“应用修复”后，角色工作副本与单卡 JSON 下载应显示修改值；“另存此修复副本到本地库”创建独立 unsigned、non-canonical 卡，重开核对内容。源文件、preset、云端原卡与此前另存的生成候选均不被自动覆盖；未修改成员保持原有数据。未点击保存不产生本地库新卡，不把下载或来源展示当成原生成候选保存资格。
4. 实际修改后，同一战报的服务器权威更新重试不可再覆盖修复；新战报恢复其正常更新流程。取消与 no-op 不应误关旧重试。Desktop 当前只提供手动修复，未实现 AI 修复入口或调用，不应看到可执行的伪 AI 修复按钮，也不得用重新生成战报冒充修复。
5. 沿用上节的云端 unknown 场景，检查修复输入、应用与保存同受原锁约束，不能借修复丢弃未决写入或另发请求。受控等待期间换账号、离页或开始新结果后，旧应用/保存回调不得修改新上下文或显示为新账号成功；无旧回调可控条件时，不以普通同步点击代验。
6. Hosted 已取得结算时，核对参战角色栏内“本局”结算明细与服务器反馈一致；角色重排不串位，重复实体、来源移除或已删角色无法唯一关联时仍在结果区保留“未关联到当前角色栏”的明细。它是生成时历史，不改变当前评分、预测或写资格；手动修复后的非原生副本不能因历史归栏恢复 canonical 身份。未取得、读取失败、pending 不得显示为已计分；Direct 不虚构服务器结算。此项不要求新开严格排位对局。
7. 另到独立自由生成页 `/free` 与情景生成页 `/scenario` 检查结果容器，不是在战报页切换模式。Free 的未签名提示、保存操作和保存反馈应同属“保存数据卡”面板，已有角色卡不重复套卡；“原始输出正文”使用独立卡片，可折叠/展开。Scenario 的“原始输出正文”也有独立卡片容器。两页在窄窗口下长正文、长名称、提示和按钮不横向溢出，键盘可操作折叠；视觉折叠或滚动限高不截断实际数据，下载 JSON 仍完整且不等于本地/云端保存成功。

## 已选角色段位与随机占位符差集

仅用既有隔离回环与无敏感内容测试卡；缺少对应合成响应时记“未执行”，不部署服务端、不调用真实付费模型。

1. 同一角色当前严格/自由段位只显示一个徽章：严格可用时优先严格，否则显示自由；旧服务缺少 `tier` 时不猜测当前段位，有选卡快照才明确标注“选卡时快照”。无快照时不显示段位，仍可显示已有分数；“本局”结算历史不冒充当前段位或恢复来源资格。
2. 两页分别添加随机魔法少女与随机残兽，占位计入 32 人上限、没有伪正文/详情/评分。取消替换结果或恢复记录时不物化；首次确认生成整批抽取一次；整批物化成功后，后续请求准备失败的重试或再次生成沿用该正文，不再抽取。物化本身失败不得留下半批角色。已有结果后追加新占位，旧生成候选与修复副本仍可独立下载/另存；向当前含占位名单应用旧战报修复应明确拒绝且不改原结果。普通 Hosted 与 Direct 各用回环代表路径核对，不由本机生成角色恢复 Strict 身份。

## 停止与回传

发生错误身份/签名来源提升、原卡被覆盖、额外生成、凭据进入 renderer 或非固定 host 请求时立即停止该操作并仅回传脱敏证据；不要反复重试真实请求掩盖问题。生产能力缺失时保留现场状态，不通过改 URL/关闭校验“解阻”。

回传先列实际通过项、失败/阻塞项和未执行项，再列构建身份与证据。只有上述有限范围逐项有真实结果时才能更新该范围结论；不据此宣布全部 Desktop 或 D4 完成。
