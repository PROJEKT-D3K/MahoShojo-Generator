# 公开排行榜浏览维护

本页维护 D5.1d-3 的公开排行榜浏览切片。Web 与 Desktop `/ranking` 实际消费同一个 `ui-web/ranking` 主面；筛选草稿/应用、实时分页、搜索和赛季归档共源。排行榜浏览不授予 Strict 参与、匹配、多人房间或治理写入能力。

## 共享与宿主边界

- `contracts/public-ranking` 定义固定公开读取、请求校验、嵌套公开投影、响应预算和目标核对；金样只含合成数据
- `domain/public-ranking` 从 Web 原逻辑提取归档事实、女王候选、筛选排序与展示名次。`arena-tier` 与 `ranking-season-extrema` 保持纯函数；服务器女王查询/缓存及 Strict 生成规则留在服务器侧
- `ui-web/ranking` 使用宿主注入的 query/read、链接、可选实时排名缓存与详情动作；不导入 Next、数据库或 Native runtime
- Web 保留原角色详情和实时排名缓存。归档名次不得写入实时缓存；Desktop 榜单详情只按点击读取公开主记录或已收录的打包预设，不预取卡正文
- Desktop query/cache 只在页面内存中存活。离页、队列/已应用筛选或赛季作用域变化隔离迟到结果；筛选草稿本身不提前发请求

## 公开读取与兼容

Native `cloud_public_ranking_read` 是独立匿名窄命令，固定项目 origin、GET 和 `leaderboard`、`search`、`tags`、`seasons`、`archive` 与 `ratingHistory` 请求。不读取 SecretStore、账号身份或 Provider Key，不接受 URL、method、headers、body 或任意路径。只允许安全赛季标识构成归档文件名，查询值使用 URL 编码；请求及嵌套筛选必须是对象，额外字段和不安全整数拒绝。

Web 与 Native 均禁止重定向，并逐块执行每类响应字节预算。超限拒绝整次读取，不截断、不冒充空数据；HTTP 404、429、网络/协议失败与真正空列表分别呈现。非法 JSON/UTF-8 和服务端错误页不能原样泄漏到页面。成功回包逐层公开字段投影，不传递归档作者 ID、卡正文或未知字段。

原 Next endpoints 不变，不需要服务端或数据库迁移。实时排行榜的当前公开、审核通过、未删除及严格队列资格仍由服务器判定；Desktop 不另算实时资格。实时榜最多展示筛选排序后的 Top300，没有 total；搜索 rank=0 表示不提供精确名次，不能显示“第零名”。Web 可使用既有有效 Top300 缓存跳转，未命中仍走原详情；Desktop 只展示可用的公开排行摘要。

归档兼容 v2/v3，以及 `top_bottom` 和 `full` 快照。必须先从所选队列的全部归档候选推导女王，再筛选和排序；段位与名次按当前规则重算。技术值为空始终排后，未知原生性保持未知；缺失的 extrema 不补造。归档作者名、赛季结束时间和特殊规则允许历史缺省。有限快照始终解释覆盖范围；当前赛季没有归档文件时显示尚无快照，不能伪造结算。

## 最近严格排位摘要

遵守[最近严格排位对局记录设计](../specs/2026-04-25_最近严格排位对局记录设计.md)。Web 所有既有入口保留；Desktop 仅榜单详情显式传入 `data_card` / `preset` 目标，不从本地、缓存、本人云卡或 `cloudRef` 推导。两端共用 history controller 与 `BaseModal`，父详情合并原举报层和历史层的遮蔽状态。仅点击读取；关闭、换目标、重试及重新打开拒认迟到结果，不预取、不轮询、不建全局或持久缓存。

`ratingHistory` 沿既有 `cloud_public_ranking_read` 与权限项，固定匿名 GET `/api/arena/entity-rating-history`，只传实体身份和 `queue=strict`，不传赛季或条数。服务端固定返回最近十条 `strict + applied`；它没有赛季过滤，也不重新校验实体当前可见性或 Strict 资格。历史可读不代表当前正文可读或可以参赛，弹窗明确说明不按当前所选赛季筛选。

响应只保留既有公开摘要字段，逐层剥离未知扩展；实体身份、strict、必需字段及条数不匹配则整次失败。`appliedAt` 和发起者身份允许显式 null；缺失与零不同，分差和赛后分保留有符号安全整数，旧 ID 和日期字符串不另加格式限制。独立 256 KiB 是两端实际流读取的客户端保护，不是服务器历史规则；超限报错且不截断。Native 已发出的 GET 不能由 renderer 的 AbortSignal 真正取消，由短请求超时结束；组件世代仍阻止迟到结果进入新弹窗。

## 验证与维护

更改合同需同步受影响的金样、两个宿主、Native DTO 与命令注册/权限来源。核心回归入口：

- contracts/domain 的 `public-ranking`：严格形状、安全整数、路径与查询、归档两版本/两策略、女王、排序和缺失值
- Desktop `public-ranking.test.tsx`：实际页面与窄桥、匿名装载、草稿应用、Top300、无假详情、错误/空态及迟到隔离
- Web `public-ranking-browser.test.tsx`：真实 query/页面消费、保留详情、配置变化引起的模式切换、归档不污染缓存、响应预算
- 共享 `entity-rating-history.test.tsx` 及两端详情／榜单测试：按需读取、历史目标、空态／错误、重试、关闭／重开／切卡、二级焦点与遮蔽
- Native `cloud/public_ranking.rs`：固定 GET、匿名/无凭据、对象限定、公开字段、状态/重定向与分块预算

跨 runtime 验证给 Native tests 设置 `PUBLIC_RANKING_NATIVE_WIRE_DIR`，输出真实 loopback reader 的 Serialize 文件（含 `ratingHistory.json` 与 Unicode 预设目标 `ratingHistory-preset.json`）；Desktop tests 的 `PUBLIC_RANKING_NATIVE_WIRE_INPUT` 指向同一目录，经现有 TypeScript bridge 驱动实际页面。验收必须开启此链并核对 Native 源闭包，不能用两端独立手写 mock 替代。

Native headless 保留原模块和逐旧名覆盖；新增共享 UI 入口登记在根 server-safe/client-only 门禁中，不放宽 exact assertion。正式 Tauri 宏/ACL、Windows WebView 的导航与关闭、真实网络异常及视觉/键盘行为仍需平台验收，合成 loopback 不替代这些证据。
