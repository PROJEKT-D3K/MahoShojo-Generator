# 服务器战报历史读取维护

本页维护 D5.1d-3 的首个纵切：Web 与 Desktop `/me` 的服务器历史列表、筛选分页、刷新及详情纯文本预览。

## 共享与宿主归属

- `packages/contracts/src/battle-report-history.ts` 是公开投影、受控筛选与 Desktop 读取请求的单一 TypeScript 合同；小型合成金样位于同包 `fixtures/battle-report-history.json`
- `ui-web/battle-report-history` 提供两端实际消费的受控列表、详情和筛选编辑；详情复用 `BaseModal` 的焦点与 Escape 层级
- Next URL、React Query 和 Web 身份留在 Web 宿主；Desktop 使用账号 store 与窄 IPC，不引入持久缓存、后台预取、下载、本地副本或重生入口
- Web 原有重生动作通过可选回调保留；它仍走原 POST，与本片只读通道分离
- 单人、多人房主/成员及旧 PVP 只表示已有记录来源；不开放多人房间、排行榜或 Strict

## 账号与服务兼容

既有 Next 两条 GET 保留原权限判断。新的可选 `expectedUserId` 在数据库读取及详情敏感词治理前核对实际认证账号；不传参数的旧客户端仍沿用原权限。成功回包的 `viewerUserId` 取自实际认证结果，不能回显请求参数，也不能代替记录的 owner/参与者访问判定。

历史列表保留既有 opaque ID。Desktop 详情仅接受合同中的安全路径标识（覆盖当前 UUID、arena 与 reconciliation 编号）；其它历史编号仍可列出，打开时提示前往网页版，不调用 Native，也不伪装成记录不存在。Web 详情只解码单个 URL segment 一次，再按原数据库键与权限读取。

新宿主要求成功回包包含实际 viewer。服务器尚未升级时明确报告读取协议不兼容，不以空列表、旧协议回退或伪造 viewer 掩盖缺口。此变更不需要数据库或 Desktop 配置 schema 迁移；发布新客户端前需发布对应 Next handlers。

Web query key 包含账号及本次登录 identity 世代；同账号重新登录、退出、切号均隐藏旧记录、关闭旧详情并隔离迟到读取/重生结果。账号变化后的旧错误不能清除或重新验证新账号。

Desktop `cloud_battle_reports_read` 只允许 list/detail 联合请求，要求 `expectedUserId`。Native 从保护存储读取凭据与账号世代，固定项目 origin、GET 和两条历史路径，不接受任意 URL、method、headers、cookie 或 body，不跟随重定向。成功和失败均在回传前检查原凭据字节与世代；该读取通道不清除凭据。renderer 再以账号、凭据世代与请求序号隔离结果，仅当前 401 可触发统一会话验证。

## 内容与资源边界

- Native 列表与详情分别执行独立的有界响应读取，具体字节预算以合同常量及金样为准。预算针对本次响应，不是生成或历史保存上限；超限拒绝整次读取，不截断正文、不冒充空记录
- 非成功 HTTP 状态直接映射受控诊断，不读取或回显任意错误页；成功回包使用嵌套 DTO 白名单投影，额外字段不进入 renderer
- 详情优先呈现屏蔽、正文读取失败、过期、现存正文、无正文；HTTP 无权、不存在、网络错误与真正空列表保持区分
- `outputPreview` 沿用服务端语义：非空 D1 预览优先，可能仅为片段；R2 正文亦可能过期或读取失败。不能凭 `hasPreview` 或 `canRegenerate` 宣称完整报告恢复
- 详情 GET 保留已有敏感词检查与服务端标记更新。因此“只读”限定客户端能力，不代表服务器绝对无治理写入
- 多人成员的私有角色字段仍由服务端剥离；Native 再按 `accessScope` 剥离同组字段。正文始终作为纯文本呈现，不执行 Markdown/HTML 或加载正文中的外部资源

## 回归入口与平台验收

修改合同需同步 producer、双宿主、Native DTO、金样及命令权限来源。重点回归：

- `packages/contracts/tests/battle-report-history.test.ts`：严格 IPC、筛选/路径边界、viewer 兼容与预算
- `packages/ui-web/tests/battle-report-history.test.tsx`：分页收束、状态优先级、可选动作、纯文本及 Modal 键盘/焦点
- Web `battle-report-history-host`、list/detail/regenerate handler 测试：实际页面消费、URL、账号世代、参与者投影及已有重生行为
- Desktop `battle-report-history.test.tsx`：实际 `/me`、窄桥、换号/重登、迟到 401 和请求顺序
- `cloud/battle_reports.rs` 的 loopback 测试：固定 GET、受控认证、重定向拒绝、嵌套投影、分块字节预算与原凭据世代

跨 runtime 对拍可为 Native tests 设置 `BATTLE_REPORT_NATIVE_WIRE_OUTPUT`（预先创建的临时目录），生成真实 loopback reader 序列化的列表及 owner/member/blocked 详情。Desktop 测试设置 `BATTLE_REPORT_NATIVE_WIRE_INPUT` 指向该目录，经现有 bridge 校验并驱动实际 `/me`；正式验收必须启用这一检查并核对输出归属于本轮 Native 源，不能拿手写 mock 当作 Native wire 证据。

Native headless 验证必须纳入新增子模块、全部相关 fixtures 和既有 `external_link` 模块，并与基线逐项对比测试名称；不能只用总数证明覆盖。它不能替代正式 Tauri command/ACL 或 OS 凭据验证。

Windows/Tauri 单列：真实 `/me` 登录/换号与同账号重新登录、离页后迟到响应、键盘焦点/Escape、长纯文本滚动、联网/断网与受控错误、窄命令 ACL。没有真实平台证据前保持待验；本地合成测试不需要真实账号、模型或生产服务。
