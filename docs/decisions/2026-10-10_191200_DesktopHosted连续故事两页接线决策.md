- 决策标识：`ADR-desktop-hosted-story-pages-v1`
- 规范：[DESK-103](../specs/2026-09-30_160000_Desktop客户端实施规格.md#desk-103-desktop-hosted-连续故事两页接线2026-10-10)
- 唯一实施入口：[Desktop 客户端阶段实施计划](../plans/2026-09-30_160100_Desktop客户端阶段实施计划.md#2026-10-10-desktop-hosted-连续故事两页接线)

规范性词汇沿 RFC 2119 / RFC 8174。`accepted` 是范围与语义许可，不是实现完成、CI 通过、线上服务或 Windows/Tauri 可用的证明。

## 1. 精确后继与共源边界

本片承接 [DESK-100 Native 传输](./2026-10-10_180600_Hosted连续故事Native传输与创建围栏决策.md)、[DESK-101 本地出口](./2026-10-10_184000_Hosted连续故事候选本地出口决策.md)与 [DESK-102 Web 完成保文](./2026-10-10_184600_Web连续故事完成正文保留与角色未决决策.md)，仅解除前两片对 `/battle`、`/arena` Hosted 连续故事 owner/UI 的范围限制。两页 **MUST** 继续使用同一 `DesktopBattleForm`、既有 `DesktopArenaStorySession` 目录/阅读/Direct 旅程和共享控件；Hosted 增加窄协调器，不复制另一整套页面、CSS/布局或第二个恢复状态机。

目标只含线性 start/continue、原任务恢复/控制、角色结果处理、本机原子保存、原件导出及明确放弃。普通 C1/C2/C3、Direct、Web 无 header 的 DTO/SSE/hash/actor 与既有分支/重写能力保持原边界；不新增 Desktop 分支/重写/删除、服务器故事库、额外模型摘要、Strict/多人、D4 执行或发布。

两端 **MUST** 真实回用 `@mahoshojo/domain/arena-story-completed-output` 的 role 判别与许可纯规则，以及 `@mahoshojo/ui-web/arena-story-session` 的受控 `BattleStoryPendingOutcome`。共享层不拥有 fetch、认证、Native、SQLite/IDB、pointer、签名或保存权利；不搬 Web 大 hook，不把 Web 仅内存候选说成 Desktop 耐久恢复。

## 2. 输入冻结、创建与完成围栏

1. 用户明确 start/continue 时 **MUST** 冻结 original product、actor 与本机世代、system/preset funding、原 input JSON、writeOptions、全部 IDs/createdAt 和原 session revision/head/checkpoint/window。后续页面编辑、配置/账号变化不能改绑；续写旧基线不可读时保候选，不能追加到当前 head。
2. 新创建 **MUST** 先受严格 story capability/readiness 门禁，再发布 exact input-only pending、校验回执、写 v4 pointer，之后才进入原 Native `create-story-stream` 与 shared C0。pointer 写失败保 input，禁止后台 create。Native claim/单次 permit 是最终派发围栏；任何 claim 后未知、404、过期或首头前失败都只查原 request，不能第二次 model POST。新创建禁止 Next/DR/Direct fallback。
3. 收到的完整正文 **MUST** 先在当前窗口保留并可导出。受检 SSE `done ok/completed`、Channel `stream-end`、订阅 EOF、取消受理均 **MUST NOT** 单独视作 Native invoke 成功。owner **MUST** 等原 invoke 成功 settle，并再次确认原 actor/owner 世代有效，之后才允许设置 `modelCompleted`、发布完成原件、调用 role、冻结或保存。晚 reject、actor 切换或 owner 失效不能越过这些副作用围栏；已收全文仍保留为可导出的窗口原文，不因此声称 durable completion。
4. 上述围栏通过后，完成输出 **MUST** 沿高级 pending publisher 以新的 revision 一次封存 markdown/reasoning/meta/header 及选定的一份成功 telemetry，保全部旧 immutable parts。封存未证实成功时只允许 exact 本地 seal 恢复，文案明确“最新正文仅本窗口保有”，不重模型或 role。
5. 完成原件 durable 后才进入原 generation 的角色处理，再走共享 project/freeze、pending seal 和 single-use save/receipt。所有异步写入/回调 **MUST** 重核原身份与世代；IPC resolve 本身不是 schema/exact identity/hash 校验的替代。

### 2.1 本地组装信息的窄补充

为从原件精确重建本机 session，pending manifest **MAY** 增加可选 `localAssembly: { version: 1, chapterPlan: { totalChapters: 1..20, source: 'user' | 'scenario', locked: boolean } | null }`。缺少整个 localAssembly 字段表示旧候选的本地组装信息未知；显式 `chapterPlan: null` 才表示已知没有计划，两者 **MUST NOT** 静默等同。

该字段 **MUST** 在初始 revision 冻结，后续 revision 精确 immutable，不后补、不从当前编辑态猜测；存在计划时其 totalChapters 与原 input.chapterPlan.totalChapters 精确一致，无计划时原 input 不得带计划。frozen session.chapterPlan **MUST** 与该原本地计划（含 source/locked）精确匹配；缺少该字段的旧候选保只读/导出，不后补或推断组装意图；明确 null 的新候选仍可按原依据恢复保存。

该小对象计入原每行 metadata+claim 合计 64 KiB，不新增 part、network DTO 或秘密字段；manifest 主 version 仍为1、SQLite 仍为8，不改旧迁移原字节。新代码 **MUST** 可读取旧1–8备份；旧v8代码遇新增字段可 fail-closed，不承诺前向可读。

start manifest.createdAt **MUST** 取原 session.createdAt；冻结章节、checkpoint 与摘要更新时间沿既有 Native 绑定使用该原 manifest.createdAt，不使用较晚的完成/重试时钟。重建 source 的 mode/language/length/custom 只取原 input.seed，provider/model 只取 Native claim 冻结 funding；不得取当前页面配置或把客户端意图摘要当服务端证明。此补充只恢复本地组装所需事实，不赋予 cold 无 claim 或 restored 候选新的执行权限。

## 3. 角色未决与冻结提交

- 未请求角色写入使用 `not-requested`。请求角色时只沿原 generation、原 Native actor 与固定 Next `reconcile-story`，由 Native 从原 input 的 workingCombatants 取原件并 fresh lookup 证明 completed；不套 Direct 未签名 effect producer，不写独立活动历史或源卡。
- 受检成功角色结果及其 Native invoke 成功 settle、原 actor 世代仍有效后，**MUST** 先将 `roleState=accepted + roleResponse` durable seal，再投影/freeze。已 accepted 的后续点击、恢复和读回 **MUST** 零 role POST；accepted 仅是角色响应已采纳，不表示章节已保存。
- 明确、受检的 HTTP non-success **MUST** 沿既有兼容语义取旧角色加 warning，记录 `old-roles/http-failure`。网络、畸形/超限响应、lookup 不确定、Native 晚 reject 保 `unresolved`，不能自动降级；保全文，提供单飞的“重试角色同步”和“保留旧角色保存本章”。重试只用原 generation，永不回到模型创建。Desktop 缺 generationId **MUST NOT** 冒充 DESK-102 的 `legacy-no-generation` Web 兼容成功。
- 任何新的 old-roles 决定与含 `storyRoleSync.reason` 的 frozen commit **MUST** 同一次 seal；容量、校验或 ACK 未证实成功时仍 unresolved，并提示决定尚未保存。不新增 manifest reason 字段或版本；恢复后不能自动 role POST。若恢复的是已成功封存的 accepted/old-roles 原件，只读该决定。
- 最终记录 **MUST** 复用 `projectHostedStoryPendingContent → buildCompletedBattleStoryRecords → freezeBattleStoryCommit → prepareStoryStorageCommit`，保 deterministic digest/summary，不额外调用模型。冻结体作为原 pending 的新 parts 发布，不另开 Direct save stage，不先删原件腾空间。

## 4. 容量、原件与保存未知

原 32 角色、12 MiB 请求（含最终 funding/封套）、正文与 reasoning 合计 4 MiB、16 MiB 角色响应、128 MiB 独立 commit、每 active 槽 128 MiB、共享 upload 128 MiB/最多两份、384 MiB 逻辑在途预算 **MUST** 不增。pending 原件加冻结 commit 合计仍须落在同一槽 128 MiB 内；whole commit 自身不超过 128 MiB 不足以证明可以 seal。该预算不限制实际 SQLite/WAL/备份/RSS，也不保证每个合法生成结果都能保存；超限保全文和原件、可导出、零模型/角色重跑。

成功 telemetry **MUST** 使用原成功 schema/原始 carrier，保 usage 数字/null/布尔与 aiModel，不从展示过滤投影反向构造。沿既有 eventWireBytes，无额外短字符串上限；header/readCount 与 telemetry 冲突保两原件并拒绝 freeze。既有 JSON 原件不通过 parse/stringify 改写扩展、Unicode 或空白。

保存 **MUST** 使用同一 single-use action：耐久 `prepareSave` → 一次 `save` → exact receipt。重复点击共享原 Promise；结果未知只查原 sessionId/operationId/wireDigest 的 receipt。absence、读错、不匹配、重启都不许可再次 prepare/save、重上传、重组冻结体或换 operation 另存；只有本次 Native 明确 rollback 且清 attempt 后，用户新的明确本地动作可重试同一 frozen commit。

receipt 证明成功后才 raw-CAS 清原 pointer 并刷新目录。章节读回失败显示“已保存，重读”，不得重新生成/保存；读回和目录刷新 **MUST** 保原 selection fence，迟到结果不得抢走用户更新的会话/章选择。

## 5. 双槽发现、冷恢复与只读作品

两页 mount **MUST** describe 两个 Native product 槽；卡片标明 original product，跨页恢复按钮导航原页，不能以当前页重绑 product。创建与普通生成继续受同槽 admission；另一槽存在同一故事未决续章时显示原入口，Native CAS 仍是最终防线。

v4/purpose=story 只使用原两个 public keys，并以读取到的原 raw 字符串做 CAS 写入/清除；旧普通 owner 不接管/清 v4。坏、超限或 foreign pointer 原件保留并明确提示，不因 Native 有快照而静默覆盖。pointer 缺失且 Native 有 claim 时，只能从原 manifest/claim/input 恢复提示并原 request lookup/replay，不 create；冷恢复从零游标开始，热续流仅使用本次完整接收前缀。cold input-only 且无 claim 时只读/导出/明确放弃，之后用户新动作使用新 IDs 创建，不猜 funding 或续发。

账号/配置变化只 detach 并使旧回调失效，本地原件仍可读/导出。网络恢复只允许原账号，匿名要求当前仍匿名且有原 secret；不能换新账号、自动匿名 fallback 或自动替换秘密。新创建的 capability 撤回 **MUST NOT** 阻断原任务 lookup/replay/status/stop 或本地出口，停止受理不等于服务器终态。

`restored=true` **MUST** 仅允许读原件、原 actor lookup/replay、exact receipt、导出与明确放弃；零 create/seal/role/prepare-save/save，不提供“保旧角色立即保存”绕过围栏。读取到 `abandonRequested=true` 说明已有耐久 confirmed abandon intent，允许针对同一身份继续 cleanup；不能借其恢复生成或保存。

## 6. 本地出口与放弃提示

sealed 原件 **MUST** 用 DESK-101 Native `pending-part` / `pending-manifest` 流式出口，逐文件校验最终 receipt；只有所有请求的原件与说明清单全部成功才称“全部已导出”。不以已提交故事 export 伪装 pending，不造 session/chapter，不新增 ZIP/import、大包 stringify/base64 或任意路径能力。单纯读取/导出不依赖在线账号匹配，也不访问网络。

未 seal 的最新正文 **MUST** 独立显示为“当前窗口原文，尚未耐久封存”，可沿既有 4 MiB 有界窗口正文出口保存；旧 input-only Native export 不能声称包含它。导出失败或取消不自动 abandon。

放弃默认动作为“先导出/返回”，另提供用户最终明确“不导出，仍放弃”。确认 **MUST** 说明将移除本机候选及恢复入口、save unknown 时库内可能已有该章、不删除已存章节或 receipt、不保证服务器停止或退款；之后生成须用户新动作与新 IDs。原 confirmed abandon intent 可继续 exact cleanup，不因跨存储失败伪称全部释放。

清理 **MUST** 沿 schema8/既有 helper 的耐久 intent → exact Flight/secret → exact candidate/uploads → v4 raw-CAS 顺序。cleanup-pending 保原件并提供继续清理；`foreign-retained` 必须具体说明本候选已移除但另一/旧恢复身份仍保留，保留其原入口与既有明确 `replaceRequestId` 流程，不自动替 secret/账户，不宣称整个 product 已可新建。离开/关闭、超时、能力撤回、登录变化或服务端 TTL 不能替用户确认放弃。

## 7. 验收与回滚

依赖片证据只能证明原边界，本片定向、真实 owner→默认 IPC binder→Native pipe/SQLite/导出链、源码独审、冻结完整 CI 和 Windows/Tauri 分列。必须覆盖两 product × 匿名/账号 × system/preset × start/continue，以及 invoke 晚 reject、原 actor 失效、role unknown/accepted、old-roles seal 失败、save ACK 丢、双槽/坏 pointer、cold no-claim、restored、cleanup/foreign-retained、容量与选择竞态。逐场景观察与未验项写入[验收记录](../reports/2026-10-10_191300_DesktopHosted连续故事两页接线验收.md)，不得仅以测试数量关门。

回滚只撤回新创建的页面 capability/接线，保原 pending/claim/receipt、旧任务控制、只读/导出/明确放弃入口和 Direct；不能清 claim、删候选或重模型来回滚。本片不使用真实账号、模型、Key 或外部请求，不部署、不远端写、不发布；真实服务 readiness 与 Windows/Tauri/OS secret/磁盘/窗口生命周期仍须独立验收。
