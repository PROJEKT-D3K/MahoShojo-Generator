# ADR：Desktop 客户端流式生成修订

- 日期：2026-10-09
- 状态：accepted（维护者明确要求在本地 AI 链路验证后实施）
- 范围：`feat/desktop`，`/details`、`/canshou`、`/scenario`、`/free`、`/creator`
- 前置：[预设与 BYOK 修订](./2026-10-09_010600_DesktopAI预设独立身份与服务器BYOK修订.md)、[本地链路实测](../reports/2026-10-09_084100_Desktop本地AI链路实测与协议修复.md)

## 精确取代关系

本修订取代 [AIP ADR](./2026-10-08_173300_DesktopAIProvider选择器与多模型连接体验统一.md)中客户端固定非流式及禁用流式按钮的阶段限制；[AIP 规格](../specs/2026-10-08_173400_DesktopAIProvider共源选择器、快速配置与多模型连接.md)历史实现记录不重写。执行位置、目标身份、凭据准备及可信出站边界不变。

## 输出形态与执行位置正交

- 客户端继续使用 `direct-local` / `direct-remote`，新增可选 `generationMode` 表达本次输出形态；旧调用省略时仍为结构化生成，不迁移旧 Profile、凭据或结果草稿。
- 流式复用 Web 同家族的 Markdown 提示构造、通用卡构造与已有正文预览。不是将原来的 JSON SSE 运输改名为产品流式。
- `/details`、`/canshou` 流式输出通用角色卡，`/scenario` 输出通用情景卡。Free/Creator 仅支持与 Web 一致的 `general` / `general-scenario` 流式模板；其他结构化 Schema 不隐式当 Markdown 解析。
- 两执行位置共用生成方式控件；改变执行位置不清除模型/参数或偷偷切换 Schema。生成中继续锁定同一意图，准备 Key、派发、防双击和取消沿用既有机制。

## 结果与失败边界

- 接收正文 delta 后实时更新已有预览；reasoning 不混入可保存正文。只有正常结束并通过家族卡构造/校验才发布完整结果卡。
- 截断、过滤、工具调用结束、异常流与取消保留收到的正文，不能冒充完整成功，不自动重试。
- 本地流式结果无官方签名；恢复草稿不会触发生成或将签名字段升级为可信状态。
- 输出资源上限、Native SSE 大帧分片、UTF-8 解码及跨源重定向拒绝复用当前契约，不增加流式专属截断上限。原始文本、usage 和 finishReason 保持可核查。

## 验收

覆盖生产页面模式选择与派发、生成前参数冻结、终态前正文、reasoning 隔离、取消与异常、最终通用卡/保存/恢复，并回归非流式与服务器通路。本地模型测试使用合成输入、无真实 Key，监督脚本确认请求数、终态及 owned process 清理。源码/Mock/headless 核验证不得冒称 Windows Tauri GUI、IPC 与操作系统凭据验收。

## 2026-10-15 窄后继：Tavern Direct Markdown 流式

本节为 accepted 范围修订，仅将上述客户端流式决策扩展到 `/tavern` 的 Direct 转换；原五页范围与
验收保留历史含义。Web 与 Desktop 已回用共源提示词、通用卡投影和输出说明，Desktop Direct
接线与定向自动验证已完成；真实 Windows/Tauri、凭据与模型验收仍为 PENDING，按
[唯一 Desktop 计划](../plans/2026-09-30_160100_Desktop客户端阶段实施计划.md)的 D5.1-T 推进。

### 输出与执行边界

- 五种输入模板只选择 Markdown 写作风格：`general` / `magical-girl` / `canshou` 实际输出
  `general` 通用角色卡，`general-scenario` / `scenario` 实际输出 `general-scenario` 通用情景卡。
  流式不产出结构化魔法少女、残兽或情景字段，也不重建 `userAnswers`。
- 复用 `ai-core/tavern-generation` 的 Web 提示词、`domain/tavern-card` 的 Markdown 投影与既有
  预览；输出类型及流式/结构化差异提示须由 Web 与 Desktop 共用，不复制另一份提示词或卡构造。
  投影器可用于部分正文预览，本身不证明生成完成。
- 只接 `direct-local` / `direct-remote` 的既有 wire、Native command/ACL 与可信出站机制；
  自定义连接和已验证预设仅使用当前支持的协议，不扩充协议、Native allowlist 或凭据目的地。
  Hosted 保持既有 `tavern-convert` JSON 通路，不新增流式 routeId、路由或通用代理能力。

### 完成、保文与草稿

- 仅在既有流收集器接受正文、传输正常结束且 `finishReason === 'stop'`、正文非空并通过共享
  通用卡投影及领域校验后，才发布 `completed` 结果卡。reasoning 不混入正文，结果始终未签名，
  `_tavern.raw` 仅从本次冻结的输入原件补回。
- 取消、`length`、过滤、工具调用结束、缺失正常终态的 EOF、协议失败及无效输出均保留已接受正文
  和输入原件；未完成正文可显式导出为文本，原件保留既有导出入口，不冒充完成卡或保存到卡库。
  不自动重试、重放或跨 Direct/Hosted fallback。
- Web 当前手动停止或安全截断后允许保存部分正文的政策保持不变。Desktop 使用既有 Direct
  正常终态门禁，这项必要平台差异只影响完成/保存资格，不以共源投影抹平，也不回改 Web 政策。
- Tavern 草稿仅增可选 `generationMode`，缺省按 `non-stream` 恢复；结果按实际输出 `cardKind`
  校验和恢复，不按输入模板误还原为结构化卡。恢复不派发，旧草稿和合法扩展不丢失，凭据不进草稿。
- 准备与派发继续冻结输入、模板、输出方式、目标、模型/参数及凭据世代；沿用账号/凭据变化、迟到
  结果、未保存内容与离开/换源守卫。服务器系统/自有 Key 冷却及 unknown 围栏不变，Direct 不受
  服务器冷却约束。

### 保留项与退出条件

Hosted 流式另行修订：必须先明确可验证的正常完成证明、派发后 unknown/no-replay 合同，以及严格
业务 body 与固定路由边界；不能把通用 `done.ok` 或 body EOF 隐式当作 Tavern 完成证明。本节不以
Direct 接线顺带开放 Hosted 流式、云保存、立绘或签名。

沿用现有输入/输出、内存、事件与并发资源预算、取消、UTF-8/SSE 分片及可信出站安全要求；不新增
输出截断预算，不改变 Direct 默认无应用层硬超时或 Hosted 资源保护。后继验收覆盖五模板到两种
实际输出、模式/目标切换与冻结、部分正文及 reasoning 隔离、正常与异常终态、未完成文本/原件导出、
旧新草稿恢复和完成卡本地保存，并回归 Web 部分保存政策、规则映射、非流式与 Hosted JSON。
真实 Windows/Tauri、凭据与模型证据仍须独立验收，不由本次文档修订关闭。
