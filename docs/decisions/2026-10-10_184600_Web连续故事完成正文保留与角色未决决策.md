# Web 连续故事完成正文保留与角色未决决策

状态：accepted
日期：2026-10-10
范围：DESK-102，Web 两页既有连续故事 owner 与后继 Desktop 可复用的小型视图/纯规则

## 原问题与窄修订

Web `useBattleStorySession.runGeneration` 已收到完整正文后仍等待角色同步。此前网络或 JSON
解析异常进入生成总异常路径，实时卡因 `isGenerating=false` 消失；尚未创建可保存候选，完整正文
没有可达的导出与恢复动作。这是已完成正文的保存前故障，不应显示成需要重新生成。

本决策只修订这一条 Web 失败语义。DESK-098/100 的无 header 旧 Web DTO、SSE/hash 与 actor
适配保持；不接 `arena-story-v1`、Desktop 新协议头或其响应容量限制，不改变服务器签名权威。

## 决定

- 正文完成后，先保留完整正文、报告/摘要、卡片 snapshot 与生成前独立输入，再开始角色同步。
  原 session/action、续写 CAS、分支/重写锚点由原动作闭包持有，不从重试时的编辑态重建。
- 网络、JSON 解析、成功响应结构异常保持 `unresolved`。显示“正文已完成，尚未保存”，提供
  完整正文导出、原 generation 的角色重试、用户显式保留旧角色后继续原保存流程。
- role 重试单飞；accepted、已选择旧角色、HTTP 失败兼容路径或 frozen commit 不允许再次
  role POST。重试从不回到 runGeneration/model POST。未知不自动降级旧角色。
- 明确 HTTP non-success 保持旧角色加 warning 后自动进入旧保存逻辑；错误正文不可读不
  推翻已明确的 HTTP 状态。缺 generationId 仍按旧 Web 兼容路径保留原角色加 warning；
  未请求角色写入仍为 `not-requested`。这些不是新的服务器成功证明。
- 请求只保留原 generation、投影后的原 roster 与原 actor headers 于当前窗口内存。
  异步准备请求 headers 前冻结认证原件/世代，完成后仍相同才派发，不能将旧凭据绑到新世代。
  原通用派发器只复用已准备完整头；最终模型 fetch 前再核同原世代，保其路由/credentials/
  settlement 与能力约束。请求构造和身份校验通过后才 acquire，不遗留未派发 lease。
  role 前后核对 Web 原本机认证记录、认证 snapshot 世代和匿名 actor；发生注销/切换则候选只读/导出，不借新身份
  也不继续使用旧 headers 发请求。无 header 服务器仍最终裁决 generation owner。
  本片不声称解决不可观测的 HttpOnly cookie 跨标签变化；它不新增认证协议或绕过服务端校验。
- 完整角色响应先整体校验再沿原 merge 规则应用，不以含 signature 字段推导 verified/native。
  accepted 仅表示此次角色响应已采纳，绝不表示本地章节已保存。
- start/continue 继续既有 immutable commit、原 CAS、receipt/unknown 与本地保存重试。
  branch/rewrite 继续既有多步保存，不在本片冒充原子写入；部分写失败保全文、导出与明确
  保存未知提示，不提供可能重复部分写入的保存重放，也不重新 role/model。
- 新导航/章选择优先于旧异步保存读回；候选仍可查看，但不得迟到抢选。卸载使角色回调失效，
  未决选择不会在新页面落盘。已有生成中停止仍只保不完整预览，不创建完成章；完成后不再把
  原模型流的停止按钮当角色决策。丢弃保持显式确认，取消确认保留候选。

## 共享与合理宿主差异

`domain/arena-story-completed-output` 只包含 completed-output/role 判别值与许可纯规则。
`ui-web/arena-story-session` 的受控 `BattleStoryPendingOutcome` 复用既有 Web 样式，提供正文、
角色操作及保存/导出插槽，不拥有 fetch、认证、IndexedDB、Native、签名或持久化。

Web 实际消费这两个入口。Web 完成候选目前仍仅当前 hook/window 内存，刷新/离开可能丢失，
沿既有 beforeunload 提醒；不把 arena 草稿能力说成完成章耐久恢复，不新建 Web 持久化方案。
Desktop 后继可消费相同视图/规则，但原件 seal、恢复作品 fence、原 actor 和耐久 receipt 都归
其原 owner/Native；本片不开放 Desktop Hosted owner/UI，也不把 Web 内存承诺套到 Desktop。

## 验证与回滚

定向覆盖四种动作的 complete→role 异常、结构失败、旧 HTTP/missing-id 兼容、固定输入、
双击、已接受后零 role、原 commit 重试、actor 变化、选择优先、卸载/确认取消与导出。
包纯边界、类型、实际 Panel 回用和已存章节导航回归分列。完整 CI 由整合冻结树执行；
本地合成测试不等于真实浏览器/真实账号/模型或 Desktop Windows/Tauri 验收。

撤回此切片不改变旧 IndexedDB schema、已存章节、服务器数据或原 draft key。尚未保存的
内存正文应先导出，不保证回滚页面后仍存在。
