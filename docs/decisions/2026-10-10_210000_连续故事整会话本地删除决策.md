# ADR：连续故事整会话本地删除

- 日期：2026-10-10
- 状态：`accepted`（D5.1b b-2 窄后继；源码、定向、Native/pipe、独审及冻结完整CI通过，真实平台另验）
- 决策标识：`ADR-desktop-story-session-delete-v1`
- 规范：[DESK-104](../specs/2026-09-30_160000_Desktop客户端实施规格.md#desk-104-连续故事整会话本地删除2026-10-10)
- 唯一实施入口：[Desktop 阶段计划](../plans/2026-09-30_160100_Desktop客户端阶段实施计划.md#2026-10-10-连续故事整会话本地删除窄后继)
- 分项验收：[本片验收记录](../reports/2026-10-10_212900_连续故事整会话本地删除验收.md)

规范性词汇沿 RFC 2119 / RFC 8174。本决策仅解除 Desktop 整会话删除的阶段限制；DESK-103 的 start/continue 接线与当时不含删除的历史范围保持不变。

## 1. 精确范围与不可逆语义

`/battle`、`/arena` 的 Web 与 Desktop **MUST** 真正回用同一个受控删除动作/确认区段和 BaseModal。用户每次明确确认后，只删除一个本机会话、其自己的全部章节、检查点和章内 receipt，包括未在当前目录页显示的记录。其它分支会话、源卡、服务器记录、既有文件导出与整库备份 **MUST NOT** 被连带删除。

删除不可在故事页撤销；不是安全擦除，不保证数据库文件缩小。默认安全返回/先导出，不能强制自动备份或自动导出，不自动停止服务器、清候选、换账号/执行者或请求模型。账号变更不剥夺本机读取/删除权。

本片不包括分支、重写、截尾、批量清理、回收站、undo、自动 VACUUM、永久 tombstone 或第二 operation/receipt ledger。SQLite 仍为8、IndexedDB 仍为4；不改历史 migration 字节、表/index/store、既有 JSON 与生成协议。Hosted `arena-story-v1` 仍只允许 start/continue。

## 2. 冻结目标与宿主事务

- 点击时 **MUST** 先捕获目标ID，再读取新鲜本地身份，冻结标题预览、章数与期待身份。确认回调不能改用后来选中的故事。Native 复用 session `StoryRecordDescriptor`（instance/revision/digest/length）与 expected head/count；不为删除水化全故事正文。
- Native **MUST** 按既有 stages → maintenance write permit → DB 锁序，在同一锁域检查同会话有效 Direct stage 和两个 product 的 Hosted active/upload（包括 active=0、saveAttempt、abandonRequested、restored）。匹配引用阻挡删除；损坏/不可判定的小 metadata 不得当作无引用。不自动 abort/abandon，不跨 await 持锁。
- Native **MUST** 对冻结 instance/revision/head/count/session document digest 全核验；不匹配零删除。单 SQLite transaction 删除该会话全部 checkpoint/chapter/session；失败只有明确 rollback 才可报告 not-written，commit/IPC 不确定保 unknown，未解事务继续沿现有 connection fence 拒绝读取。
- Web **MUST** 在同一三 store readwrite transaction 内读取 session，比较冻结完整 session 的现有 canonical digest 后，再全量 cursor 删除自有记录；明确区分 deleted/currently-absent/conflict，oncomplete 才返回成功。missing 不能冒称本次实际删过记录。
- Web 子记录 writer 的相邻护栏 **MUST** 在同一 readwrite transaction 纳入 sessions store，所有父 key 已存在才 put chapter/checkpoint(s)。它阻止删除后的迟到孤儿，不使旧 branch/rewrite 多事务流程变成原子，也不承诺跨 tab 的完整双向隔离。

## 3. 未知结果与 owner 生命周期

删除 **MUST** 单飞；本 owner 生成、保存、导出或有未处理作品时先处理原作品。取消、Esc、关闭确认只关层，不删除、不停模型、不清恢复 pointer。

删除 ACK 未知时 **MUST** 在本 owner 内保留一个绑定原会话的小型内存观察描述。关闭确认层不丢该身份，原 A 在核实前不可继续生成/编辑；选择无关 B 后其阅读、生成、保存与导出仍可用。第二次删除先明确要求只读核对上一次结果，不扩成多删除恢复系统，不持久化观察信息。

删除 ACK 未知仅允许原目标的只读 describe/get 观察：

1. 受检 missing：目前已确认本机会话不存在，不证明某一次操作 exactly-once
2. 原身份仍在：未确认删除，若用户仍要删除需重新读取并再次确认
3. 原身份变化：不继续删新版，重新读取/确认
4. IO、坏数据或未恢复连接：仍待确认，不以空目录/不完整分页冒充 missing

**MUST NOT** 自动重发 delete、save、prepareSave、begin/end、模型/角色请求，也不耐久保存或启动时重放删除 intent。删除移除章内生成 receipt；旧 generation unknown 查不到 receipt 仍 unknown，不因此重存原 start。既有备份恢复可能重新带回故事，原 restored/cold 围栏保持，不赋予新的写权。

删除成功后只刷新目录；原 selection epoch 仍有效且活动目标仍是原会话才采用 fallback/清空。新选择优先，迟到删除不能抢回后来选择。目录读取失败显示“已删除，目录刷新失败”，只允许重读，不重复删除；目录成功但 fallback 详情失败，也须在原选择 token 内清掉已删缓存，不能重新启用基于旧 A 的生成。

## 4. 预算与验收

原32角色、12MiB请求、4MiB正文/推理、16MiB角色响应、128MiB独立commit/active槽、共享128MiB upload与384MiB逻辑在途预算保持。actor/funding/createClaim/v4 pointer、原JSON和Direct/Hosted协议保持。删除只用受限metadata与SQL行，不新增固定总章数上限。

验收 **MUST** 分列冻结源码、定向TypeScript/React/真实IndexedDB、Native/真实默认binder→Native pipe、独立审查、完整CI与Windows/Tauri。必须覆盖全量多页、其它会话不变、每次DELETE前后rollback、active/upload/stage竞态、descriptor篡改、success丢ACK后四类只读观察、success+目录失败、A确认后选B、单飞/取消/导出和原未知生成零重发。pipe不等于Tauri或真实模型验收。

若实际现有 owner 路径能在删除后重新 begin 同一已提交的 start，须先停下报告真实轨迹与合同缺口；不得悄悄新增永久账本。任意调用方重放很久以前的 raw IPC start 的永久阻断，不是本片承诺。
