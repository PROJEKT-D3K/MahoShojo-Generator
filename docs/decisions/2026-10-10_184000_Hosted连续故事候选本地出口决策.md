## 1. 范围与用户含义

新增 Native 与 contracts/IPC 的 sealed pending 原件导出、明确本机候选放弃，以及 TS 高级逐帧 reader/publisher/single-attempt receipt 原语。本片 **MUST NOT** 开放两页 Hosted story owner/UI capability、修改 Web hook、增加通用 jobs、永久 request 墓碑、数据库、产品槽、秘密槽、ZIP/import 或远端操作。

后继 UI 默认动作 **MUST** 为“先导出/返回”。用户明确最终放弃 **MAY** 不先导出；磁盘不可写不能强制用户永远保留候选。放弃仅移除本机候选恢复入口，不保证服务器已停止或退款；save unknown 时本机库可能已有章节，放弃 **MUST NOT** 删除已提交 chapter/checkpoint/receipt，不能变成自动重保存、换 operation 另存或重模型许可。任何新模型任务仍需用户新动作与全新 IDs。

cold input-only 且没有 claim 时 **MUST NOT** 自动猜 funding 或补 create。保留、导出、明确放弃后，由用户明确新建。跨页恢复卡 **SHOULD** 导航回 original product 页，不以当前页重绑原候选。本片不实现这些 UI。

## 2. 最小耐久清理意图

schema8 **MUST** 仅通过新迁移给原 `arena_story_pending` 加 `abandon_requested INTEGER NOT NULL DEFAULT 0 CHECK(... IN (0,1))`。MIGRATION_6/7 原字节不变。该位仅 Native 可设，无 renderer manifest、上传、清除或回滚入口；不新增任务表或超越 pending 生命周期的记录。

`PendingSnapshot.abandonRequested` 为 Native 的必需只读布尔投影。v1–v7 历史备份按版本读列，不能 SELECT 不存在的列；v8 位、原 claim 与原件一同备份。恢复保留位并继续加 restored fence，既不自动恢复执行，也不自动完成秘密清理。metadata/claim 的原 64 KiB 合计上限和原 32 角色、12 MiB input、4 MiB output、16 MiB role、128 MiB 单槽及384 MiB 合计预算不变。

本机 abandon 请求 **MUST** 闭合为 `{key:{product,requestId,pendingRevision},inputDigest,actor}`。Native 在同 product admission 下，以还存在的 active manifest 重验全部 identity/actor；不凭 renderer identity 清理不存在的候选。不要求当前在线账号相同，不访问全局登录状态，也不授予网络权利。

顺序固定：

1. 将 exact active 的位耐久设为 1，仍保留身份、原件、claim、save attempt。位设置后 create/rebind/role/seal/prepare-save/save **MUST** 拒绝；只读原件、导出与原 exact receipt 查询仍可用
2. 释放 DB 锁，在既有 Flight mutex 内使 exact 原 Flight、subscription、内存凭据失效；原 create permit 下一次消费必须因位或缺失 original 而失败。不得另建 registry；晚 token header 不能重写原秘密或新槽
3. 在同一 Flight mutex 保护下读/精确清理唯一 original anonymous slot，并读回确认。秘密库失败或读取不确定 **MUST** 留 active+位+原件；继续明确返回 cleanup-pending，不称槽已释放
4. 只有该秘密步骤得到确定结论，才在同 admission 下 exact 删除 active 与原身份关联 uploads，并清这些 token 的内存 buffers/attempts。删除事务不确定时重读；不能把未知回执表述为全部完成。之后 UI 仅可 raw-CAS 清自己的 v4 pointer，不能覆盖新 pointer

admission、Flight、SQLite、维护锁 **MUST NOT** 跨网络 await。OS secret 步骤是本机同步短操作，不持 DB connection。pending 原身份始终留到最后，因此崩溃后仍可用相同请求显式继续；没有自动后台清理或自动扩权。

## 3. 匿名槽的 exact 绑定与兼容

新 story 的 OS anonymous record **MUST** 带可选 Native-only `storyBinding:{attemptId,inputDigest}`，由耐久 create claim 的同次准备产生。普通单次旧记录与旧 story 记录可无该字段，不能伪造补 binding。binding 不进 pointer、导出清单或 renderer 可写对象；账户 Cookie、Provider Key 与另一 product 不在本操作目标内。

abandon 删除秘密 **MUST** 同时匹配 product、requestId、claim attemptId 与 inputDigest。无 claim 的 input-only、历史无 binding、不同 binding 或不同 request 仅返回 `foreign-retained`，绝不盲删。缺失是确定的 `absent`；delete 返回失败也必须读回，真正缺失才可视为清理完成。当前 original slot 仍在或读回失败则 `unresolved`。

`foreign-retained` 允许移除用户已明确放弃的 DB 候选，但 **MUST NOT** 宣称整个 product 可新建或其秘密已删除。另一/旧恢复身份继续按既有恢复提示显示，新的明确任务仍须通过原 `replaceRequestId` 确认流程；本 helper 不自动设置 replacement，不自动重试 create。此结果是“本候选已移除，另一个恢复身份仍保留”，不是隐藏永久锁死，也不是清未知秘密的例外。

分步 reply 包含 exact 请求身份、state、flight、secret、candidate。仅 candidate 确定 removed 且 flight/secret 非 unresolved 时 state 才可为 abandoned。无 active 无法获得清秘密权限；未知仍保守。

## 4. Native 原件导出

复用原故事导出 sink 的唯一 session、临时文件、空间检查、有限帧、取消/TTL、SHA-256、长度、fsync、no-clobber 和最终成功 receipt，不引入新文件权限。

闭合 source 为：

- `pending-part`：exact key/inputDigest/kind/digest/byteLength，读取 sealed BLOB 原字节
- `pending-manifest`：exact key/inputDigest，由 Native 明确白名单生成 ≤原 metadata 上限的小说明清单，只含非秘密身份、parts 描述与 model/role/save/restored/cleanup 状态；非备份/import 格式

renderer **MUST NOT** 提供路径、文件名、SQL、源文件或导出正文。Native advance 逐帧读原件并写临时文件，只返回进度。begin、每帧、end 重核 exact source 与 Native sealed token，防止删除后重建相同公开 identity 的旧导出复活。end 在同 product admission 内重核并出版；原件变化、取消、损坏、磁盘失败不能返回成功。

按固定 kind 顺序逐文件导出原件，最后导出说明清单；只有每文件完整 end receipt 才是成功，整个动作全数完成才可说“全部已导”。中途失败保留已成功文件，不自动 abandon。最新未 sealed 正文 **MUST NOT** 被 input-only 的 Native export 宣称已保住；后继 UI 必须另示当前窗口原文未耐久。

## 5. 高级本地原语与角色冻结

TS reader/publisher **MUST** 对 schema、完整 identity、长度、摘要与每步回执验证。原 JSON bytes 保真，不整包 stringify/base64。新 revision 保全部旧 parts，不更改 immutable 原件，未知 seal 只作 exact 本地封存恢复，不授予模型/角色执行。

新 `old-roles` 选择与含 `storyRoleSync.reason` 的 frozen commit **MUST** 同一次 seal；封存失败仍 unresolved。不加 manifest reason 字段。历史旧快照继续可读，不能倒拒备份。

保存以单次 action 的闭包封装 prepare/save，多次点击返回原 Promise。已 restored/已有 attempt/abandoning 只 receipt；prepare 或 save ACK 未知后，absence/mismatch/读错都不能再次 prepare/save。只有该次 Native 明确 rollback 且清 attempt，并由用户新的明确本地动作选择原 frozen commit，后继 owner 才可重新尝试。

## 6. 验证边界

必须覆盖：schema1–8、恢复位、跨进程重开、secret删除失败及ACK丢、账户切换、无claim/无binding/异binding、两product、late header/permit/seal/save、既有receipt不变；export逐帧原 bytes、exact token/hash/length、取消/TTL/无空间/no-clobber/fsync/abandon竞态；TS回执漂移、未知单次保存与部分导出。

定向测试、同源 headless Native、源码独审、正式完整 CI 与真实 Windows/Tauri/OS secret/磁盘/网络验收 **MUST** 分列。此 ADR 的 accepted 不关闭真实平台或完整两页旅程门禁，不授权发布、部署或真实凭据/模型。
