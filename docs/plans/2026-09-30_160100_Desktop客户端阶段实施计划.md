## 0. 总体原则

1. **按实际依赖关闭平台门禁，再宣称业务完成。** 静态产品壳只依赖 D0 的本地 UI/安全基础；生成依赖 D1，持久化依赖对应 D2，执行不可信内容依赖 D4。无关能力未验收不阻止独立静态页面，但不能被默认为通过。
2. **先冻结既有语义，再跨端复用。** 本地库阶段不得改摘要算法；TS 业务不复制到 Rust。
3. **共源抽取与 Web 回用一起交付。** 不写第二份 Desktop 页面等待以后统一；先补真实共享壳，再按功能纵切。
4. **每个阶段独立可交付。** 只增加当前所需依赖，不把版本升级、产品重写和资源生成混在一起。

  |                              -> D2.3 a 契约、b 导出、c 导入

          +-- D3.2 本地角色管理（依赖 D2）

### D0 Desktop skeleton 与安全边界

交付物：

- `apps/desktop`：manifest、README、Vite 配置、TypeScript 配置、lint/test 配置、最小 UI shell；
- `apps/desktop/src-tauri`：`Cargo.toml`、`build.rs`、`tauri.conf.json`、`capabilities/main-ui.json`、
  入口与一个只读运行时自述 command；
- 仓库接线：`.gitignore`、workspace 边界检查忽略 `target`、`tests/workspace-structure.test.ts`
  结构门禁、root 过滤脚本、独立 Rust CI workflow；
- 显式 CSP，`withGlobalTauri=false`，无 Tauri 插件。

退出门禁：

- 前端 `build`、`test`、`lint` 通过；
- `cargo fmt --check`、`cargo clippy`、`cargo test` 通过；
- `check:workspace:boundaries` 与 `test:repo` 通过；
- `apps/desktop` 的 `build` 脚本不含 `tauri build`；
- capability 只用 `webviews` 且不含通配；
- 渲染层无 shell / fs / sql / 任意 fetch 依赖。

已知限制：GUI 交互行为无法在无头环境验证。凡涉及"实际点击后运行结果"的验证 **MUST** 记录为
未验证并附可复现步骤，**MUST NOT** 记为 PASS。

### D0.5 Secret store spike

结论：**成立**。`keyring` 的 Windows Credential Manager 后端在本机完成写入、读取、删除与
幂等二次删除，全程无需交互式解锁；Stronghold 不进入 V1。ADR 第 6 条随之冻结。

已落地：`secret.rs` 可插拔 `SecretStore` trait + `keyring` 绑定；command 层只有 `set` / `has` /
`delete`，没有明文读取入口；secret 引用字符集与长度上限由 `desktop-ipc` 契约与共享 fixture 约束；
`SecureVault` 收敛为 `set/has/delete`。macOS Keychain 与 Linux Secret Service 的真实往返留待 D5
发行门禁。

退出门禁：renderer 无返回明文 secret 的入口；secret 不出现在 SQLite、日志与导出；ADR 结论记录。

### D1 Direct AI 最薄纵切

交付物：

- SQLite 与 Provider Profile 存储（Profile 只存非秘密字段与 `secretRef`，明文 API Key 只在 OS 凭据存储）；
- Rust 侧 HTTP transport 与 OpenAI-compatible adapter；
- `streamDirectAi` / `cancelDirectAi` / 连接测试 command，`Channel<AiStreamEvent>` 流式；
- TypeScript 侧 `DesktopAiExecutionPort` 适配与最小测试面板；
- 契约一致性门禁（共享 fixture + 两侧校验）。

依赖选择：`reqwest` + `rustls`（纯 Rust，无 OpenSSL，跨平台一致）、`rusqlite` + `bundled`
（不依赖系统 SQLite，代价是编译 C 源码与二进制增大）。

退出门禁：

- 至少一个 loopback OpenAI-compatible 端点与一个公网端点实测通过；
- 取消真正中止上游，并投递 exactly-once 终态；
- 契约一致性门禁在两侧均生效；
- Direct 出站路径拒绝项目自有域名；
- 出站端点只来自已保存 Profile，请求 DTO 不含 endpoint / header / secret 明文。

未验证项必须显式记录：真实 Ollama、LM Studio 与公网端点的连通性由使用者在
`pnpm --filter @mahoshojo/desktop run dev:tauri` 下自行复现；CI 内只跑进程内自建的
OpenAI-compatible SSE 服务。

#### D1 当前状态

执行核已落地：SQLite + `provider_profile` 表 + migration journal（Rust 为 opaque 文档的 dumb
store）、Profile CRUD 与保存前 native 独立校验、`stream_direct_ai`/`cancel_direct_ai`（SSE 增量解析、
取消注册表、exactly-once 终态）、transport policy（自有域名拒绝、公网明文 HTTP 需显式确认、重定向
缺省关闭、`no_proxy`、header 白名单与 secret 引用校验）、桌面 `AiExecutionPort`、最小 Profile 面板。

**尚未完成，D1 退出门禁未闭合**（属延期而非放弃，尤其第 1 条不能被无声跳过）：

1. 真实端点（Ollama / LM Studio / 公网）未实测；
2. `thinking` 字段被 `deny_unknown_fields` 拒绝，尚未映射到 Provider 参数；
3. serde 不支持在 internally tagged enum 上使用 `deny_unknown_fields`，流事件未知字段会被静默忽略，
   已知弱点，靠 fixture 双向断言兜底；
4. `anthropic` / `google` adapter 未实现，当前显式拒绝；
5. 面板只覆盖最小流程，完整设置页归 D5。

> 「D1 门禁未闭合却已推进到 D2.3」是必须显式记录的迁移差距：五条未闭合项均落在其他阶段
> （Provider 覆盖面 / Direct 流语义 / 设置页），不阻断本地库工作，但「D1 门禁未闭合」与
> 「D2.3 可以开工」同时为真，不得被误读为门禁被默认放弃。

#### D1/D2 职责边界修订

原计划把 SQLite 整体放在 D2，会使 D1 无法满足「出站端点只来自已保存 Profile」：Rust 侧必须自己
持有 Profile 才能解析 endpoint 与 secret 引用。修订为 **D1** 引入 SQLite 与 migration journal、只建
`provider_profile` 表（Rust 是「已校验文档的 dumb store」）；**D2** 在同一 SQLite 上增加本地卡、
Web 包与 blob 表及崩溃一致性、备份/恢复与 GC。该修订不改变 ADR 第 7 条分层：Profile 组装与校验仍在
TypeScript，Rust 仍自产路径与 SQL 选择器。

### D1.5 内容摘要语义下沉（已完成）

拆成文档修订（D1.5a）、下沉共享包（D1.5b）、golden fixture 冻结（D1.5c）三个可独立提交的原子步骤，
均已落地：

- ADR 第 8 条改为「单一权威 TS 实现 + golden fixture 冻结 V1 逐字节输出」；
- canonicalization、内容摘要、本地 ID 派生与传输元数据剥离下沉 `@mahoshojo/local-library`，
  `apps/web` 直接消费；传输元数据剥离函数有 4 处生产消费方，更名 `stripLocalCardTransportMeta`；
- fixture：`packages/local-library/fixtures/local-card-digest-v1.json`，覆盖 UTF-16 键排序、
  `1e-6` → `0.000001`、`-0` → `0` 等与 Rust 默认不同的历史语义；孤立代理项的摘要是
  `JSON.stringify` 转义产物 `"\ud800"` 8 个 ASCII 字符的 SHA-256。

**已知的门禁边界**：fixture 只能探测未同步的改动，探测不到「实现改了、fixture 一起重新生成」；
后者由 `caseDescription` 与 code review 拦住，已写入 fixture 注释。

### D2 Installed 本地库

D2 拆成五段，顺序固定：每一段引入一类新的失败模式（SQL、文件系统、并发、跨运行时契约、破坏性
恢复），合并成一个交付会让任何一类问题的根因都被其余部分淹没。

#### D2.0 SQLite 本地卡存储（已完成，含一轮 remediation）

交付物：schema v2 与 migration、`local_card` 表（opaque `document` + `card_type`/`updated_at`/
`deleted_at`/`content_digest` 四个 Rust 自有索引列）、索引列与 document 一致性复核、keyset 分页、
业务级卡片 IPC、桌面端 `CardRepository` adapter。

对后续仍有约束的实现决定（审查发现并修复，门禁经注入验证）：

- 三个写入口（`save`/`delete`/`restore`）同形：都接受调用方组装的完整记录，native 校验状态转移并
  单条语句写入整行——软删若只动索引列，`get()` 会交回「看起来未删除」的 document；
- migration 每个版本一个显式事务（建表 + journal + `user_version = N` 同进同退），否则崩溃后
  会永久跳过后续迁移；
- keyset 排序键是 `updated_at_sort`（UTC epoch 毫秒），由 native 自行从 document 解析——字符串
  比较在带 offset 的 RFC3339 下不成立，且调用方提供的排序键不可采信；
- document 载荷为 `Box<RawValue>` 保留原始文本，`serde_json` 拒绝的 `\ud800` 转义必须能落库
  （`DESK-062`）；跨运行时契约在 `contracts/desktop-ipc` + `fixtures/desktop-local-cards.json`
  （放 contracts 而非 local-library 是为了避免 workspace 依赖环）。

#### D2.1 Web Package ZIP blob 持久化（已完成）

schema v4 落地 blob 内容寻址存储、`local_web_package` 与引用表、同目录临时文件 + flush + 原子 rename
与去重/自愈。对后续仍有约束的结论：

- `contentDigest`（= `ref.digest`）是 **manifest** 的摘要即领域身份；blob 地址是**归档字节**的摘要。
  两者必然不同，MUST NOT 加「相等」校验；归档字节归属由 TS 侧 `unpackWebPackageZip` 重算核对；
- 记录自称的 `archiveByteLength` 由 native 与实际字节数复核，不一致按 `index-mismatch` 拒绝；
- 共享 fixture 的 base64 载荷必须解码后断言长度与 ZIP 魔数，且读写方向共用同一 `Base64Bytes` DTO；
- `readArchive(digest)` 的键是 **manifest 摘要**：`contentDigest → 包记录 → 引用行 → blob` 两跳；
- `deriveLocalWebPackageId` 权威在 `@mahoshojo/local-library`，记录契约 `superRefine` 强制；
  native 不在 SQL 里重算派生规则；`ref_digest UNIQUE` 与 Web IndexedDB unique index 对齐；
- metadata 在但字节丢失时重写报 `repaired` 而非 `stored`，否则「库已不健康」会被说成正常写入；
- 读取方向已切 `tauri::ipc::Response` raw 响应；写入方向保持 base64。「是否切 raw」按量级逐向决定，
  MUST NOT 当作一次性全局决定（见 D2.3b2-r5）。

#### D2.2 完整性审计与孤儿 GC（已完成）

`DESK-065`（维护并发模型）与 `DESK-066`（审计分类）是 GC 正确性的定义：保存跨 blob 文件、blob
metadata、包事务三个资源，GC 落在「blob 已发布、引用行未 commit」窗口会删掉 in-flight 的 blob。

- D2.2a 并发地基：`LocalLibrary` 单一 managed state（四个 store 共用一条连接）、`MaintenanceGate`
  （窗口内写入被拒）、数据目录 `fs4` advisory lock。单实例**不用** `tauri-plugin-single-instance`——
  后者按 app id 判定，挡不住「不同 app id、同一数据目录」（`DESK-068`）。这段同时修掉了 D2.1 已存在
  的「写 blob」与「写包事务」之间无互斥的缺陷。
- D2.2b 完整性审计：`audit.rs` 按 `DESK-066` 分六桶 + `PRAGMA foreign_key_check`，只报告不修复。
  第六桶 `record-without-reference`（缺引用行的包对用户表现为打不开）。V1 不纳入 `quick_check`——
  它回答「文件是否损坏」而非「不变量是否成立」。
- D2.2c 孤儿 GC：只删不在任何引用表中的 blob，判定只依据引用表（`last_referenced_at` 不参与），
  标记—再确认；删除顺序由 `DESK-072` 固定为「先 metadata 后文件」。桶五的包字节会被 GC 回收——
  这不是 bug：这类包在 GC 前就已打不开，真正损失由审计桶五暴露。Web 侧不实现审计/GC：IndexedDB
  记录与字节在同一事务，无可审计中间态。

Rust 陷阱（对后续 native 代码仍有效）：`rusqlite::MappedRows` 的 `Item` 是 `Result<T>`，`.flatten()`
能编译但会静默跳过出错行——审计会少报、GC 会把每个 blob 误报孤儿。修法是
`store::collect_rows`：`Result` 不实现 `FromIterator`，正确写法在类型上无法被误写成 flatten；
同样勿用 `scalar()` 的 `unwrap_or(0)` 折叠「查询失败」与「真有 0 条」。

#### D2.3 Portable archive（Web 与 Desktop 共用）

交付物：`@mahoshojo/local-library` 持有 portable archive manifest 契约（V2）、两端 adapter 产出
与消费、导入前摘要与冲突策略、设备级承载页面。manifest V2 **直接替换** V1（野外不存在 V1 归档），
`formatVersion` 从 `2` 起步；`assets` 命名空间移除。

规范性要求（`DESK-063/070/071b/074/059b-c`，详见规格）：

- 包内容摘要与归档字节摘要 MUST 是两个明确命名、明确验证的字段；
- Web 包条目 MUST 是独立 schema，MUST NOT 复用 V1 asset 条目（其 superRefine 对 Web 包不成立）；
- 上限拆三个：打包输入（256 MiB，由 ~2.1× `zipSync` 峰值实测推导）、最终归档输出、单次 IPC 块；
  归档上限 MUST NOT 复用 `MAX_BLOB_BYTES`；
- 字节传输切 Tauri raw IPC：结构化请求 + raw 响应可共存（`Response::new(Vec<u8>)` → `ArrayBuffer`）；
  raw 请求体不能携带结构化参数，但 `InvokeOptions.headers` 可携带元数据；
- 导出 MUST 全程不持维护窗口（`DESK-071b`）：自洽性由内容寻址与 `BlobStore::read` 摘要校验保证，
  并发只能让导出**失败**、不能让清单与载荷错配；命令形状为 `begin` + `append` 两条，没有
  `finish`（native 按累计字节自行核对、fsync、原子 rename），exportId 由 native 分配作 epoch
  guard，`begin` 回收任何已存在会话；
- 一致性口径是「成功导出 = 自洽列举」，不是 point-in-time 快照；
- 导出目录 `<data_root>/exports/`，文件名 `local-library-<YYYYMMDDTHHMMSSZ>.zip`（UTC），
  不覆盖（`persist_noclobber`，目标存在即 `export-target-occupied`）、V1 不自动清理、文件名不含
  用户数据；native 备份另落 `<data_root>/backups/`，不混。`persist_noclobber` 是同卷原子落位 +
  no-clobber，不做父目录 fsync，不宣称断电级持久；
- 不可信归档解压边界由 `DESK-074` 固定：manifest 优先是格式属性（先读清单才能在任何分配发生前
  拒绝超限输入），bounded streaming import 是 mandatory 而非可选优化；冲突策略收敛为
  existing wins / skip + report；
- 导入 MUST 全程零网络请求，且由可执行断言证明（导入路径上 fetch/XHR 被换成抛错桩，并另有断言
  证明守卫本身有效）；
- portable archive 业务语义继续归 TS 权威实现，MUST NOT 为产出它让 Rust 实现 ZIP/manifest/
  canonicalization；
- 回收站 UI 不属于本阶段退出门禁。

实现层面留下的约束：两趟设计（preflight 一趟只校验、apply 一趟才写入，换来「全部 preflight 在第一次
mutation 前完成」且峰值仍为一个条目）；每条目长度上限取清单声明长度本身；manifest 上限是独立常量
（16 MiB）；`fflate` 流式 `Unzip.push` 在一次调用内按条目数递归，块大小取 32 KiB 以控制栈深度并
有「3000 条目仍可导入」门禁钉住。

已修复的线上缺陷（留档）：ZIP 固定条目时间经 fflate 本地时间 getter 编码，UTC 以西时区年份越界
抛错——跨时区门禁 MUST 起真实子进程改 `TZ`（进程内改 `process.env.TZ` 不可靠）。

**仍开放（需真机）**：`<input type="file">` 真实 Tauri 文件对话框；raw chunk 吞吐实测；
「未发生 `postMessage` 静默回退」的运行时断言（读写两方向，回退时读取方向拿到 `number[]` 会被
`fromRawBytes` 响亮拒绝）；真实 WebView 内存/响应性；Web↔Desktop 实包往返。

#### D2.4 完整备份与恢复（已落地，真机部分通过）

交付物：Desktop 用 `VACUUM INTO` + blob 复制 + 逐个 digest 校验 + 最后写 manifest；受控维护窗口；
恢复前自动备份当前库；恢复采用重启时交换（`DESK-073`）+ 可幂等重放的 restore intent/journal。

规范性约束：

- 中断的备份不会被当作可用备份——「manifest 最后写、未完成 manifest 不视为有效」是对 `VACUUM INTO`
  中断失败模型的回应；`VACUUM INTO` 的目标文件名 MUST NOT 已存在、或 MUST 是空文件（不是「存在即
  失败」）；
- **备份不含 secret 明文**（`DESK-040`）：只备份 Profile 与 `secretRef`，恢复后 secret 缺失必须提示
  重新录入；
- **备份持维护窗口、导出不持**——两者 MUST NOT 互相引用为前提：备份要在之后整体替换当前库，必须是
  单一时刻精确快照；导出是人工产物，内容寻址已保证自洽；
- D2.4b 不得在运行中热替换（`manage()` 持有的 connection 换不掉），也不得把「重启」当原子性保证：
  `library.sqlite`（含 `-wal`/`-shm`）与 `blobs/` 两个资源之间可能崩溃，journal 每步必须可重放，
  无法安全向前或回滚时 fail closed、不打开混合代际；
- staging 复制用 temp + sync + no-clobber 发布；恢复面板二次确认；Provider 缺失凭据明确提示；
  Web 侧不新增整库替换语义。

**仍开放**：磁盘失败注入、大库性能基线、断电耐久性；D2.3/D2.5 原真机门禁继续开放。

### D4 Web Package 隔离

交付物：独立零 capability webview、默认拒绝浏览器权限、`maho-webpkg://` resolver、overlay 与
单文件目标约束。共享层只复用结果契约/控制/资源语义，不把 Web iframe 组件当作 Desktop renderer。
D4 关闭前任何 Desktop 页面均不执行该能力，不用临时主 UI iframe 绕过。

**第一道门禁是启用 `AppManifest::commands`，不是创建第二个 webview。** Tauri 应用自注册 command
默认对所有 window/webview 可用；没有 `AppManifest` 时自定义 command 对所有本地 webview 全开。
拆两段：D4a 建立 ACL 边界（先于第二个 webview），D4b 在已验证边界内扩张。结构门禁比对
`generate_handler!` ↔ `AppManifest::commands` ↔ `main-ui` capability 三方一致——否则每新增一个
native command 都会有人忘记进 ACL，而这种缺失不会让任何现有测试变红。

- D4a（结构门禁 PASS；运行期实机 PENDING）：`build.rs` 启用 `AppManifest::commands` 逐项登记；
  `main-ui` capability 以 `core:event:allow-listen`/`allow-unlisten` + `core:window:allow-destroy`
  替代 `core:default`（`DESK-011` 最小显式集；Channel 取回由 Tauri 豁免 ACL）；`permissions/
  autogenerated/` 是衍生资产不入库。Tauri 安全下限 `>=2.11.6`（GHSA-w28w-mhc8-qvjv：`<=2.11.5`
  Channel 取回 ID 可预测，无 capability webview 可窃取可信 webview 数据）。
- D4b（结构/静态门禁 PASS；运行期实机 PENDING）：`maho-webpkg://` instance 两态 staging（声明表 +
  TTL reaper → Open，窗口销毁回收）；begin 逐条复核 portable path/mediaType 且 entry 必须是已声明
  `text/html`；append 按 `x-webpkg-offset` 分块升序投递；`open` 为 `async fn`（Windows 同步建窗
  可能死锁，wry#583）；`WebviewUrl::CustomProtocol`（`External` 契约是 http/https）；顶层导航
  fail-closed 只放行 declared `text/html` 路径集快照（黑名单枚举必然漏，`evil.svg` 类可执行
  Document 会逃出 opaque origin）；resolver 支持 `Range`（206/416 +
  `Access-Control-Expose-Headers: Content-Range`）；长度校验统一 UTF-16 code unit 口径；
  staging 预算语义是「有效载荷字节」而非进程 RSS cap。模块内零文件系统 API。

实机验收沿用三项负向探针加：零 capability webview invoke 自有/core command 均被拒、
`maho-webpkg://` 只服务本 instance（foreign/非法路径/main-ui 均 404）、`on_navigation` 对外链与
`about:`/`data:` 的实际拦截、permission 默认拒绝、窗口关闭后资源释放、同 instance 重复 open
（聚焦而非死锁/误删）、大媒体 Range 与 RSS 上界、staging 中断后 TTL 释放、含 `<script>` 的
`evil.svg` 导航拒绝。设置页诊断面板是执行入口。有限补验见
[D4b 规范来源与 Document 关闭补验](../runbooks/2026-10-10_074400_D4b规范来源与Document关闭有限补验.md)与
[D4b 隔离窗口 Windows 有限验收](../runbooks/2026-10-10_030600_D4b隔离窗口Windows有限验收.md)。

不可信 Web 内容的受限策略与普通确认共源：沿用 Web 既有两套规则，纯 owner 由 Web 回用；
Desktop 生产基线不继承 Web 开发/HMR 与可选站点集成。合同见

N1 落地。生成确认框统一登记 Escape 层，忙碌时消费按键但不关闭或取消业务操作；
Web Details/Name/CharacterManager 与 Desktop Details/Canshou 的长图预览复用
`ImagePreviewModal` 的对话框语义、焦点约束与恢复，保留各入口图片宽度、遮罩关闭、层级和 Blob
生命周期；原生确认/详情、旧密钥迁移提醒及角色管理云卡操作在前台时，预览保留图片并让位。
Web Canshou/CharacterParty/Sublimation/BattleLite 同样复用共享图片预览；这四处异步结果通过
既有 Escape 栈的 opt-in 让位订阅，在云保存、删除、评分历史、举报等已登记模态前台期间暂停，
保留图片并在这些层退出后恢复。不改变普通模态排序，也不根据 DOM 或 z-index 猜测层级；
未登记的宿主层仍须由宿主显式协调。
真实 WebView 键盘、IME 与视觉无障碍仍在 D5.2 前集中验收。

备份兼容按 `DESK-058` 独立验证格式与 schema：保留 V1 读取、新写 V2；迁移链支持的历史真实结构
经恢复后正常升级，未来 schema / 未知格式 / 版本声明不符均拒绝。

## 2. 提交切分

共同流程使用[双端共源切片模板与验收指南](../runbooks/2026-10-06_084500_双端共源切片模板与验收指南.md)，按本次风险填写对照与失败边界；它不新增阶段、门禁平台或实施完成证明。

规范发生变化时先修 ADR/spec，再按真实切片组织实现。共享模块提取与 Web 回用应在同一可构建提交闭合，随后可独立提交 Desktop 接线；测试随行为提交，不能全部留在最后。

每阶段按职责区分 `contract / adapter / UI / tests / docs`，不把文档顺序误当成先实现后补规范的许可。大量生成资产
（`Cargo.lock`、`gen/schemas/`、图标）**MUST** 与行为修改分开提交，避免把机械变更混入语义变更。

D2.2 与 D2.4 各再切一层（`D2.2a/b/c`、`D2.4a/b`）：并发地基会改动每一个
command 签名，把它与审计混在一起时地基的回归无法归因；备份与恢复的破坏性风险量级不同。
`D2.3a/b/c/d` 的切分对应"契约 → 机制 → 消费者 → Web 侧"，让每一层都能独立验收。

## 3. 门禁与失败处理

- 任何阶段 **MUST NOT** 以降低门禁强度的方式"通过"；
- 任何阶段 **MUST NOT** 以未实际运行的检查声称 PASS；
- 阶段失败时 **MUST** 回到最近一个退出门禁已通过的状态，或显式记录新的迁移差距；
- 生产动作（发布、凭据变更、代码签名、Updater 激活）不在本计划授权范围内，需要单独授权。
