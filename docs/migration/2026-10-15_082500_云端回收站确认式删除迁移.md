# 云端回收站确认式删除迁移

## 发布与回滚

- 前置是“回收站满时拒绝软删除、停止自动清理”的后端版本（A）。回滚最低保留该行为；更早版本仍可能无确认清理墓碑，新 trigger 不能阻止旧 prune
- 先用现有 D1 安全迁移流程应用 `drizzle/0019_data_card_recycle_generation.sql`，再发布确认协议。这里只提供迁移源码，不代表已运行远端迁移
- B1 增加迁移与新安全端点，保留旧 Web 路径兼容。B2 将 Web/Desktop 切到共源确认流程，并同时关闭不含快照的 legacy recycle DELETE（返回 `CONFIRMATION_REQUIRED`）。完整快捷旅程需要 B2，不能以 B1 代替
- 缺少 generation 列或兼容 trigger 时新协议失败关闭；不要临时回退无版本的永久删除。保留新增列及 trigger，不需破坏性回滚数据

## 不可削弱的边界

- 每次活动卡进入回收站显式生成随机 generation，恢复保留它。窄 trigger 为尚未写 token 的 A writer 换代；旧 null 墓碑可作为初代。`AFTER` trigger 的结果不在旧 writer 的 `RETURNING` 中
- 确认版本同时覆盖 generation、正文、元信息、审核、类型、可见性、墓碑及完整待审记录；generation 不能替代内容 CAS。统计计数变化不使确认失效
- 永久删除仅接受当前账号的明确 `{id,version}` 集合；单条 SQL 同时确认所有目标，任何一项变化整组不删。提交后新到的墓碑不进入确认集合。预览超过安全集合上限时引导分批，不截断冒充全部
- 清空后继续先确认原活动卡未变、清空已确认集合后确有容量，再原子清空。只有严格成功回执才以原活动版本进行第二步软删除；间隙满额或目标变化需分别说明已完成和未完成的动作
- 身份、协议、操作类型、实际返回 ID 集合任一不匹配，或传输/服务端结果不确定时停止，不自动重发、续步或切换旧端点。重新读到空回收站也不证明先前删除成功
- 删除和恢复的在途/未知提示按账号与凭据代次保留在会话内；宿主关闭、卸载或普通关闭警告只隐藏 UI，不能消除可能已派发的提示。删除须明确「已知晓，结束本次操作」，恢复须明确「已核对，结束本次操作」才结束所观察的那次提示；旧组件不得清除较新的操作。提示不持久化、不保存正文、不代表回执；重启或换身份不延续，重新操作仍须读取新快照，不重放旧请求

数据卡正文分别绑定，小字段由 SQLite 固定顺序编码；执行前检查 D1 参数数量及单字符串字节上限。迁移、集合 CAS、级联与 ABORT 回滚同时由 SQLite 和 Miniflare D1 测试保护。
